Enhanced QB Police Job

Full-featured police job resource — duty toggling, armory, garage, evidence, ANPR, fingerprints, file cabinet, weapon registry, and more — by Kakarot / DS Customs

v1.3.5 QBCore qs-inventory ox_inventory qb-inventory Lua 5.4

1 — Requirements

ResourceNotes
qb-coreRequired framework. Must start before qb-policejob.
oxmysqlRequired for all database operations (stash, evidence, fingerprints, weapon registry, file cabinet).
PolyZoneRequired for zone-based interactions (duty points, impound, stash, radar triggers).
qs-inventory or ox_inventory or qb-inventoryOne inventory must be running. Auto-detected at startup in priority order: ox → qs → qb.
LegacyFuel (or custom)Configurable via Config.FuelResource. Must expose GetFuel() and SetFuel().
ds_notify (optional)Set Config.UseDSNotify = true to use ds_notify for all notifications. Falls back to QBCore notifications automatically.

2 — Installation

server.cfg Start Order

ensure qb-core
ensure oxmysql
ensure PolyZone
ensure qs-inventory   # or ox_inventory / qb-inventory
ensure LegacyFuel     # or your fuel resource
ensure qb-policejob

Required Items

Ensure the following items are registered in your QBCore shared items (qb-core/shared/items.lua). These are referenced by the resource at runtime.

ItemUsed for
handcuffsHandcuffing suspects (configurable via Config.HandCuffItem)
empty_evidence_bagCollecting blood, casings, and DNA samples
filled_evidence_bagFilled by evidence collection
police_stormramUsed to breach doors (armory loadout item)
mdt_tabletMDT loadout tablet item (links to ds_mdt)

3 — Configuration — config.lua

All global settings live in config.lua, which is fully open and unencrypted.

General

KeyDefaultDescription
Config.UseTargetfalseReads the UseTarget convar. Set to true in server.cfg to enable target-based interactions instead of proximity prompts.
Config.Inventory'auto'Inventory bridge. 'auto' detects ox → qs → qb at runtime. Force with 'ox', 'qs', or 'qb'.
Config.UseDSNotifytrueUse ds_notify for all notifications. Falls back to QBCore notifications if ds_notify is not running.
Config.UseDSGaragesfalseWhen true, impounded vehicles are sent to the nearest ds_garages depot (any garage with type = 'depot') instead of the built-in qb-policejob impound zone. Officers retrieve seized vehicles from the depot ped. Requires ds_garages to be running.
Config.MaxSpikes5Maximum spike strips an officer can have deployed at once.
Config.HandCuffItem'handcuffs'Item name for handcuffs.
Config.LicenseRank2Minimum job grade level required to grant/revoke licenses via /grantlicense and /revokelicense.
Config.ArmoryWhitelist{}Array of citizenids allowed to access the armory regardless of job. Leave empty to allow all on-duty officers.
Config.WhitelistedVehicles{}Array of vehicle model names that are always exempt from impound. Officers cannot impound these models.
Config.PoliceHelicopter'POLMAV'Vehicle spawn name of the police helicopter used in the heli system.
Config.FuelResource'LegacyFuel'Resource name of your fuel script. Must expose GetFuel(veh) and SetFuel(veh, level).

Locations

All in-world interaction points are defined in Config.Locations. Each key is an array of vector3 or vector4 coords.

KeyTypeDescription
dutyvector3[]On/off duty interaction points.
stashvector3[]Police evidence stash locations.
impoundvector3[]Vehicle impound lot locations.
helicoptervector4[]Helicopter spawn points (position + heading).
trashvector3[]Evidence disposal bin locations.
fingerprintvector3[]In-world fingerprinting station for suspects.
fingerprint_dbvector3[]AFIS fingerprint database terminal. Officers press E to open.
file_cabinetvector3[]Records filing cabinet terminal. Officers press E to open.
evidencevector3[]Evidence locker locations.
stationstable[]Named police stations. Each entry: { label, coords = vector4 }.

Ammo Labels

Maps GTA ammo type names to human-readable strings for evidence bag labels and ballistic reports.

Config.AmmoLabels = {
    AMMO_PISTOL  = '9x19mm parabellum bullet',
    AMMO_RIFLE   = '7.62x39mm bullet',
    AMMO_SHOTGUN = '12-gauge bullet',
    AMMO_SNIPER  = 'Large caliber bullet',
    -- ... see config.lua for all entries
}

Deployable Objects

Defines placeable police objects for the /pobject command.

Config.Objects = {
    cone     = { model = `prop_roadcone02a`,       freeze = false },
    barrier  = { model = `prop_barrier_work06a`,  freeze = true  },
    roadsign = { model = `prop_snow_sign_road_06g`, freeze = true  },
    tent     = { model = `prop_gazebo_03`,         freeze = true  },
    light    = { model = `prop_worklight_03b`,     freeze = true  },
}

Vehicle Settings

Per-model extra and livery overrides. When a vehicle matching one of these keys is spawned from the police garage, the listed extras are toggled and the livery is applied.

Config.VehicleSettings = {
    ['modelname'] = {
        ['extras'] = {
            ['1'] = true,   -- true = extra on, false = extra off
            ['2'] = false,
            -- ... up to ['13']
        },
        ['livery'] = 1,  -- livery index to apply on spawn
    },
}

The key must exactly match the vehicle's spawn name (e.g. 'police', 'sheriff2'). Omit a model entirely to leave its extras/livery unchanged.

4 — Police Garage — Config.Garage

The garage system spawns NPC attendant peds at each location. Officers approach the ped and press the prompt to open the garage UI. Vehicles are filtered by minGrade so cadets see different options than senior officers.

Garage Location Schema

Config.Garage.locations = {
    {
        coords      = vector4(444.94, -1012.18, 28.55, 183.6),  -- ped position + heading
        spawn       = vector4(443.78, -1019.92, 28.61, 89.01), -- vehicle spawn point
        park        = vector3(452.19, -1007.57, 27.25),         -- drive in to park
        badge       = 'LSPD',                                        -- UI header badge
        -- optional overrides:
        model       = 's_m_y_cop_01',
        scenario    = 'WORLD_HUMAN_COP_IDLES',
        radius      = 2.5,
        parkRadius  = 10.0,
    },
}

Garage Vehicle Schema

Config.Garage.vehicles = {
    { model = 'police',  label = 'Police Car 1',  minGrade = 0 },
    { model = 'police2', label = 'Police Car 2',  minGrade = 0 },
    { model = 'sheriff', label = 'Sheriff Car 1', minGrade = 0 },
    -- minGrade 0 = all ranks, 1 = officer and above, 2 = senior and above
}

Shared Ped Defaults

Applied to every garage location unless overridden per-entry in Config.Garage.pedDefaults.

KeyDefaultDescription
model's_m_y_cop_01'Ped model
scenario'WORLD_HUMAN_COP_IDLES'Ped animation scenario
radius2.5Proximity trigger radius (metres)
label'Open Garage'[E] prompt text
badge'LSPD'Fallback badge shown in the UI header

5 — Police Armory — Config.Armory

The armory system lets officers collect pre-defined loadouts from a ped at each armory location. Loadouts can be grade-restricted via minGrade.

Armory Location Schema

Config.Armory.locations = {
    {
        coords = vector4(461.85, -981.07, 30.69, 91.59),
        badge  = 'LSPD',
        -- optional: model, scenario, radius, label
    },
}

Loadout Schema

Config.Armory.loadouts = {
    {
        id       = 'patrol',
        label    = 'Patrol Loadout',
        desc     = 'Standard patrol gear for everyday duty.',
        minGrade = 0,   -- 0 = all ranks
        items    = {
            { name = 'weapon_pistol',     amount = 1 },
            { name = 'weapon_nightstick', amount = 1 },
            { name = 'pistol_ammo',       amount = 50 },
            { name = 'handcuffs',         amount = 1 },
            { name = 'armor',             amount = 1 },
        },
    },
}

Four default loadouts are included: MDT (all ranks), Patrol (all ranks), Tactical (grade 1+), and SWAT (grade 2+). Add or remove entries from the loadouts array freely.

6 — Weapon Registry — Config.WeaponRegistry

The weapon registry is a physical terminal where officers can look up registered weapons by serial number, or register a new weapon from a suspect's inventory. Data is persisted to the database and can be queried from the MDT.

Location Schema

Config.WeaponRegistry.locations = {
    {
        coords = vector4(440.59, -978.85, 30.69, 149.9),
        badge  = 'LSPD',
        label  = 'Weapon Registry',  -- [E] prompt text
        -- optional: radius (default 2.0)
    },
}

7 — Security Cameras — Config.SecurityCameras

Defines CCTV cameras that officers can view via the /cam [id] command. Each camera is a static scripted-camera viewpoint. Officers cycle through cameras using in-game controls.

Camera Entry Schema

Config.SecurityCameras.cameras = {
    [1] = {
        label     = 'Pacific Bank CAM#1',
        coords    = vector3(257.45, 210.07, 109.08),
        r         = { x = -25.0, y = 0.0, z = 28.05 },  -- camera rotation
        canRotate = false,
        isOnline  = true,
    },
}
FieldDescription
labelCamera name shown in the HUD when viewing.
coordsWorld position of the camera viewpoint.
rCamera pitch (x), roll (y), and yaw (z) in degrees.
canRotateIf true, the camera can be panned with the mouse while viewing.
isOnlineIf false, the camera feed shows as offline/static.
Set Config.SecurityCameras.hideradar = true to hide the minimap radar while viewing a camera feed.

8 — ANPR & Plate Radars

The Automatic Number Plate Recognition (ANPR) system alerts on-duty officers when a flagged vehicle passes through a radar zone. Radar positions are defined in Config.Radars and processed client-side.

Enabling / Disabling Radars

Config.EnableRadars = true  -- set false to disable all radar alerts

Adding Radar Positions

Config.Radars = {
    vector3(1051.42, 331.11, 84.00),
    vector3( 544.43, -373.24, 33.14),
    -- add/remove entries freely
}

When a vehicle with a flagged plate (wanted level or police note attached in the MDT) drives within range of a radar position, all on-duty officers receive an alert with the plate and nearest street.

10 — Feature Overview

Evidence System

Officers can collect evidence from crime scenes using empty_evidence_bag items:

  • Blood drops — collected near injured/downed players.
  • Bullet casings — spawn when weapons are fired. Collected with evidence bags.
    • DNA samples — taken via /takedna [id]. Hash is derived from the player's citizenid.

Collected evidence is stored in the police stash at Config.Locations.stash or in evidence lockers at Config.Locations.evidence. Evidence bags can be disposed of at Config.Locations.trash.

Fingerprint Database (AFIS)

The fingerprint database terminal (at Config.Locations.fingerprint_db) allows officers to query a suspect's fingerprints and return their identity and criminal history. When a player is fingerprinted at Config.Locations.fingerprint, their print is stored server-side.

File Cabinet

A physical records terminal at Config.Locations.file_cabinet. Officers can create, search, and retrieve written criminal records. Data is persisted to the database.

Vehicle Tracker

Officers can attach a GPS tracker to a vehicle. The /ankletlocation [cid] command requests the live position of a player wearing an ankle monitor. The tracker is stored in player metadata (metadata['tracker']).

Helicopter

Officers can request a police helicopter at the spawn points defined in Config.Locations.helicopter. The helicopter model is set via Config.PoliceHelicopter.

Car Items

Default items placed in police vehicles when spawned from the garage, defined in Config.CarItems:

Config.CarItems = {
    [1] = { name = 'heavyarmor',          amount = 2,  slot = 1 },
    [2] = { name = 'empty_evidence_bag', amount = 10, slot = 2 },
    [3] = { name = 'police_stormram',     amount = 1,  slot = 3 },
}

11 — Developer API

qb-policejob exposes server exports and a server event for cross-resource integration.

Server Exports

PoliceAlert(playerSrc, text) boolean

Dispatches a police alert to all on-duty LEOs. Location is derived from the calling player's ped position.

ParameterTypeDescription
playerSrcnumberServer source of the player triggering the alert.
textstringAlert message shown to on-duty officers.
 
-- From a heist resource — alert all cops to a robbery
exports['qb-policejob']:PoliceAlert(source, 'Armed robbery in progress at Fleeca Bank')

PoliceAlertCoords(coords, text) boolean

Dispatches an alert at explicit world coordinates. Ideal for script-triggered events where there is no specific player source.

ParameterTypeDescription
coordsvector3 or {x,y,z}World position of the incident.
textstringAlert message.
 
-- From an alarm script — known coords, no player source
exports['qb-policejob']:PoliceAlertCoords(
    vector3(441.0, -982.0, 30.7),
    'Bank alarm triggered'
)

GetOnDutyCopCount() number

Returns the number of players currently on duty with a job type of 'leo'. Useful for robbery scripts that require minimum officer count.

local count = exports['qb-policejob']:GetOnDutyCopCount()
if count < 2 then
    -- block the action, not enough cops online
end

GetOnDutyCops() table[]

Returns an array of all on-duty LEO players with basic profile data.

KeyTypeDescription
sourcenumberPlayer server ID
namestringFirst + last name of the character
jobstringJob name (e.g. 'police')
callsignstring|nilOfficer callsign set via /callsign
 
local cops = exports['qb-policejob']:GetOnDutyCops()
for _, officer in ipairs(cops) do
    print(officer.source, officer.name, officer.callsign)
end

Server Events

qb-policejob:server:911pCall (callerSrc, data)

Fired whenever a civilian uses /911p. Subscribe to this event from any server-side script to record or process emergency calls (e.g. ds_mdt uses this to create dispatch alerts).

KeyTypeDescription
callerSrcnumberServer source of the caller
data.xnumberCaller X coordinate
data.ynumberCaller Y coordinate
data.znumberCaller Z coordinate
data.messagestringThe message text provided by the caller
 
AddEventHandler('qb-policejob:server:911pCall', function(callerSrc, data)
    print('911 call from', callerSrc, 'at', data.x, data.y, data.z)
    print('Message:', data.message)
end)
The on911pCall export provides a convenience wrapper to register a listener without writing a raw AddEventHandler: 
exports['qb-policejob']:on911pCall(function(callerSrc, data)
    -- handle it here
end)

12 — FAQ & Troubleshooting

Which inventory resource takes priority?

When Config.Inventory = 'auto', detection runs in this order: ox_inventory → qs-inventory → qb-inventory. The first running resource wins. Force a specific one with 'ox', 'qs', or 'qb'.

Notifications are not showing

If Config.UseDSNotify = true and ds_notify is not running, the resource falls back to QBCore notifications automatically. If you see no notifications at all, confirm ds_notify is started before qb-policejob in server.cfg.

The garage ped / armory ped is not appearing

Ensure PolyZone is started before qb-policejob. Check that the coords in Config.Garage.locations and Config.Armory.locations match a walkable surface — peds placed underground or in water will not render.

How do I add more police stations?

Add entries to Config.Locations.stations. Each entry needs a label and a coords (vector4). The MDT uses this list to populate the station selector for calls and warrants.

Fine command falls through to phone invoice

This is expected behaviour — if the player has insufficient bank and cash funds, a QBCore phone invoice is created instead of an immediate deduction. The fine is still tracked.

Spike strips disappear after reconnect

Spike strips are client-side entities managed per-session. They do not persist across server restarts or reconnects by design. Config.MaxSpikes limits simultaneous deployments per officer.
