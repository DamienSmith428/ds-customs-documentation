DS Television

Server-synced TV system. Stream YouTube, Twitch, or any website onto in-world TV props. Per-TV distance controls, a custom default image, location-spawned props, and a clean in-game control menu — by DS Customs

v1.0.0 FiveM QBCore OneSync Escrow

1 — Overview

DS Television renders a live DUI (browser texture) onto any GTA V TV prop in the game world. Players walk up to a TV, type /tv, and get a compact control panel where they can play YouTube videos, Twitch streams, or open any website. Playback state is stored server-side so late-joining players automatically see whatever is already playing.

3 — Installation

Drop-in

Copy the ds_television folder into your [tv] category folder (or any resource folder). No SQL files to run.

Default screen image

The file html/tv_image.png is displayed on the TV whenever no content is playing. Replace this file with any 1280×720 PNG of your choice — a server logo, a "No Signal" graphic, or anything else. The filename must remain tv_image.png.

server.cfg start order

ensure ds_television
No other resources need to start before ds_television. If you are using location-spawned props, ensure OneSync is enabled in your server.cfg with set onesync on (or infinity).

4 — Configuration — config.lua

All configuration lives in config.lua, which is fully open and unencrypted.

4.1 — Global settings

KeyDefaultDescription
Config.InteractRange20.0How close (in units) a player must be to use /tv on a TV. Acts as the fallback value for every model and location entry that does not define its own Range. Does not affect whether the screen renders — that is controlled by the 50-unit RENDER_DISTANCE constant in client/main.lua.

4.2 — Config.Models

Every TV prop model that the resource should handle must have an entry here. The resource ignores any object whose model hash is not listed.

Config.Models = {
    [`prop_tv_flat_01`] = {
        DefaultVolume = 0.5,   -- Starting volume (0.0 – 1.0) when no saved value exists
        Range         = nil,   -- /tv interact range. nil = Config.InteractRange
        Target        = "tvscreen", -- Named render-target. Only set if the prop has one.
        Scale         = 0.085, -- Scaleform scale (only used when Target is nil)
        Offset        = vector3(-1.02, -0.055, 1.04), -- Screen offset from prop origin
    },
}
FieldTypeRequiredDescription
DefaultVolumenumberYesVolume applied when the player first approaches the TV and no saved volume exists. Range 0.0–1.0.
Rangenumber / nilNoPer-model override for /tv interact distance. nil falls back to Config.InteractRange.
Targetstring / nilNoNamed render-target registered on the prop (e.g. "tvscreen"). When set, the DUI is projected directly onto the prop's render target for perfect screen alignment. Leave nil for models without a registered render target — the scaleform DrawScaleformMovie_3dSolid path is used instead.
ScalenumberYes (if no Target)Scaleform scale multiplier. Only used when Target is nil. Adjust to fit the screen face of the model.
Offsetvector3Yes (if no Target)World-space offset from the entity origin to the screen face. Only used when Target is nil. Adjust X/Y/Z until the image is centred on the screen.
The 17 models listed in the default config cover the most common GTA V TV props. Add any additional model hashes you need — the model must exist in the game files or be streamed by another resource.

4.3 — Config.Locations

Location entries tell the resource to spawn and manage a TV prop at a specific world coordinate. Requires OneSync. Remove all entries (leave the table empty) if your server does not use OneSync.

Config.Locations = {
    {
        Model        = `prop_tv_flat_01`,
        Position     = vector4(144.3038, -1037.4647, 29.4173, 70.81),
        SpawnRange   = 50.0,  -- Create prop within this distance. nil = Config.InteractRange
        DespawnRange = 70.0,  -- Delete prop beyond this distance.  nil = SpawnRange + 20.0
        Range        = 10.0,  -- /tv interact range for this TV only. nil = model / global default
    },
}
FieldTypeRequiredDescription
Modelmodel hashYesProp model to spawn. Must also be listed in Config.Models.
Positionvector4YesWorld position (X, Y, Z) and heading (W) for the spawned prop.
SpawnRangenumber / nilNoDistance at which the prop is created. nil uses Config.InteractRange.
DespawnRangenumber / nilNoDistance at which the prop is deleted. nil uses SpawnRange + 20.0. Should always be larger than SpawnRange to prevent pop-in.
Rangenumber / nilNoOverrides the /tv interact distance for this specific TV. Falls back to the model's Range, then Config.InteractRange.
OneSync required. If you use Config.Locations without OneSync enabled, the spawned props will not be visible to other players and the resource will produce errors. Set Config.Locations = {} to disable location spawning.

4.4 — Config.Channels

Pre-defined broadcast channels that can be queued by channel index from server-side code. Channels listed here are the defaults — they cannot be overridden by players through the menu.

Config.Channels = {
    { name = "Twitch", url = "twitch.tv/twitch" },
}
FieldTypeDescription
namestringDisplay name for the channel. Used in channel-change notifications.
urlstringTwitch channel path (e.g. twitch.tv/channelname) or YouTube URL.

4.5 — Config.BannedWords

A list of strings that are blocked in any URL submitted through the in-game menu. If a submitted URL contains any of the listed strings (case-sensitive substring match), the server rejects the request and nothing plays.

Config.BannedWords = {
    "google",
}
Add any domains or keywords you want to block, e.g. "pornhub", "discord". The check runs server-side inside Config.Events.ScreenInteract, so it cannot be bypassed from the client.

4.6 — Config.Events

Two server-side gate functions that control whether a screen interaction or broadcast is allowed to proceed. Call cb() to approve; return without calling it to silently block.

Config.Events = {
    -- Fires whenever a player submits a URL or browser link through the menu.
    -- source = player server id, data = screen data, key = "ds_tv_status",
    -- value = { type, url/channel/... }, cb = approval callback
    ScreenInteract = function(source, data, key, value, cb)
        -- default: run banned-word check, then approve
        cb()
    end,

    -- Fires whenever a player sends a server:broadcast event.
    -- source = player server id, data = channel data, cb = approval callback
    Broadcast = function(source, data, cb)
        cb()
    end,
}
These callbacks are synchronous. Do not yield inside them (no Wait, no async database calls). If you need to check permissions asynchronously, use Citizen.CreateThread inside and call cb() from within that thread.

5 — Range & Distance System

DS Television separates rendering distance from interaction distance. This means the TV always shows its content when a player is nearby, but the /tv command only works if they are close enough to interact.

ConceptValueWhat it controls
Render distance50 units (hardcoded)How close a player must be for the DUI to be created and the screen content to appear. Not configurable per TV.
Interact rangeConfig.InteractRange (default 20)How close a player must be to type /tv and open the control menu. Configurable globally and per-TV.
Volume falloffWithin interact rangeVolume scales linearly from the player's set level down to 0 as they walk from the TV outward to the interact range boundary.

Range priority order

When determining a TV's interact range, the system checks in this order:

  1. Config.Locations[i].Range — per-location override (highest priority)
  2. Config.Models[model].Range — per-model override
  3. Config.InteractRange — global fallback (lowest priority)

Spawn hysteresis for location props

Location-spawned props use two separate distance thresholds to prevent the prop from rapidly appearing and disappearing when a player walks near the boundary:

  • Prop is created when the player comes within SpawnRange
  • Prop is deleted only when the player moves beyond DespawnRange

Always set DespawnRange larger than SpawnRange. A gap of 20 units is the recommended minimum.

6 — In-Game Control Menu

Open the menu by typing /tv while standing within range of a TV. The menu appears in the top-right corner. It closes when you click Close or press ESC.

ButtonSectionBehaviour
Play VideoPlaybackOpens a text input. Paste a full YouTube (https://youtube.com/watch?v=… or https://youtu.be/…) or Twitch URL (twitch.tv/channel). Submitting sends the URL to the server for ban-word checking, then broadcasts playback to all players.
Web BrowserPlaybackOpens a text input. Paste any https:// URL. The TV screen becomes a live web browser showing that page.
Refresh ScreenScreenImmediately stops any playing video/browser and resets the TV to the default static image (tv_image.png). Works even if the screen is already showing the default image.
Set VolumeSettingsOpens a text input. Enter a number between 0 and 100. This is a local-only volume change — it affects only the player who submits it.
Interact With ScreenSettingsEnables mouse cursor mode so the player can click on interactive content rendered on the TV (e.g. web pages). Press ESC or close the menu to exit interact mode.
Close—Closes the menu and releases cursor focus. Equivalent to pressing ESC.

Text input behaviour

When a text input overlay is shown (for URL or volume entry):

  • Press Enter to confirm
  • Press ESC to cancel and return to the menu
  • Click Cancel to cancel and return to the menu
  • Empty submissions are ignored — nothing is sent to the server

7 — Default Screen Image

The file html/tv_image.png is shown on the TV screen whenever no video, stream, or browser is active. This replaces the old "NO SIGNAL" text that was present in earlier versions.

Replacing the image

  1. Create or export your image at 1280 × 720 px, saved as a PNG.
  2. Name the file tv_image.png.
  3. Drop it into ds_television/html/, overwriting the existing file.
  4. Restart the resource — no other changes are needed.
The image is declared in fxmanifest.lua under the files block as "html/tv_image.png". FiveM will not serve it to the DUI unless it appears in that block. If you rename the file you must also update fxmanifest.lua and html/index.html.

When is it shown

SituationResult
Player first approaches TV with no active contentDefault image shown
Submitted URL is invalid or not recognisedDefault image shown
Player clicks Refresh ScreenDefault image shown
Channel broadcast ends and no other content is queuedDefault image shown
YouTube or Twitch video is playingDefault image hidden
Web browser URL is loadedDefault image hidden (browser fills screen)

8 — Adding a New TV Model

To support a prop model that is not in the default list, add an entry to Config.Models in config.lua:

Config.Models[`your_prop_model`] = {
    DefaultVolume = 0.5,
    Range         = nil,     -- uses Config.InteractRange
    Target        = nil,     -- set to "tvscreen" only if the model has a named render target
    Scale         = 0.085,  -- adjust until the image fits the screen face
    Offset        = vector3(0.0, 0.0, 0.0), -- adjust until image is centred
}

Does my model have a named render target?

A named render target is a pre-defined texture slot in the model's drawable that the game exposes for DUI injection. Most Rockstar TV props use "tvscreen". If your prop has one, set Target = "tvscreen" (or whatever name applies) and leave Scale and Offset at defaults — the image will fill the screen perfectly without any adjustment.

If your prop does not have a render target, set Target = nil and use Scale and Offset to position the scaleform overlay manually on the screen face.

9 — Adding Location-Spawned TVs

Location TVs are props that the resource creates, positions, and manages entirely in code — no map editor or YMAP required.

Config.Locations[#Config.Locations + 1] = {
    Model        = `prop_tv_flat_01`,
    Position     = vector4(X, Y, Z, Heading),
    SpawnRange   = 50.0,
    DespawnRange = 70.0,
    Range        = nil,
}

To get the coordinates and heading of the exact position you want, stand at the location in-game and use a coords-printer command (e.g. /coords if your server has one), or use a resource like spawn-anywhere in a dev environment.

Every model used in Config.Locations must also appear in Config.Models, otherwise the DUI will not know how to render onto it.

10 — Net Events & Internal Architecture

Understanding the event flow is useful if you want to trigger TV actions from other resources or hook into the system server-side.

Event flow — player sets a video

-- 1. Player submits URL in the menu:
Client (NUI) → menuAction { action: "video", value: "https://..." }
    → RegisterNUICallback('menuAction')
    → TriggerServerEvent("ds_television:event", screenData, "ds_tv_status", { type="play", url=... })

-- 2. Server validates and stores:
Server RegisterNetEvent("ds_television:event")
    → Config.Events.ScreenInteract(source, data, key, value, cb)
    → SetTelevision(coords, "ds_tv_status", value, true)   -- true = broadcast
    → TriggerClientEvent("ds_television:event", -1, Televisions, index, key, value)

-- 3. All clients receive and apply:
Client RegisterNetEvent("ds_television:event")
    → PlayVideo({ url = value.url }) / PlayBrowser({ url = value.url })

All registered net events

EventDirectionPurpose
ds_television:eventClient → Server → All ClientsA player submitted a menu action (play, browser, etc.). Server validates via Config.Events.ScreenInteract, stores state, then broadcasts to all clients.
ds_television:broadcastClient → Server → All ClientsA player is starting/stopping a server-side channel broadcast. Server validates via Config.Events.Broadcast.
ds_television:requestSyncClient → Server → ClientSent when a player's DUI finishes loading for a TV. Server replies with the current TV state so late joiners see what is already playing.
ds_television:requestUpdateClient → Server → ClientSent on resource start. Server replies with the full Televisions and Channels tables.

Triggering a TV from another resource

You can set a TV playing from any server-side resource by calling SetTelevision directly — but since this function lives inside ds_television's server scope, the cleanest approach is to trigger the net event:

-- From another server-side resource, play a video on the TV at specific coords:
TriggerClientEvent("ds_television:event", -1, Televisions, index, "ds_tv_status", {
    type = "play",
    url  = "https://www.youtube.com/watch?v=dQw4w9WgXcQ"
})
You will need index (the key under which the TV is stored in Televisions) to target a specific TV. Use GetTelevision(coords) — defined in shared/main.lua and available on both client and server — to look up an entry by its world coordinates.

11 — FAQ

Do I need OneSync?

Only if you use Config.Locations. Location entries spawn props server-side using CreateObject, which requires OneSync so all players see the same entity. If your server does not run OneSync, remove all entries from Config.Locations (leave it as an empty table). TVs that already exist as part of the map work without OneSync.

Which YouTube URLs are supported?

Full watch URLs (https://www.youtube.com/watch?v=XXXXXXXXXXX) and short URLs (https://youtu.be/XXXXXXXXXXX). Playlists, shorts, and channel pages are not supported — only individual video URLs.

Which Twitch URLs are supported?

Channel paths in the form twitch.tv/channelname. The https:// prefix is optional. VOD and clip URLs are not supported.

Will late-joining players see what is playing?

Yes. When a player's DUI finishes loading, the client fires ds_television:requestSync. The server replies with the stored TV state (Televisions[index].ds_tv_status) including the URL and a timestamp so the video can be seeked to the correct position.

Is volume change shared or local?

Volume is local only. Each player sets their own volume independently through Set Volume in the menu. Setting volume does not affect what other players hear.

There are multiple TVs nearby — which one does /tv target?

The nearest TV that is within its interact range. The resource scans all objects in the game pool every cycle and selects the closest eligible TV. If two TVs are both in range, the one with the shorter distance from the player wins.

The TV shows the image but content does not play

Check: (1) The URL is a supported format (YouTube watch URL or twitch.tv/channel). (2) The URL does not contain a banned word. (3) The player has internet access — FiveM's NUI browser fetches YouTube/Twitch content live from the internet. (4) Config.Events.ScreenInteract is calling cb() — if you customised this function, make sure it always calls the callback when approved.

How do I change the default screen image?

Replace html/tv_image.png with your own 1280×720 PNG. Keep the same filename. See Section 7 for full instructions.

My location TV keeps appearing and disappearing

Set a larger gap between SpawnRange and DespawnRange. A gap of at least 20 units is recommended. For example: SpawnRange = 40.0, DespawnRange = 65.0. This hysteresis band means the prop is not deleted until the player has moved 25 units past the point where it was created, preventing rapid pop-in/out.

I added a model but the TV screen is blank or misaligned

First, check whether the prop has a named render target. If it does, set Target = "tvscreen" (or the correct target name). If it does not, adjust Scale and Offset in small increments until the image aligns with the physical screen face of the prop.

Does this store anything in the database?

No. DS Television has zero SQL dependency. All TV state (current URL, volume, last update time) lives in server memory and resets when the resource or server restarts.
