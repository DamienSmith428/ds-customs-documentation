GS Business Banking

Standalone shared business bank account system — NPC banker, grade-restricted access, and a full server export API — by GunSmoke Creations

v1.0.0 QBCore FiveM Lua 5.4 ds_notify

1 — Overview

GS Business Banking provides every QBCore job on your server with a shared, database-backed bank account. Banker NPC peds spawn at configurable world locations. Authorised employees can deposit and withdraw funds through a clean NUI panel. Any other resource can read and write balances through simple server-side exports or QBCore callbacks.

Every QBCore shared job gets a bank account row created automatically on resource start — no manual SQL inserts required.

2 — Requirements

ResourceNotes
qb-coreRequired framework. Provides player data, money functions, and the jobs table.
oxmysqlRequired for all database operations.
qb-targetRequired for the banker NPC interaction prompt.
ds_notifyRequired for all in-game toast notifications.

3 — Installation

  1. Place the gs-businessbanking folder inside your resources directory.
  2. Add to your server.cfg after qb-core, oxmysql, qb-target, and ds_notify:
ensure qb-core
ensure oxmysql
ensure qb-target
ensure ds_notify
ensure gs-businessbanking
  1. Optionally import sql/gs_business_accounts.sql — the resource also creates the table automatically on first start if it does not exist.
  2. Open config.lua and customise banker locations, allowed grades, and jobs (see §4).
To declare the dependency in a job resource add dependency 'gs-businessbanking' to that resource's fxmanifest.lua.

4 — Configuration — config.lua

All settings are in config.lua, which is open and unencrypted (excluded from escrow).

Banker NPC Models — BBConfig.BankerPeds

A list of ped model names. Each bank location spawns one randomly-chosen ped from this list. Any valid GTA V ped model name works.

BBConfig.BankerPeds = {
    "IG_Bankman",
    "U_M_M_BankMan",
}

Bank Locations — BBConfig.BankLocations

Each entry spawns one banker NPC. coords is a vector4 (x, y, z, heading). label is the text shown in the qb-target interaction prompt.

BBConfig.BankLocations = {
    {
        coords = vector4(243.51, 226.35, 106.29, 169.84),  -- Downtown Maze Bank
        label  = "Business Banker"
    },
    {
        coords = vector4(-112.35, 6469.2, 31.63, 45.0),   -- Paleto Savings
        label  = "Business Banker"
    },
    {
        coords = vector4(1175.22, 2706.75, 38.09, 180.0), -- Sandy Shores Bank
        label  = "Business Banker"
    },
}

Add or remove entries freely. Each location gets its own independently-spawned ped.

Jobs to Initialise — BBConfig.InitJobs

Job names listed here are guaranteed to have a bank account row created on every server/resource start. This is optional — all QBCore shared jobs are scanned and initialised automatically. Use this list only as a safety net for jobs you want guaranteed even before QBCore finishes loading.

BBConfig.InitJobs = {
    -- "mechanic",   ← uncomment if needed
}

Per-Job Allowed Grades — BBConfig.JobGrades

Controls which job grade levels are permitted to access the business bank — both via the in-game NPC terminal and via the exports. Any grade level listed will be permitted to deposit and withdraw. Jobs not listed fall back to BBConfig.DefaultAllowedGrades.

BBConfig.JobGrades = {
    ["whitewidow"] = { 4 },          -- grade 4 only
    ["police"]     = { 3, 4, 5 },    -- grades 3, 4, and 5
    ["mechanic"]   = { 3, 4 },       -- grades 3 and 4
}

Default Allowed Grades — BBConfig.DefaultAllowedGrades

Fallback grade list used for any job that is not listed in BBConfig.JobGrades.

BBConfig.DefaultAllowedGrades = { 4 }  -- grade 4 for all unlisted jobs
If a player's grade is not in the allowed list for their job, the banker will show an error notification and the NUI will not open.

5 — In-game NPC Banker Terminal

Banker peds spawn at each BBConfig.BankLocations entry 2 seconds after the resource starts. Each ped is:

  • Invincible and frozen in place.
  • Running the WORLD_HUMAN_STAND_IMPATIENT scenario.
  • Wrapped with a qb-target box zone at 2.5 metre range with the label from BBConfig.BankLocations[n].label.

Access flow

  1. Player looks at the banker and selects the target prompt.
  2. Client checks the player's job grade against BBConfig.JobGrades (or DefaultAllowedGrades). If insufficient, an error notification is shown and the menu does not open.
  3. Server validates the job and grade a second time, then fetches a fresh balance directly from the database and sends it to the client.
  4. The NUI banking panel opens showing the current business account balance, the player's cash, and the player's bank balance.
  5. The player enters an amount, selects Cash or Bank, and clicks Deposit or Withdraw. The transaction is processed server-side and the UI balance updates in real time.
Banker peds are cleaned up automatically when the resource stops or restarts — no orphaned entities.

6 — Server Exports

All exports are server-side. Call from any other server-side script in any resource.

GetBalance(jobName) number

Returns the cached balance for a job. Safe to call any time after resource startup (the cache is warm by the time any player connects). Returns 0 if the job is not found or the cache is empty.

Synchronous — returns from the in-memory cache, not directly from the database. For a guaranteed-fresh read use the gs-businessbanking:getBalance QBCore callback instead (see §7).
local balance = exports['gs-businessbanking']:GetBalance("whitewidow")
print("Business account: $" .. balance)

Deposit(jobName, amount) boolean

Adds funds to a job's account unconditionally. Returns true if the deposit was queued, false if amount is invalid (<= 0 or non-numeric).

This does not remove money from a player. It only adds to the business balance. Use it for sale proceeds, billing payments, fines deposited to a job account, etc.
-- A customer just paid — put the revenue in the business account
local ok = exports['gs-businessbanking']:Deposit("whitewidow", 500)
if not ok then print("Deposit failed — invalid amount") end

Withdraw(jobName, amount) boolean

Removes funds from a job's account. Returns false if amount is invalid. The withdrawal is silently rejected internally if the balance is insufficient (no error return — use the gs-businessbanking:transaction callback for guaranteed-result writes).

This does not give money to a player. It only reduces the business balance. Pair it with Player.Functions.AddMoney if you need to transfer funds to a player.
exports['gs-businessbanking']:Withdraw("whitewidow", 200)

AddFunds(jobName, amount) boolean

Alias for Deposit. Provided for naming consistency in job resources.

exports['gs-businessbanking']:AddFunds("whitewidow", 1000)

FetchBalance(jobName, cb) void (async)

Always reads directly from the database, then syncs the in-memory cache. cb(balance) is called asynchronously with the live value. Use this wherever you need a guaranteed-fresh balance (e.g. when opening a management UI).

exports['gs-businessbanking']:FetchBalance("whitewidow", function(balance)
    print("Live balance from DB: $" .. balance)
end)

IsGradeAllowed(jobName, grade) boolean

Returns true if the given grade level is permitted to access the specified job's account, according to BBConfig.JobGrades (or BBConfig.DefaultAllowedGrades as the fallback). Lets other resources gate their own UIs without duplicating the config logic.

local Player  = QBCore.Functions.GetPlayer(source)
local allowed = exports['gs-businessbanking']:IsGradeAllowed(
    Player.PlayerData.job.name,
    Player.PlayerData.job.grade.level
)
if not allowed then
    -- block access
end

7 — QBCore Callbacks

These callbacks are the preferred API for job resources that need to interact with balances from their own server scripts. Both callbacks verify the player's job and grade before acting, and always use the database as the source of truth.

gs-businessbanking:getBalance

Returns a fresh balance for the player's current job. The player's job must match jobName and their grade must be allowed.

cb keyTypeDescription
okbooleantrue = authorised and balance returned
balancenumberCurrent account balance (0 when ok = false)
 
QBCore.Functions.TriggerCallback('gs-businessbanking:getBalance', function(result)
    if result.ok then
        print("Account balance: $" .. result.balance)
    end
end, "whitewidow")

gs-businessbanking:transaction

Performs a deposit or withdrawal, validates the player's job and grade, checks that sufficient funds exist, and moves money between the player and the business account atomically. Use this when you need a guaranteed result with proper error messaging.

ParameterTypeValuesDescription
jobNamestringAny job nameThe job account to transact against.
directionstring'deposit' / 'withdraw'Direction of the transaction.
amountnumberPositive integerAmount in dollars.
payMethodstring'cash' / 'bank'Player money source/destination for the deposit/withdrawal.
cb keyTypeDescription
okbooleantrue = transaction completed successfully
msgstringHuman-readable result message
msgTypestring'success' or 'error'
balancenumberUpdated account balance (only present on success)
 
QBCore.Functions.TriggerCallback(
    'gs-businessbanking:transaction',
    function(result)
        if result.ok then
            print(result.msg, "New balance: $" .. result.balance)
        else
            print("Transaction failed:", result.msg)
        end
    end,
    "whitewidow",  -- jobName
    "deposit",    -- direction
    500,           -- amount
    "cash"         -- payMethod
)

8 — Wiring Into a Job Resource

Step 1 — Declare the dependency

In your job resource's fxmanifest.lua:

dependency 'gs-businessbanking'

Step 2 — Deposit revenue when a sale is made

RegisterNetEvent('yourjob:buyItem', function(itemName, amount)
    local src    = source
    local Player = QBCore.Functions.GetPlayer(src)
    if not Player then return end

    local price      = 500
    local totalPrice = price * amount

    if not Player.Functions.RemoveMoney("cash", totalPrice) then
        exports['ds_notify']:NotifyClient(src, "Not enough cash!", "error")
        return
    end

    exports['gs-businessbanking']:Deposit("yourjob", totalPrice)
    -- Give item to player...
end)

Step 3 — Read the balance for a management menu

QBCore.Functions.CreateCallback("yourjob:getBankBalance", function(source, cb)
    local Player = QBCore.Functions.GetPlayer(source)
    if not Player then cb({ ok = false, balance = 0 }) return end

    if not exports['gs-businessbanking']:IsGradeAllowed(
        "yourjob", Player.PlayerData.job.grade.level
    ) then
        cb({ ok = false, balance = 0 })
        return
    end

    local balance = exports['gs-businessbanking']:GetBalance("yourjob")
    cb({ ok = true, balance = balance })
end)

Step 4 — Handle a deposit/withdraw from your HR menu

QBCore.Functions.CreateCallback("yourjob:bankTransaction", function(source, cb, direction, amount, payMethod)
    local src    = source
    local Player = QBCore.Functions.GetPlayer(src)
    if not Player then cb({ ok = false, msg = "Player not found" }) return end

    if not exports['gs-businessbanking']:IsGradeAllowed(
        "yourjob", Player.PlayerData.job.grade.level
    ) then
        cb({ ok = false, msg = "No permission" })
        return
    end

    amount = tonumber(amount)
    if not amount or amount <= 0 then
        cb({ ok = false, msg = "Invalid amount" })
        return
    end

    if direction == "deposit" then
        local money = Player.PlayerData.money[payMethod] or 0
        if money < amount then
            cb({ ok = false, msg = ("Not enough %s"):format(payMethod) })
            return
        end
        Player.Functions.RemoveMoney(payMethod, amount)
        exports['gs-businessbanking']:Deposit("yourjob", amount)
        cb({ ok = true, msg = ("Deposited $%d"):format(amount),
             balance = exports['gs-businessbanking']:GetBalance("yourjob") })

    elseif direction == "withdraw" then
        local bal = exports['gs-businessbanking']:GetBalance("yourjob")
        if bal < amount then
            cb({ ok = false, msg = ("Not enough funds (have $%d)"):format(bal) })
            return
        end
        exports['gs-businessbanking']:Withdraw("yourjob", amount)
        Player.Functions.AddMoney(payMethod, amount)
        cb({ ok = true, msg = ("Withdrew $%d"):format(amount),
             balance = exports['gs-businessbanking']:GetBalance("yourjob") })
    end
end)

Step 5 — Add the job to config.lua

BBConfig.JobGrades = {
    ["yourjob"] = { 3, 4 },   -- grades 3 and 4 can deposit/withdraw
}

9 — Database

The resource uses a single table: gs_business_accounts. It is created automatically on resource start via CREATE TABLE IF NOT EXISTS.

ColumnTypeDescription
job_nameVARCHAR(50) PKQBCore job name — primary key.
balanceBIGINTCurrent account balance in dollars. Default 0.
allowed_gradesVARCHAR(100)Comma-separated permitted grade levels, e.g. '3,4'. Set from config at account creation.
updated_atINTUnix timestamp of the last balance change.
Rows are created automatically for every QBCore job on resource start. You never need to insert rows manually. Existing rows are never overwritten — only the balance and updated_at columns change during normal operation.

Caching behaviour

Export / CallbackSource of truthNotes
GetBalanceIn-memory cacheSynchronous. Safe after startup. Not guaranteed-fresh if DB was edited externally.
FetchBalanceDatabase (async)Always reads from DB. Use when opening a UI.
gs-businessbanking:getBalance callbackDatabase (async)Preferred for job resource management menus.
gs-businessbanking:transaction callbackDatabase (async)Atomic deposit/withdraw with full validation and error messaging.

10 — Net Events Reference

These are internal net events used by the NUI terminal. You can also fire them from other resources to open the banking UI for a player.

EventDirectionPayloadDescription
gs-businessbanking:server:OpenBankingMenuClient → ServerjobNameServer validates job+grade, fetches DB balance, fires OpenBankingUI back to the client.
gs-businessbanking:client:OpenBankingUIServer → Client{ jobName, balance, playerCash, playerBank }Opens the NUI panel with the provided data.
gs-businessbanking:server:TransactionClient → ServerjobName, direction, amount, payMethodProcesses a deposit or withdrawal from the NUI panel.
gs-businessbanking:client:UpdateBalanceServer → ClientnewBalancePushes the updated balance to the open NUI after a transaction.
