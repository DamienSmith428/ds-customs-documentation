DS ATM Robbery

Fully configurable ATM robbery with a custom NUI wire-cutting minigame, multi-inventory bridge, per-ATM cooldowns, police alerts, and a forensic fingerprint system — by DS Customs

v1.0.0 QBCore ds_progressbar ds_notify Lua 5.4 Escrow

1 — Overview

DS ATM Robbery turns every standard GTA V ATM prop into a robbable target. Players approach an ATM, use a configurable tool item to crack the casing via a ds_progressbar animation, then complete a custom NUI wire-cutting / decryption minigame to extract cash, marked bills, and bonus loot — all while risking a police alert at every stage.

The resource ships fully open in config.lua and is escrow-protected everywhere else. Inventory and notification systems are handled through a runtime bridge — no code changes are needed when switching between ox_inventory, qs-inventory, or qb-inventory.

Features

Two-stage robbery flowProgress bar (crack casing) → NUI wire-cut minigame (extract cash). Cancelling the bar refunds the tool item.
Custom NUI minigameFour difficulty presets (easy, medium, hard, insane) with individually tunable wire count, time limit, mistake tolerance, and sequence length.
Multi-inventory bridgeAuto-detects ox_inventory → qs-inventory → qb-inventory at runtime, or pin a specific system in config.

Per-ATM cooldownsCoord-key-based cooldown ensures each ATM cools down independently. Cooldown survives player reconnects.

3 — Installation

Drop-in

Copy the ds_atmrobbery folder into your resources directory. No SQL files to run.

server.cfg Start Order

ensure qb-core
ensure ds_progressbar
ensure ds_notify
ensure qb-policejob      # only needed if police alerts are enabled
ensure ds_atmrobbery
Inventory resources (ox_inventory, qs-inventory, qb-inventory) must be started before ds_atmrobbery when using Config.Inventory = 'auto' so the auto-detection query finds them already running.

Payouts

Each entry in Config.Payouts is evaluated independently on every successful robbery. A dice roll against the entry's chance field determines whether it fires. All passing entries are awarded — there is no mutual exclusion between entries.

KeyDefaultDescription
Config.MarkedMoneyItem'markedbills'Item name for marked/dirty money. When a payout entry uses this name, the resource gives 1 item with worth and serial metadata instead of stacking items.
Config.PayoutMultiplier1.0Global multiplier applied to all payout amounts. Use 0.5 for half, 2.0 for double.

Payout Entry Schema

{
    type    = 'cash',        -- 'cash' | 'bank' | 'item'
    chance  = 100,           -- % chance this entry fires (1–100)
    amount  = { min = 1500, max = 4500 },  -- random range, OR a fixed number
}

For type = 'item' entries, two additional fields control which items are given:

{
    type    = 'item',
    chance  = 35,
    pickOne = true,        -- true = pick ONE random entry from items[]; false = give all
    items   = {
        { name = 'goldbar',  amount = 1 },
        { name = 'diamond',  amount = { min = 1, max = 2 } },
    },
}

Luxury Jackpotitem (pickOne)8%One of: goldbar, diamond ×1–2, rolex, diamond_ring, goldchain ×1–2

5 — Robbery Flow

The robbery runs in four discrete server-verified steps. The item is never consumed until the progress bar fully completes — cancelling mid-bar gives it back.

StepWhereWhat happens
1 — Pre-flightServerPlayer presses E near an ATM. Server checks: minimum police, item presence, and per-ATM cooldown. If any check fails, the player is notified and nothing proceeds. On success, the server green-lights the client.
2 — Casing crackClientThe ds_progressbar plays with a two-handed ATM animation. The player is frozen in place. Pressing X cancels — the item is refunded and the pending crack is voided on the server.
3 — MinigameClient (NUI)Once the bar completes the server consumes the tool item, sets the ATM cooldown, optionally fires a start-phase police alert, and sends minigame settings to the client. The NUI wire-cutting game opens.
4 — ResultServerThe NUI reports pass/fail. Server distributes payouts on success or sends a failure message. Police alerts fire at the configured chance. A fingerprint is stored on the ATM for both outcomes.
ATM props are non-networked static world objects. The resource identifies them by a stable coord-key (atm_X_Y_Z) derived from the object's rounded world position — both client and server agree on this key without network entity IDs.

6 — The Minigame

The minigame runs entirely in the NUI layer (html/). It presents a wire-cutting panel and a decryption sequence. The player must cut the correct wires and input the right sequence within the time limit and mistake tolerance set by the active difficulty.

Outcomes

ResultTriggerWhat happens
PassPlayer completes all objectives within time and mistake limitsSuccess particle, success notification, server distributes payouts, success-phase police alert chance fires.
FailTime expired or mistake limit exceededFailure notification, no reward, fail-phase police alert chance fires.
AbortPlayer closes the UI with ESCNo reward, no police alert from this event. ATM cooldown still applies (the crack was completed).
To swap the NUI minigame for a Lua-based one (e.g. ps-ui, memorygame), replace the logic in client/minigame.lua and update the RegisterNUICallback handlers in client/main.lua. The server-side flow is untouched.

7 — Forensics System

Every robbery attempt (success or fail) can leave a fingerprint on the ATM. Online LEOs are notified in real-time when a fresh print is stored. Off-duty LEOs who come on duty automatically receive a sync of all currently active prints.

What gets stored

The server reads the player's biometric fingerprint from their QBCore metadata (metadata.fingerprint) — the same hash used by qb-multicharacter and other framework resources. This raw hash, along with the ATM coordinates and a timestamp, is stored in server memory.

How a LEO lifts a print

  1. LEO walks within Config.FingerprintLiftDistance (default 3 m) of an ATM that has a live print.
  2. The prompt "Aim flashlight to scan for prints" appears above the ATM.
  3. LEO enters free-aim (RMB) — the prompt updates to "[G] Lift Fingerprint".
  4. LEO presses G. The server validates job, TTL, prior-lift, tool item, and evidence bag.
  5. On success: the empty evidence bag is consumed and replaced with a filled bag containing fingerprint, crimeDate, and a formatted label in its metadata.

Filled evidence bag metadata

FieldExample valueDescription
fingerprint'Uv088g29BKp9973'Raw biometric hash from the suspect's QBCore metadata. Identity is unknown until cross-referenced with a lab/MDT system.
crimeDate'06/15/2025 22:45'Date and time the robbery took place.
label'Evidence Bag [ATM Print - 06/15/2025 22:45]'Human-readable display name shown in the inventory UI.

Rules & Edge Cases

RuleDetail
One collection per officerEach citizenid can lift a print from a given ATM only once. A second attempt is rejected without consuming the bag.
TTL expiryPrints degrade after Config.FingerprintTTL seconds. Expired prints are rejected and purged. A server-side thread runs every 60 seconds to clean up stale entries.
Print survives robbery failureA print is stored whether the robbery succeeded or failed — the suspect touched the ATM either way.
Print is overwrittenIf the same ATM is robbed again before its print degrades, the old print is replaced with the new robber's data.
No name in the bagThe filled evidence bag intentionally stores only the raw fingerprint hash. Identity resolution requires a separate MDT/lab lookup.

8 — Inventory Bridge

The bridge runs entirely server-side (bridge/inventory.lua). It exposes three functions used throughout the server: Inventory.HasItem, Inventory.AddItem, and Inventory.RemoveItem.

ModeHow it resolves
'auto'Checks if ox_inventory is started → falls back to qs-inventory → falls back to qb-inventory.
'ox'Always uses ox_inventory exports. Warns in console if the resource is not running.
'qs'Always uses qs-inventory exports.
'qb'Always uses qb-inventory exports.
'custom'Loads bridge/custom_inventory.lua which must define Inventory.HasItem, Inventory.AddItem, and Inventory.RemoveItem.
The resolved inventory type is printed to the server console on startup: [ds_atmrobbery] Inventory bridge resolved: qs. Check this line if items are not being added or removed correctly.

9 — Notification Bridge

The notify bridge runs on both client and server. It normalises notification type strings (success, error, info, warning) before forwarding to the chosen system.

ModeWhat it calls
'ds'Server: exports['ds_notify']:NotifyClient(src, msg, type, duration). Client: exports['ds_notify']:Notify(msg, type, duration).
'qb'Server: TriggerClientEvent('QBCore:Notify', src, msg, type). Client: QBCore.Functions.Notify(msg, type, duration).
'custom'Loads bridge/custom_notify.lua. Must define Notify.Send(src, message, ntype, duration) (server) and Notify.Send(message, ntype, duration) (client).

10 — Server Exports

Three exports are available for use by other resources on the server.

ResetATMCooldown

-- Reset the cooldown for a specific ATM by its coord key
exports['ds_atmrobbery']:ResetATMCooldown('atm_441_-982_30')

Clears the cooldown for one ATM so it can be robbed immediately. The coord key format is atm_X_Y_Z where X, Y, Z are the world coordinates rounded to the nearest integer.

ResetAllATMCooldowns

-- Reset cooldowns for all ATMs at once
exports['ds_atmrobbery']:ResetAllATMCooldowns()

GetATMCooldown

-- Get remaining cooldown seconds for an ATM (0 if not cooling down)
local remaining = exports['ds_atmrobbery']:GetATMCooldown('atm_441_-982_30')
if remaining > 0 then
    print('ATM is on cooldown for ' .. remaining .. 's')
end
Use GetATMCooldown to build a server-side admin command that shows which ATMs are currently cooling down.

11 — Marked Bills & Serials

When a payout entry's item name matches Config.MarkedMoneyItem (default 'markedbills'), the resource gives exactly 1 item with two metadata fields instead of stacking multiple items:

Metadata fieldExampleDescription
worth1450Dollar value of the bills, after the payout multiplier is applied.
serial'0615-384920571836'Tracing number — zero-padded month + day, dash, then 12 random digits. Formatted MMDD-############.

This approach is compatible with qb-bankrobbery and other resources that read the worth field from marked bills metadata. Set Config.MarkedMoneyItem = nil to disable this handling and treat marked bills like any other item.

12 — FAQ

My item is being consumed even when I cancel the progress bar.

This should not happen with the default configuration. The item is only consumed in the CrackComplete server event, which only fires after the progress bar finishes. Cancelling the bar triggers CrackAborted instead — which voids the pending crack without touching the item. Confirm that ds_progressbar is correctly firing its cancel callback when the player presses X.

Police alerts aren't firing.

Check that qb-policejob is started and running before ds_atmrobbery. Alerts are silently skipped if the resource is not in a started state. Also verify that the relevant chance value (AlertOnStartChance, etc.) is greater than 0. Enable Config.Debug = true to see alert logs in the server console.

LEOs can't see the fingerprint prompt.

Verify that the LEO's QBCore job has its type field set to 'leo' (or whatever value you have in Config.FingerprintLeoTypes). The forensics client thread only activates for players whose job type matches. Also check that Config.FingerprintChance is above 0 — if it's 0, no prints are ever stored.

How do I find an ATM's coord key to reset its cooldown?

Enable Config.Debug = true. The server will print the coord key when a robbery attempt is made: [ds_atmrobbery] Player X pre-flight approved for ATM atm_441_-982_30. Use that string with the ResetATMCooldown export.

Can I replace the NUI minigame with a Lua-based one?

Yes. The client/minigame.lua file is a thin placeholder — all minigame logic is in html/script.js. To swap it out, implement your replacement in client/minigame.lua and update the two RegisterNUICallback calls in client/main.lua (minigameResult and minigameAbort) to match your library's callbacks. The server-side flow is entirely unaffected.

Can I add custom ATM props?

Yes. Add the prop model name string to Config.ATMProps. The client builds a hash set from this list at startup using GetHashKey, so any valid GTA V model name (or any custom streamed prop) works as long as the model is loaded in the world.

Does this resource use a database?

No. There is no SQL. Cooldowns, pending crack state, and fingerprint records all live in server memory and reset when the resource or server restarts.
