DS Police Grappler

Fully server-authorised police spike-and-grapple system. Officers install a physical grappler arm onto supported patrol vehicles, deploy it to hook a fleeing suspect's rear tyre, and release when the tyre pops and the vehicle stops — with a police-styled NUI HUD, Discord logging, and multi-target support — by DS Customs

v1.1.0 QBX Core QB-Core ESX vRP ox_inventory qs-inventory qb-inventory ESX Inventory vRP Inventory oxmysql Lua 5.4 Escrow

1 — Overview

DS Police Grappler is a purpose-built law-enforcement tool for FiveM. A permitted officer (job-checked server-side) stands near a configured patrol vehicle and uses a target interaction or the /grappler install command to physically attach a custom prop arm to the rear of the vehicle. While driving, pressing Y deploys the arm and fires a rope toward the nearest eligible rear wheel of a target vehicle — popping the tyre, triggering a forced handbrake, and clamping the rope until the officer presses Y again to release.

All critical state transitions — install, deploy, attach, remove — are validated server-side before the client is allowed to proceed. A persistent NUI HUD shows live grappler status (Inactive / Installed / Deployed / Attached) and can be dragged to any position on screen; its position is saved per-player in MySQL and restored on next login.

config.lua is fully open and controls every tunable value. All other files are escrow-protected.

3 — Installation

Drop-in

Copy the ds_policegrappler folder into your resources directory (recommended path: inside a [police] or [leo] category folder).

Database

One table is created automatically by the resource on first start via server/ui.lua:

-- Created automatically — no manual SQL import needed
ds_grappler_ui_positions (
    citizenid  VARCHAR(50) PRIMARY KEY,
    pos_x      FLOAT,   -- HUD X position (percentage of viewport width)
    pos_y      FLOAT    -- HUD Y position (percentage of viewport height)
)
The table is created with CREATE TABLE IF NOT EXISTS — no manual SQL import is required. If the table already exists from a previous version, it is left untouched.

Inventory Item

Add the grappler item to your inventory's item definition file. The item definition and image are provided in the install/ folder:

  • install/item.txt — item definition (copy into your inventory's items file)
  • install/grappler.png — inventory image (copy into your inventory's images folder)

For ox_inventory, the item entry looks like this:

grappler = {
    label  = 'Police Grappler',
    weight = 1000,
    stack  = false,
    close  = true,
    image  = 'grappler.png',
},

server.cfg Start Order

ensure oxmysql
ensure qbx_core      # or qb-core / esx / vRP
ensure ox_inventory  # or whichever inventory you use
ensure ox_target     # or qb-target / ds_target
ensure ds_policegrappler

Discord Webhook

Open server/utils.lua and set your webhook URL at the top of the file:

local webhook = "https://discord.com/api/webhooks/YOUR_WEBHOOK_HERE"
Logging is enabled by default (logging.enabled = true in config.lua). If you leave the webhook blank, log calls will silently fail — no errors will be thrown but no messages will be posted.

vehicles{} — Supported Patrol Vehicles

Each key is a vehicle model hash (using the backtick hash syntax). Only vehicles listed here will show the Install target and accept the /grappler install command.

vehicles = {
    [`police`] = {
        name     = "Response Car",       -- used in logs only
        boneName = "engine",            -- attachment bone on the vehicle model
        offSet   = {0.0, 1.25, 0.0},  -- X / Y / Z offset from the bone
        rotation = {0.0, 0.0, 0.0},  -- pitch / roll / yaw adjustment
    },
}
To add a new vehicle, duplicate an entry and change the model hash key. Use developerMode = true to display bone position helpers in-world while tuning offSet and rotation.

5 — Grappler Flow

The grappler operates as a four-state machine. Each transition is server-authorised before the client proceeds.

StateHUD labelTriggerWhat happens
InactiveINACTIVEDefault / after removeNo props in world. Officer is on foot near a configured vehicle.
InstalledINSTALLEDTarget "Install Grappler" or /grappler installServer validates permission + inventory item. Client removes item, spawns bumper + frame props on the vehicle's engine bone. HUD turns on.
DeployedDEPLOYEDY key while drivingServer validates state. Client plays arm-swing animation, transitions the frame prop to the deployed variant, and begins scanning for a nearby rear wheel of any non-police vehicle within range.
AttachedATTACHEDRope connects to target tyreServer validates and confirms. Client spawns wheel-block prop on the target tyre, creates the native rope, bursts the tyre (if burstTyre = true), and starts the handbrake timer. Press Y to release.

Release & Remove

  • Pressing Y while Attached — releases the rope, deletes the wheel-block prop, returns state to Installed.
  • Pressing Y while Deployed (no attach) — retracts the arm, returns to Installed state.
  • Target "Uninstall Grappler" or /grappler remove (from Installed) — server validates, client deletes all props, returns the grappler item to the officer's inventory, state returns to Inactive.
  • /grappler reset — emergency reset command that forces all props to be deleted and state to reset to Inactive without returning the item.

NUI HUD

The /grapplerui command opens (or closes) the status HUD. The HUD is only functional for officers driving a vehicle that has the grappler installed. Four state pips update in real time via a polling NUI callback.

  • Hold N (control 249) — enters drag mode; the panel can be repositioned with the mouse.
  • Release N — exits drag mode and saves the new position to MySQL.
  • HUD position is loaded from MySQL on the next /grapplerui open.

9 — FAQ

The Install target option isn't appearing on my patrol vehicles.

Confirm the vehicle model is listed in vehicles{} in config.lua using the correct backtick hash ([`police`]). Confirm Target.targetResource matches your running target resource and that it is started before ds_policegrappler. Also verify Permissions.EnablePermissions and the active framework's job check — the officer must have the configured job or permissions for the target to be registered. Enable DEBUG_PRINT_ENABLED = true in config.lua and check the F8 console for target registration output.

The grappler deploys but never attaches to the target vehicle.

The rope will only connect if the target vehicle's rear wheel is within radiusToAttachToVehicle metres (default 2 m) when Y is pressed. The target vehicle's class must not be in disallowedVehicleClasses. Make sure the officer vehicle is close behind the target — the grappler is designed for PIT-manoeuvre range. Increase radiusToAttachToVehicle slightly if you find the tolerance too tight.

The grappler prop is in the wrong position on my vehicle.

Each vehicle has its own offSet and rotation values in vehicles{}. Enable developerMode = true to display live bone markers. Adjust the three floats in offSet (X/Y/Z) and rotation until the prop sits correctly on the rear bumper. Also try changing the boneName — some vehicle models attach better to a rear-specific bone.

Officers get "no permission" even though their job is set correctly.

Confirm that Permissions.EnablePermissions = true and that exactly one framework permission block has Enabled = true. The active block's CheckJob.Jobs array must contain a job name that exactly matches the player's job name as stored in the framework database (case-sensitive on some frameworks). Also check that the permission check server event fires — enable DEBUG_PRINT_ENABLED = true and watch the server console.

The NUI HUD isn't showing up.

Run /grapplerui to toggle the HUD on. The HUD is only operational when the officer is driving a vehicle that has a grappler installed. If you see the HUD briefly and it hides itself, the status poll returned "no active grappler" — confirm the vehicle is in the Installed state. If the HUD never appears, check the F8 console for NUI errors and confirm html/index.html is present and the resource started cleanly.

The grappler item isn't being returned on uninstall.

Confirm that Inventory has exactly one flag set to true and that it matches your running inventory resource. The item name in your inventory definition must match Inventory.itemName (default "grappler"). If using ox_inventory, confirm the item entry was added to ox_inventory/data/items.lua and the resource was restarted after the change.

Discord logs aren't posting.

Open server/utils.lua and confirm the webhook variable at the top of the file contains a valid Discord webhook URL. Confirm logging.enabled = true in config.lua. Test the webhook URL directly in a tool like Postman or a browser-based webhook tester to rule out Discord-side issues (rate limits, deleted channel, wrong URL).

Can I add more patrol vehicles?

Yes. Add a new entry to vehicles{} in config.lua using the vehicle's model hash as the key. Set an appropriate boneName (usually "engine" or a rear-bumper bone), then tune offSet and rotation with developerMode = true until the prop aligns correctly. No resource restart is required if you use ensure ds_policegrappler after saving the config.
