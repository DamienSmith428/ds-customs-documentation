DS Food Delivery

Lore-friendly food delivery app built on lb-phone. Customers order from real Los Santos restaurants, kitchen staff manage the live queue, and drivers earn pay and tips on every completed run — all inside a polished in-phone UI with live GPS tracking.

QBCore FiveM Lua 5.4 lb-phone oxmysql Escrow

1 — Overview

DS Food Delivery is a full-stack lb-phone app that connects customers, restaurant staff, and delivery drivers through a single live system. Every order flows through a server-authoritative state machine — from placement through kitchen confirmation, preparation, driver dispatch, pickup, and final delivery — with real-time push notifications at each stage.

DS Food Delivery ships as two resources that work together: ds-fooddelivery (the lb-phone app covered in this document) and ds-fooddelivery-tablet (a standalone in-world tablet for restaurant kitchen staff and bosses). The tablet resource is included in your purchase and is required for the full kitchen management experience. Both resources must be running and ensured together.

Feature summary

  • Full lb-phone app — customers, kitchen staff, and drivers each get their own personalised view inside a single app
  • Real-time order state machine — Pending → Confirmed → Preparing → Awaiting Driver → Out for Delivery → Arriving Soon → Delivered
  • Live GPS map — customers track their driver's position on a Leaflet map updated every 3 seconds
  • Driver portal — any player can register a driver account and accept deliveries; no specific job required
  • NPC orders — configurable random NPC delivery orders that appear on the driver board between real orders
  • Delivery bag prop — optional cityeats_prop hand prop spawned on drivers during active deliveries
  • Restaurant boss controls — set delivery fee, service fee, driver payout, and per-item prices live from the phone UI
  • Per-restaurant permissions — configure which job grade can accept, decline, view all orders, or disable ordering
  • Auto-progression timers — each order stage can auto-advance after a configurable delay (fully tuneable per stage)
  • Driver availability gates — optionally require an online or signed-in driver before customers can place orders
  • DB-driven menus — menus are stored in ds_fd_menu_items and managed by bosses in-app; no config restarts needed
  • Restaurant bank — every order credits the restaurant's internal bank; bosses view and manage it from the app
  • ds-fooddelivery-tablet — included companion resource providing a physical in-world tablet for kitchen order management

2 — Included Resources

Your purchase includes two separate FiveM resources that are designed to work together. Both must be installed and running.

ds-fooddelivery The lb-phone app — customer ordering, driver portal, live GPS, and kitchen queue view inside the phone Yes
ds-fooddelivery-tablet A standalone in-world tablet prop placed inside restaurant locations. Kitchen staff and bosses use it to accept, advance, and manage orders without opening their phone. Includes boss-bank and permission management screens. Yes — included with purchase
The tablet resource shares the same database tables as the phone app — orders accepted on the tablet appear instantly in the phone app and vice versa. Do not run the tablet resource without the main phone app resource also running.

4 — Installation

  1. Place both ds-fooddelivery and ds-fooddelivery-tablet inside your resources directory.
  2. Open ds-fooddelivery/config.lua and review all settings — at minimum verify Config.PaymentAccount and Config.DriverAvailability (see §5).
  3. Open ds-fooddelivery/restaurants/ — each .lua file defines one restaurant. Adjust job, pickup_location, and permissions to match your server's job names and map positions (see §6).
  4. If NPC orders are enabled, review npc_config.lua for spawn timing, pay scale, and drop-off zones (see §7).
  5. Add ensure ds-fooddelivery and ensure ds-fooddelivery-tablet to server.cfg after all dependencies.
  6. All database tables are created automatically on first resource start — no manual SQL import is required.
  7. Menu items for each restaurant are managed in-app by boss-grade employees. No menu data is pre-seeded; bosses add items after the first start via the Restaurant Bank / Menu screen.
# server.cfg — ensure in this order
ensure oxmysql
ensure lb-phone
ensure qb-core

ensure ds-fooddelivery
ensure ds-fooddelivery-tablet
The tablet resource must be ensured after ds-fooddelivery because it relies on the shared database tables that the main resource creates on startup.

5 — Configuration — config.lua

config.lua is open (not escrowed) and is the primary settings file. All keys are documented inline.

Global Settings

KeyDefaultDescription
Config.AppIdentifier"ds-fooddelivery"lb-phone app ID — must be unique server-wide. Do not change after first run.
Config.UseDeliveryBagProptrueSpawn the cityeats_prop bag on the driver's hand during active deliveries. Set false to skip entirely.
Config.PaymentAccount"bank"Which account is charged for orders: "bank" or "cash"

Driver Availability

Config.DriverAvailability = {
    RequireDriverOnline   = false,  -- true = at least one registered driver must be online
    RequireDriverSignedIn = false,  -- true = at least one of those drivers must be signed into the portal
}

Both flags are independent. RequireDriverSignedIn only has effect when RequireDriverOnline is also true.

Order Auto-Progression Timings

After a restaurant employee accepts an order, each status stage can auto-advance after a configurable delay. Set any timer to 0 to disable auto-advancement for that stage (the employee must advance it manually or use the tablet).

Config.OrderTimings = {
    confirmed      = 2  * 60 * 1000,  -- 2 min  → Preparing
    preparing      = 5  * 60 * 1000,  -- 5 min  → Awaiting Driver
    awaitingDriver = 0,                -- stays until a driver claims it manually
    outForDelivery = 10 * 60 * 1000,  -- 10 min → Arriving Soon
    arrivingSoon   = 2  * 60 * 1000,  -- 2 min  → Delivered
}

Global Categories

Categories are seeded into ds_fd_categories once on first start using INSERT IGNORE. Subsequent restarts do not overwrite any boss-added categories. To add a new global category, add an entry here and restart once (or INSERT directly into the DB).

Config.Categories = {
    { id = "all",     label = "All"     },
    { id = "burgers", label = "Burgers" },
    { id = "pizza",   label = "Pizza"   },
    { id = "drinks",  label = "Drinks"  },
    { id = "mexican", label = "Mexican" },
    { id = "coffee",  label = "Coffee"  },
}

Order Status Keys

KeyValueMeaning
PENDING"pending"Order placed, awaiting kitchen confirmation
CONFIRMED"confirmed"Kitchen accepted the order
PREPARING"preparing"Kitchen is actively preparing the order
AWAITING_DRIVER"awaiting_driver"Order is ready; waiting for a driver to claim it
OUT_FOR_DELIVERY"out_for_delivery"Driver has claimed the order and is en route
ARRIVING_SOON"arriving_soon"Driver is near the delivery address
DELIVERED"delivered"Order successfully delivered
DECLINED"declined"Kitchen declined — customer refunded automatically
CANCELLED"cancelled"Order cancelled

6 — Adding Restaurants

Each restaurant is a separate .lua file inside restaurants/. The resource loads all files matching restaurants/*.lua automatically — add a new file to add a new restaurant, no other changes required.

Restaurant schema

Config.Restaurants["pearls_diner"] = {
    id          = "pearls_diner",
    name        = "Pearl's Diner",
    description = "$$ · Burgers · 20–35 min",
    categories  = { "burgers", "drinks" },  -- global category IDs from Config.Categories
    rating      = 4.7,
    reviewCount = 0,
    eta         = "20–35 min",
    priceRange  = "$$",

    image = "images/pearls_diner/main/hero.png",  -- relative to resource root
    logo  = "images/pearls_diner/main/logo.png",

    job = "pearls",  -- QBCore job name for kitchen staff

    -- Driver pickup location — where drivers collect the order in-world
    pickup_location = vector4(-1905.35, -1311.24, 3.05, 140.53),

    -- Permission grade thresholds — seeded to DB on first start, boss-editable after
    permissions = {
        CanAcceptOrders  = 0,   -- any employee
        CanDeclineOrders = 0,
        CanCancelOrders  = 0,
        CanViewAllOrders = 0,
        CanDisableOrders = 3,   -- grade 3+
        IsBoss           = 5,   -- grade 5 only
    },
}

Restaurant fields reference

FieldTypeDescription
idstringUnique internal key — matches the table index. Used as the primary key in every DB table.
namestringDisplay name shown in the app.
descriptionstringShort subtitle shown on the restaurant card (e.g. price range and cuisine type).
categoriestableArray of global category IDs this restaurant belongs to. Used for the Home screen filter bar.
jobstringQBCore job name. Players with this job see the Kitchen view in-app and can use the tablet.
pickup_locationvector4World coordinates (x, y, z, heading) where drivers collect orders. Set this to a position inside or just outside the restaurant.
imagestringPath to the hero banner image relative to the resource root. Place images inside images/<restaurant_id>/main/.
logostringPath to the restaurant logo (square format recommended) — shown in order history and driver info cards.
permissionstableMinimum job grade required for each permission. Seeded to ds_fd_permissions on first start only — bosses can edit live via the tablet.
The permissions block is only written to the database once (on first start, using INSERT IGNORE). After that, changes in config have no effect — use the boss tablet to update permission grades on a live server.

Adding restaurant images

Create a folder at images/<restaurant_id>/main/ inside the resource root and place two images there:

  • hero.png — wide banner shown at the top of the restaurant page (recommended: 1280×400 px)
  • logo.png — square logo shown on the restaurant card and in order history (recommended: 256×256 px)

7 — NPC Orders (npc_config.lua)

NPC orders are randomly generated deliveries that appear on the driver board when no restaurant orders are available, keeping drivers active at quieter times. NPC orders skip the kitchen queue entirely — they appear directly as awaiting_driver and pay the driver on completion. No restaurant bank account is involved.

npc_config.lua is fully open (not escrowed).

Core settings

KeyDefaultDescription
NpcConfig.EnabledtrueSet false to completely disable NPC order generation.
NpcConfig.SpawnInterval4 minHow often the server rolls for a new NPC order.
NpcConfig.SpawnChance0.65Probability (0.0–1.0) of an order being created each interval.
NpcConfig.MaxActiveOrders6Maximum unclaimed NPC orders in the queue at any time.
NpcConfig.ClaimTimeout8 minHow long an unclaimed NPC order remains before auto-deletion.
NpcConfig.DeliveryTimeout20 minHow long a claimed order may stay open before auto-cancellation (protects against driver disconnects).

Pay scale

NpcConfig.BasePayMin  = 8   -- minimum base dollars regardless of distance
NpcConfig.BasePayMax  = 18  -- maximum random base before distance bonus
NpcConfig.PayPerKm    = 3   -- extra dollars per km (straight-line distance)
NpcConfig.PayRoundTo  = 1   -- round payout to nearest dollar

Drop-off zones

NPC customer drop-off locations are defined in NpcConfig.DropOffZones as an array of { coords = vector4(...), label = "Name" } entries. The default set covers locations across the full GTA V map. Add or remove entries freely.

Visual settings

KeyDefaultDescription
NpcConfig.BoardLabel"🤖 NPC Order"Tag shown on the driver board next to NPC orders so they are visually distinct from player restaurant orders.
NpcConfig.BlipColour5 (yellow)GTA blip colour for NPC pickup points.
NpcConfig.BlipSprite68GTA blip sprite for NPC pickup points.

Marker settings

A GTA world marker is drawn at the restaurant pickup point for NPC orders. Configure it via NpcConfig.Marker:

NpcConfig.Marker = {
    enabled      = true,
    type         = 1,              -- cylinder (see FiveM marker docs for other types)
    drawDistance = 30.0,           -- metres before the marker appears
    size         = { x = 1.5, y = 1.5, z = 0.5 },
    color        = { r = 255, g = 185, b = 0, a = 180 },  -- amber, semi-transparent
    rotate       = false,
    bobUpDown    = false,
}

8 — Gameplay Loop

Customer — Ordering

Open lb-phone and launch the Food Delivery app. On first launch, create or log into a customer account. Browse restaurants by category, tap a restaurant to view its menu, add items to the cart, optionally add a tip, and confirm the order. Payment is deducted immediately from the configured account. Real-time status updates appear as lb-phone push notifications at every stage change.

A live GPS map is visible on the active order card once a driver has been assigned — it polls the driver's position every 3 seconds and shows their pin on a Leaflet map. Customers can also tap Send to Messages to receive the driver's coordinates as an lb-phone location pin via SMS.

Kitchen Staff — Order Queue

Players with the restaurant's job see a Kitchen view inside the app showing all pending and active orders. Employees can accept or decline pending orders, and manually advance accepted orders through the Preparing → Awaiting Driver stages. The ds-fooddelivery-tablet companion resource provides a dedicated in-world tablet for this workflow — ideal for immersive kitchen roleplay.

Restaurant Boss — Management

Boss-grade employees (grade ≥ IsBoss threshold) see additional tabs: Restaurant Bank (view funds, set delivery fee, service fee, and driver payout), Menu Editor (add, edit, remove menu items and prices), and Permissions (adjust grade thresholds for each permission live without restarting). All changes persist to the database immediately.

Driver — Deliveries

Any player can open the Driver Portal on the app's login screen, create a driver account, and start accepting deliveries — no specific job is required. The driver board shows all awaiting_driver orders (both restaurant and NPC) with the estimated payout and distance. Claim an order to receive a waypoint to the restaurant pickup. Once on-site, confirm pickup to switch the waypoint to the customer's location, then confirm delivery to receive payout. Tips from the customer's order are paid directly on top of the restaurant's configured driver payout.

Driver — NPC Orders

If NpcConfig.Enabled = true, NPC orders appear on the driver board between real restaurant orders. They are labelled with NpcConfig.BoardLabel (default: 🤖 NPC Order) and show a randomised pay amount based on straight-line distance. A customer NPC ped spawns at the drop-off point when the driver enters the delivery phase and despawns automatically on completion.

9 — Database Tables

All tables are created automatically on first resource start using CREATE TABLE IF NOT EXISTS. No manual SQL import is required.

TablePurpose
ds_fd_restaurantsOne row per restaurant. Stores delivery fee, service fee, driver payout, and accumulated bank funds. Auto-seeded from Config.Restaurants on startup.
ds_fd_menu_itemsDB-driven menu — items are added and managed by bosses in-app. Supports label, description, price, category, image URL, and sort order.
ds_fd_categoriesGlobal and per-restaurant categories. Global rows (restaurant_id = NULL) power the Home screen filter bar. Seeded from Config.Categories on first start.
ds_fd_restaurant_categoriesMany-to-many mapping of restaurants to global categories. Seeded from restaurant.categories in config.
ds_fd_permissionsPer-restaurant permission grade thresholds. Seeded once from restaurant.permissions; bosses edit live.
ds_fd_ordersOrder records. Stores full item JSON, all fee fields, status, driver assignment, and delivery coordinates.
ds_fd_accountsCustomer app accounts (username, password hash, profile picture, citizenid).
ds_fd_driver_accountsDriver portal accounts. Stores username, password hash, profile picture, and lifetime earnings stats.
ds_fd_npc_ordersActive NPC-generated orders. Cleaned up automatically on claim timeout or delivery completion.
The ds-fooddelivery-tablet resource reads and writes to the same tables as the phone app. Ensure both resources are running before using either interface.

10 — Fees & Payouts

Fee values are stored per-restaurant in ds_fd_restaurants and are seeded with the defaults below on first start. They are fully editable at runtime by boss-grade employees via the Restaurant Bank screen (in-app or on the tablet).

FeeDefaultWho pays / receives
delivery_fee$4.00Charged to the customer on top of the subtotal. Credited to the restaurant bank.
service_fee$2.00Charged to the customer on top of the subtotal. Credited to the restaurant bank.
driver_payout$5.00Deducted from the restaurant bank and paid to the driver on delivery completion.
tipPlayer-setOptionally added by the customer at checkout (capped at $100). Paid directly to the driver on top of the payout.

The full order total charged to the customer is: subtotal + delivery_fee + service_fee + tip. The restaurant bank receives the full total on order placement. The driver receives driver_payout + tip on delivery completion, deducted from the restaurant bank.

13 — Notes & FAQ

  • All database tables are created automatically on first resource start. There is no SQL file to import manually.
  • The permissions block in each restaurant config is only seeded once (INSERT IGNORE). After the first start, use the boss tablet or phone app to change grade thresholds — config changes have no effect on existing rows.
  • Restaurant fee defaults (delivery_fee, service_fee, driver_payout) are similarly seeded once. Edit them in-app via the Restaurant Bank screen.
  • Menu items are entirely DB-driven — there is no menu array in config. Bosses add items after the first start via the Menu Editor in the app or on the tablet.
  • The ds-fooddelivery-tablet resource must be ensured after ds-fooddelivery in server.cfg. Both resources share the same database tables; the phone app creates them on startup.
  • Changing Config.AppIdentifier after first run will break all persisted login sessions — lb-phone stores sessions keyed by app identifier.
  • The delivery bag prop (cityeats_prop) is streamed from inside the ds-fooddelivery resource. Set Config.UseDeliveryBagProp = false to disable it if the prop causes issues with other stream resources.
  • NPC orders do not involve any restaurant account — payout goes directly to the driver's configured payment account. They appear on the same driver board as real orders and are distinguished by NpcConfig.BoardLabel.
  • The live GPS map requires the driver to be online and have an active delivery session. If the driver goes offline mid-delivery the map will stop updating but the order remains in the database.
  • If Config.DriverAvailability.RequireDriverOnline = false (the default), customers can place orders at any time regardless of whether any drivers are currently online.
