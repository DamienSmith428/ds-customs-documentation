DS Food Delivery

Lore-friendly food delivery app built on lb-phone. Customers order from real Los Santos restaurants, kitchen staff manage the queue, and delivery drivers earn pay and tips on every completed run — all through a polished in-phone UI. Includes an autonomous NPC order system so drivers always have work even when the server is quiet.

QBCore FiveM Lua 5.4 lb-phone oxmysql v1.0.1

1 — Overview

DS Food Delivery integrates directly with lb-phone as a custom app called City Eats. Every part of the delivery pipeline — from a customer browsing the menu to a driver marking the order delivered — happens inside the phone, using native lb-phone callbacks, notifications, and the live-tray lock-screen widget.

Feature summary

  • Full lb-phone custom app — registered programmatically with icon, name, and description
  • Four pre-built player-operated lore-friendly restaurants: Burger Shot, Pizza This…, Bean Machine, and Los Santos Taco
  • Five pre-built NPC-operated restaurants: Cluckin' Bell, Taco Bomb, Wigwam Burger, Bean Machine (NPC), and Sub Urban Sub
  • Customers browse menus, build a cart, add a tip, and pay via bank or cash
  • Restaurant staff tab — accept / decline / advance orders, see the full live queue
  • Driver portal tab — claim available deliveries, follow GPS waypoints, mark as picked up & delivered
  • NPC order system — server auto-generates deliveries every few minutes so drivers always have work, even with no active players ordering
  • NPC deliveries go to a randomly spawned NPC ped at a random drop-off zone across Los Santos; driver completes pickup/handoff animations
  • Live tray (lock-screen widget) tracks order progress from confirmation through delivery
  • In-app map with live driver dot — customer can see the driver moving in real time
  • Driver GPS broadcast every 5 seconds — customer can also tap Call to reach the driver directly through lb-phone
  • Two-phase waypoint system: driver gets a restaurant blip first, then the customer blip once they confirm pickup
  • Persistent GPS waypoint — auto-recreated every 2 seconds to prevent GTA from clearing it on arrival
  • Delivery bag prop (cityeats_prop) — custom 3D bag attached to the driver's left hand while on a delivery, despawns in vehicles and respawns on exit
  • Restaurant boss screen — set delivery fee, service fee, driver payout, deposit/withdraw business bank, send payroll
  • Boss-adjustable per-item menu prices stored in the database — changes take effect immediately without a restart
  • Separate app account system for customers and drivers (username + password, profile picture)
  • Order auto-progression state machine — configurable timers advance orders through each status automatically
  • Fully modular restaurant files — add a new restaurant by adding a single .lua file to restaurants/ or npc-restaurants/

2 — Dependencies

No additional bridge resources are needed. DS Food Delivery communicates entirely through the standard lb-phone callback and notification APIs — no external UI or notification resource is required.

3 — Installation

  1. Place the ds-fooddelivery folder inside your resources directory.
  2. Assign a QBCore job name to each restaurant you want to enable in the relevant restaurants/*.lua file.
  3. Add ensure ds-fooddelivery to server.cfg after lb-phone, qb-core, and oxmysql.
  4. Restart the server — all database tables are created automatically on first start.
# server.cfg — ensure dependencies before the resource
ensure oxmysql
ensure qb-core
ensure lb-phone

ensure ds-fooddelivery
Database tables are created with CREATE TABLE IF NOT EXISTS and restaurant rows are seeded with INSERT IGNORE. Existing fee/price data is never overwritten by a restart.

4 — Configuration

Two open configuration files control all behaviour: config.lua for global settings and npc_config.lua for the autonomous NPC order system.

4.1 — config.lua

Global Settings

KeyDefaultDescription
Config.AppIdentifier"ds-fooddelivery"Unique app ID registered with lb-phone. Must not clash with any other custom app on the server.
Config.UseDeliveryBagProptrueWhen true, spawns the custom cityeats_prop delivery bag on the driver's left hand for the duration of the delivery. Set to false to disable the prop.
Config.PaymentAccount"bank"Which player account is charged for orders. Accepts "bank" or "cash".

Order Auto-Progression Timings

After a restaurant employee accepts an order, a server-side timer automatically advances the order through each status stage. Set any value to 0 to require a manual action for that stage.

Config.OrderTimings = {
    confirmed      = 2  * 60 * 1000,   -- 2 min  → Preparing
    preparing      = 5  * 60 * 1000,   -- 5 min  → Awaiting Driver
    awaitingDriver = 0,               -- 0 = stays until a driver claims manually
    outForDelivery = 10 * 60 * 1000,   -- 10 min → Arriving Soon
    arrivingSoon   = 2  * 60 * 1000,   -- 2 min  → Delivered
}

4.2 — npc_config.lua

Controls the autonomous NPC order system. All keys live in the NpcConfig table.

Feature Toggle & Timing

KeyDefaultDescription
NpcConfig.EnabledtrueMaster toggle. Set to false to disable all NPC order generation.
NpcConfig.SpawnInterval4 minHow often the server attempts to generate a new NPC order.
NpcConfig.SpawnChance0.65Probability (0.0–1.0) that an order is created on each interval tick.
NpcConfig.MaxActiveOrders6Maximum number of unclaimed NPC orders that can exist at any one time.
NpcConfig.ClaimTimeout8 minTime before an unclaimed NPC order is automatically cancelled and removed.
NpcConfig.DeliveryTimeout20 minTime a driver has to complete an NPC delivery after claiming it.

NPC Driver Pay

KeyDefaultDescription
NpcConfig.BasePayMin8Minimum base payout ($) for an NPC delivery.
NpcConfig.BasePayMax18Maximum base payout ($) — a random value between min and max is picked each time.
NpcConfig.PayPerKm3Extra dollars added to payout per kilometre of distance between pickup and drop-off.
NpcConfig.PayRoundTo1Round payout to the nearest n dollars (1 = nearest dollar).

Drop-Off Zones

NPC orders use a fixed pool of 18 drop-off zones spread across the map. Each zone has a coords (vector4 with heading) and a label shown on the driver's delivery board. Add or remove zones in NpcConfig.DropOffZones to control where NPC orders can be delivered.

Customer Peds

NpcConfig.CustomerPeds holds 25+ GTA ped model names. When an NPC delivery is activated, a ped is randomly selected from this list and spawned at the drop-off zone for the driver to hand off to.

6 — NPC Order System

The NPC order system generates autonomous deliveries on the server so drivers always have work available, regardless of how many real players are ordering. NPC orders appear on the same driver board as player orders and are visually marked with a robot icon (🤖 NPC Order) and a yellow blip.

Order Lifecycle

  1. Every NpcConfig.SpawnInterval (default 4 min) the server checks whether to create a new order. There is a NpcConfig.SpawnChance (65%) chance a new order is generated, up to NpcConfig.MaxActiveOrders concurrent unclaimed orders.
  2. An NPC restaurant is selected at random (weighted by each restaurant's weight value). A random drop-off zone and a random customer ped model are also chosen.
  3. Payout is calculated: random(BasePayMin, BasePayMax) + distanceKm × PayPerKm + base_pay_bonus.
  4. The order appears on the driver board. If no driver claims it within NpcConfig.ClaimTimeout (8 min), it is automatically deleted.
  5. Driver claims the order — a yellow blip and GPS waypoint appear for the restaurant pickup location.
  6. Driver arrives at the restaurant counter and presses E to confirm pickup (plays a 3-second animation).
  7. Waypoint switches to the NPC drop-off zone.
  8. At the drop-off, a random NPC ped spawns. The driver approaches and presses E to hand off (plays a 3-second animation).
  9. The NPC ped despawns. The driver receives their payout directly to cash. Lifetime stats are updated in ds_fd_driver_accounts.
  10. If the driver doesn't complete delivery within NpcConfig.DeliveryTimeout (20 min), the order is auto-cancelled.

7 — Database Tables

All tables are created automatically by DB.Init() on the first resource start. No manual SQL import is required.

TablePurpose
ds_fd_restaurantsOne row per restaurant. Stores live delivery fee, service fee, driver payout, whether the restaurant accepts orders (accepts_orders), and the restaurant bank balance (bank_funds). Seeded from Config.Restaurants using INSERT IGNORE — boss changes survive restarts.
ds_fd_pricesBoss-set per-item menu prices. When a boss changes a price via the Menu Manage screen it is written here. Orders always use DB prices, not config defaults, once this row exists.
ds_fd_ordersEvery player-placed order. Tracks status, items (JSON), all fee breakdowns, driver assignment, pickup phase flag, and both restaurant pickup and customer delivery coordinates.
ds_fd_accountsCustomer app accounts. Stores username, hashed password, preferred payment method, and profile picture. A citizen can have multiple accounts — all tied to username, not citizen ID.
ds_fd_driver_accountsDriver portal accounts. Separate from customer accounts. Stores driver username, password, profile picture, and lifetime earnings stats (lifetime_tips, lifetime_base, lifetime_total).
ds_fd_npc_ordersAuto-generated NPC deliveries. No customer_id or items JSON — stores restaurant name, pickup/delivery coords, driver payout, distance, assigned driver, claim/delivery deadlines, and whether the driver confirmed pickup (pickup_confirmed).
Migration queries using ADD COLUMN IF NOT EXISTS run on every resource start. These are safe to run on an existing database — columns that already exist are silently skipped.

8 — Order Flow

Customer Places an Order

  1. Player opens City Eats in lb-phone and logs in (or creates an account).
  2. Browses restaurants, selects items, optionally adds a tip, and taps Place Order.
  3. The server validates all items and prices server-side, deducts the full total from the player's account, and writes the order to the DB.
  4. The customer's current world coordinates are captured at order time — this becomes the delivery drop-off location.
  5. All online kitchen staff at the restaurant receive a phone notification and the order appears in their Staff tab.
  6. The customer's order tracker screen shows the order as Pending.

Kitchen Staff Manages the Queue

  1. Staff open City Eats → Staff tab → tap the incoming order.
  2. Accept — moves order to confirmed. The auto-progression timer starts immediately. The customer receives a push notification and live-tray update.
  3. Decline — moves order to declined and issues a full refund to the customer's account automatically.
  4. Staff can also manually Advance an order from confirmed → preparing, or preparing → awaiting_driver, overriding the auto timer.
  5. Once the order reaches awaiting_driver, all online delivery drivers receive a push notification and the order appears on their Deliveries board.

Delivery Driver Completes the Run

  1. Driver opens City Eats → Deliveries tab and taps an available delivery to claim it.
  2. Claiming is atomic — only one driver can claim each order. Other drivers see the order disappear from their board instantly.
  3. A blue restaurant blip and persistent GPS waypoint appear on the driver's map pointing to the kitchen pickup location. If Config.UseDeliveryBagProp is true, the delivery bag prop attaches to the driver's left hand.
  4. Driver drives to the restaurant, taps I've Picked Up in the app.
  5. The restaurant blip is removed and replaced with a customer blip at the delivery address. The waypoint switches to the customer's location.
  6. Driver drives to the customer and taps Mark as Delivered.
  7. The driver receives their payout (base payout from the restaurant bank + customer tip) directly to their QBCore account. The delivery bag prop is removed.
  8. The customer receives a Your food has arrived notification. The order tracker updates to Delivered.

9 — Fees & Payments

Every player order involves three fees in addition to the item subtotal. All default values are seeded into ds_fd_restaurants on first start. Bosses can change them live in-app via the Restaurant Bank screen.

FeeDefaultWho pays / who earns
delivery_fee$4.00Paid by the customer. Goes into the restaurant bank balance.
service_fee$2.00Paid by the customer. Goes into the restaurant bank balance.
driver_payout$5.00Deducted from the restaurant bank when the driver marks the order delivered. Paid directly to the driver.
tip$0.00 (customer-set)Optional. Paid by the customer, added on top of the total. Paid directly to the driver on delivery — not held in the restaurant bank.
The total charged to the customer is: subtotal + delivery_fee + service_fee + tip. The restaurant bank accumulates the full order total (including fees) on each order, then pays out driver_payout per completed delivery.

For NPC orders, the payout goes directly to the driver as cash — no restaurant bank is involved.

10 — Live Features

Live Tray (Lock Screen Widget)

When a customer places an order a live tray entry is created on the lb-phone lock screen. It shows the current status string and a progress bar that advances as the order moves through each stage. Tapping the tray opens the City Eats app directly. The tray is removed automatically when the order is delivered, declined, or cancelled.

In-App Driver Map

While an order is out_for_delivery, the customer's order detail screen shows a minimap with a live driver dot. The driver's position is broadcast to the server every 5 seconds and relayed to the customer. The dot stops updating when the order is delivered or the driver drops it.

Call the Driver

The customer's order detail screen shows the driver's phone number with a Call button. Tapping it uses lb-phone's native CreateCall export to initiate a call directly through the in-game phone — no additional call resource is needed.

Delivery Bag Prop

When a driver claims any delivery (player or NPC), a custom cityeats_prop bag is spawned as a networked object and attached to the driver's left hand bone. The prop automatically despawns when the driver enters a vehicle and re-attaches when they exit. It is fully cleaned up when the delivery is completed or dropped. This behaviour is controlled by Config.UseDeliveryBagProp.

13 — Notes & FAQ

  • Can I add my own restaurant? Yes — create a new .lua file in restaurants/ following the schema in §5.1. The resource loads all files in that folder automatically. No other files need editing.
  • Can I add my own NPC restaurant? Yes — create a new .lua file in npc-restaurants/ following the NPC restaurant schema in §5.2. Set enabled = true and a pickup_location. The resource loads all files in that folder automatically.
  • Can I disable a restaurant? Remove or rename its file in restaurants/ and restart the resource. Existing orders for that restaurant remain in the database but the restaurant will no longer appear in the app.
  • Can I disable NPC orders entirely? Set NpcConfig.Enabled = false in npc_config.lua and restart the resource.
  • The boss changed fees but the old values still show. Fee changes take effect immediately on the next order — the cart screen always fetches live fees from the server before displaying the checkout total.
  • Order prices changed in config but the menu still shows old prices. Once a boss sets a price via the Menu Manage screen, the DB value overrides the config default. Reset the row in ds_fd_prices to revert to the config default.
  • Driver GPS stops updating. The broadcast loop is tied to the order being out_for_delivery. If the order was auto-advanced to arriving_soon the loop stops — this is by design. The customer will still see the last known position.
  • The persistent waypoint keeps reappearing after I arrive. This is intentional — the waypoint is kept alive until the driver taps I've Picked Up or Mark as Delivered. It prevents GTA's auto-clear from removing navigation before the driver is done.
  • The delivery bag disappears when I get in my car. This is by design — the prop despawns on vehicle entry and re-attaches when you exit. Disable this behaviour by setting Config.UseDeliveryBagProp = false.
  • Can I use a different payment type per restaurant? Not currently — Config.PaymentAccount is a global setting. All orders use the same account type.
  • Does the app manage player inventories or give items automatically? No — DS Food Delivery does not touch inventories at any point. Item trading is handled entirely in-game through roleplay: customers trade with restaurant staff to receive their order, and drivers hand items over to customers directly. The app manages the order queue, payments, and driver dispatch only.
  • The app doesn't appear in lb-phone. Make sure lb-phone is started before ds-fooddelivery in server.cfg. The resource waits for lb-phone to reach started state before registering the app, and re-registers automatically if lb-phone restarts.
  • NPC orders appear on the driver board but nobody claims them. NPC orders expire after NpcConfig.ClaimTimeout (default 8 min) and are automatically removed. Lower NpcConfig.MaxActiveOrders or increase NpcConfig.SpawnInterval to reduce board clutter if needed.
