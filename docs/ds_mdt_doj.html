DS MDT — DOJ

Department of Justice terminal for judges, prosecutors, and defense attorneys — by DS Customs

v1.0.0 QBCore Lua 5.4 Escrow ds_notify Requires ds_mdt

1 — Overview

DS MDT DOJ is the legal-system companion to DS MDT. It gives judges, prosecutors, and defense attorneys their own dedicated terminal with a role-based access model. The two resources share a database: ds_mdt_doj reads case files, reports, statements, and evidence from ds_mdt's tables and writes its own DOJ-specific tables for motions, hearings, verdicts, court orders, and case assignments.

ds_mdt_doj requires ds_mdt to be running. It calls three exports on ds_mdt (ApproveWarrantRequest, DenyWarrantRequest, GetPendingWarrantRequests) and reads ds_mdt's tables directly.

Three roles

RoleKey abilities
judgeApprove/deny warrant requests, issue court orders, schedule hearings, record verdicts, assign counsel, share police reports/statements with defense.
prosecutionFile motions, respond to defense motions, view assigned case reports. DAs can also request warrants on behalf of police (rank-gated).
defenseFile motions, respond to prosecution motions, view police reports/statements only when explicitly shared by the judge on their assigned case.

4 — Installation

Database Setup

Run ds_mdt's sql/install.sql first if you haven't already. Then run ds_mdt_doj's own SQL file.

Fresh install

Run sql/install.sql. Creates all ds_mdt_doj tables. Safe to re-run.

Existing install

Run sql/alter.sql. Adds tables introduced in v1.1–v1.3 without touching existing data.

Job → Role mapping (Config.JobRoles)

Maps QBCore job.name values to one of three roles. Any job not listed is denied access.

    -- Judges
    ['judge']            = 'judge',
    ['doj']              = 'judge',
    -- Prosecutors
    ['prosecutor']       = 'prosecution',
    ['districtattorney'] = 'prosecution',
    ['ada']              = 'prosecution',
    -- Defense
    ['defense']          = 'defense',
    ['publicdefender']   = 'defense',
    ['attorney']         = 'defense',
}

7 — Developer API

Server Exports

GetDOJRole(Player) string|nil

Returns the role string ('judge', 'prosecution', 'defense') for the given QBCore Player, or nil if the player has no DOJ role or doesn't meet Config.MinGrade.

local Player = exports['qb-core']:GetPlayer(source)
local role   = exports['ds_mdt_doj']:GetDOJRole(Player)
if role == 'judge' then
    -- player is a judge
end

IsDOJAllowed(Player) boolean

Returns true if the player has any DOJ role at the required minimum grade. Shorthand for GetDOJRole(Player) ~= nil.

if exports['ds_mdt_doj']:IsDOJAllowed(Player) then
    -- player can access the DOJ terminal
end

NotifyAllDOJ(msg, ntype, duration)

Sends a ds_notify toast to every on-duty DOJ member (all three roles).

exports['ds_mdt_doj']:NotifyAllDOJ('Court is now in session.', 'info', 5000)

Net Events — Client → Server

ds_mdt_doj:server:approveWarrantRequest (requestId, judgeNotes)

Judge approves a warrant request. Calls exports['ds_mdt']:ApproveWarrantRequest() internally. Rank-gated by Config.Ranks.ApproveWarrant.

ds_mdt_doj:server:denyWarrantRequest (requestId, reason)

Judge denies a warrant request with a written reason. Calls exports['ds_mdt']:DenyWarrantRequest() internally. A denial reason is required.

ds_mdt_doj:server:clockIn / ds_mdt_doj:server:clockOut

Toggle duty status. On clock-in, a row is upserted into mdt_doj_unit_status. On clock-out, the row is deleted. Fires ds_mdt_doj:client:unitStatusUpdated and ds_mdt_doj:client:rosterUpdated to all open terminals.

ds_mdt_doj:server:setUnitStatus (status)

Updates a DOJ member's unit status. Valid values: 'available', 'in-chambers', 'in-court', 'off-duty'.

Server Event (incoming from ds_mdt)

ds_mdt_doj:warrantRequestReceived (requestId, data)

Fired by ds_mdt's server when an officer submits a warrant request. ds_mdt_doj handles this by notifying all on-duty judges via ds_notify and broadcasting a live refresh to all open DOJ terminals.

data fields: citizenid, suspectName, charges, details, caseNumber, requestedByCitizenid, requestedByName.

This event is fired server-side by ds_mdt and received server-side by ds_mdt_doj. No client involvement. If you want to hook into warrant submissions from a third resource, add a handler for ds_mdt_doj:warrantRequestReceived in your own server script.

8 — Cross-Resource Data Flow

Understanding what each resource owns helps avoid confusion when reading the database.

TableOwned byds_mdt_doj access
mdt_casesds_mdtRead only — browse case files, join on case_number
mdt_reportsds_mdtRead only — display in case detail; judges share with defense
mdt_statementsds_mdtRead only — display in case detail; judges share with defense
mdt_case_evidenceds_mdtRead only — shown in warrant request detail view
mdt_warrantsds_mdtRead only — active warrant list; written via ApproveWarrantRequest export
mdt_warrant_requestsds_mdtRead only — warrant review queue; updated via Approve/DenyWarrantRequest exports
mdt_doj_*ds_mdt_dojFull read/write ownership
ds_mdt_doj never writes directly to any ds_mdt table. All writes to ds_mdt's data go through the exported functions (ApproveWarrantRequest, DenyWarrantRequest) which live in ds_mdt's own server code.

9 — FAQ & Troubleshooting

DOJ members can't open the terminal

Check that the player's PlayerData.job.name is listed in Config.JobRoles and their grade meets Config.MinGrade. Use exports['ds_mdt_doj']:GetDOJRole(Player) to debug.

Warrant requests aren't appearing in the DOJ terminal

Confirm Config.UseDOJWarrants = true in ds_mdt's config.lua and that ds_mdt is started before ds_mdt_doj. The ds_mdt_doj:warrantRequestReceived handler must be registered before requests come in.

Defense attorneys can see all police reports

Defense attorneys only see reports that a judge has explicitly shared on their assigned case via the Share Report button in the case view. If they are seeing everything, check the role classification in Config.JobRoles — the job may be mapped to 'judge' or 'prosecution' instead of 'defense'.

Motions aren't showing the correct types for each side

Each entry in Config.MotionTypes has a side field: 'both', 'defense', or 'prosecution'. The NUI filters the dropdown based on the logged-in member's role. Verify the side values in your config.

Court order notifications aren't firing

Check Config.NotifyOnCourtOrder = true and that ds_notify is running. The target attorney must be on-duty and online for the notification to fire. If they are offline, the order still saves but no in-game notification is sent.

mdt_doj_clients or mdt_doj_case_notes table missing

Run sql/alter.sql. These tables were added in v1.1 and are not in the original install for pre-v1.1 installs.
