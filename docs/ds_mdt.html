DS MDT

Full-featured Mobile Data Terminal for law enforcement — by DS Customs

v1.0.0 QBCore Lua 5.4 Escrow ds_notify

1 — Requirements

ResourceNotes
qb-coreRequired framework. Must start before ds_mdt.
oxmysqlRequired for all database operations.
ds_notifyRequired for all in-game toast notifications (BOLO alerts, warrant broadcasts, panic alerts, etc.).
qb-policejobProvides duty status, callsign, and rank via QBCore player metadata. Not a hard dependency but expected for full functionality.
ds_mdt_doj (optional)Required only when Config.UseDOJWarrants = true. Officers submit warrant requests; judges approve/deny from the DOJ MDT.
ds_prisoncreator (optional)Required only when Config.UsePrisonCreator = true. Adds an Inmates tab with sentence pause/resume controls.
gs-businessbanking or qb-management (optional)One of these is needed if you want citation fines deposited into a job account. See Config.CitationBanking.

2 — Escrow & Open Files

DS MDT is protected with FiveM Escrow. Only config.lua is excluded — everything else is encrypted.

Open — editable by you

  • config.lua

Encrypted — Escrow protected

  • client/main.lua
  • server/*.lua
  • bridge/banking.lua
  • html/*
All job roles, rank thresholds, citation types, dispatch codes, map locations, and integration toggles are configured entirely inside the open config.lua.

3 — Installation

Database Setup

Choose one SQL file from the sql/ folder.

Fresh install

Run sql/install.sql. Creates all ds_mdt tables. Safe to re-run (all statements use IF NOT EXISTS).

Existing ds_mdt install

Run sql/alter.sql. Adds columns and tables introduced in v1.1–v1.8 without touching existing data.

Items

Register both items in your QBCore shared items file:

-- MDT Tablet — given to officers; opens the MDT when used
['mdt_tablet'] = {
    name        = 'mdt_tablet',
    label       = 'MDT Tablet',
    weight      = 500,
    type        = 'item',
    image       = 'mdt_tablet.png',
    unique      = true,
    useable     = true,
    shouldClose = true,
    description = 'Law enforcement MDT tablet.',
},

-- Citation — given to citizens when an officer issues one; unique+useable
['mdt_citation'] = {
    name        = 'mdt_citation',
    label       = 'Citation',
    weight      = 10,
    type        = 'item',
    image       = 'mdt_citation.png',
    unique      = true,
    useable     = true,
    shouldClose = true,
    description = 'A traffic or civil citation.',
},
Both items must be unique = true and useable = true. Set Config.CitationItem = false to disable item-based citations entirely.

server.cfg Start Order

ensure qb-core
ensure oxmysql
ensure ds_notify
ensure qb-policejob
ensure ds_mdt
ensure ds_mdt_doj   # only if Config.UseDOJWarrants = true

4 — Configuration — config.lua

Access

Config.CitationItem'mdt_citation'Item given to citizens when an officer issues a citation. Must be unique and useable. Set to false to disable.

Config.AllowedJobTypes{ 'leo' }Array of QBCore job.type values whose members can open the MDT.

Citation fine banking

Config.CitationBankingBehaviour
'gs-businessbanking'Deposits fine into the issuing officer's job account via exports['gs-businessbanking']:Deposit(jobName, amount).
'qb-management'Deposits into the QBCore society boss_accounts table for the officer's job.
'qb-banking'Fine is removed from the citizen and deposited nowhere (government fine / evaporates).

6 — Developer API

Server Exports

Call these from any server-side script.

IsMDTAllowed(Player) boolean

Returns true if the given QBCore Player object has a job type in Config.AllowedJobTypes and meets Config.MinGrade.

local Player = exports['qb-core']:GetPlayer(source)
if exports['ds_mdt']:IsMDTAllowed(Player) then
    -- player is an authorised officer
end

NotifyAllOfficers(msg, ntype, duration)

Sends a ds_notify toast to every on-duty LEO on the server.

ParamTypeDescription
msgstringNotification text
ntypestring'info' · 'success' · 'error' · 'warning'
durationnumber|nilDuration in ms (optional)
 
exports['ds_mdt']:NotifyAllOfficers('All units respond to Pillbox.', 'error', 6000)

ApproveWarrantRequest(requestId, judgeInfo) boolean, number|string

Called by ds_mdt_doj when a judge approves a warrant request. Converts the request into a live mdt_warrants row, notifies the requesting officer and all on-duty LEOs, and returns true, warrantId on success.

ParamTypeDescription
requestIdnumberID of the mdt_warrant_requests row
judgeInfotable{ citizenid, name } of the approving judge
 
local ok, warrantId = exports['ds_mdt']:ApproveWarrantRequest(requestId, {
    citizenid = 'JUD-001',
    name      = 'Judge Smith',
})

DenyWarrantRequest(requestId, reason, judgeInfo) boolean

Called by ds_mdt_doj when a judge denies a warrant request. Marks the request denied, records the reason, and notifies the requesting officer.

local ok = exports['ds_mdt']:DenyWarrantRequest(requestId, 'Insufficient probable cause.', {
    citizenid = 'JUD-001',
    name      = 'Judge Smith',
})

GetPendingWarrantRequests() table[]

Returns all mdt_warrant_requests rows with status = 'pending'. Called by ds_mdt_doj to populate the warrant review queue.

local requests = exports['ds_mdt']:GetPendingWarrantRequests()
for _, r in ipairs(requests) do
    print(r.id, r.suspect_name, r.charges)
end

Net Events

ds_mdt:server:setUnitStatus (status)

Officers fire this from the MDT to update their live unit status. Valid values: '10-8', '10-7', '10-6', 'panic', 'off-duty'. Panic automatically triggers a ds_notify alert to all on-duty officers.

ds_mdt:server:clockIn / ds_mdt:server:clockOut

Toggle on/off duty from the MDT login screen via QBCore SetJobDuty. Also fires ds_mdt:client:dutyStateChanged back to the player.

ds_mdt:server:requestWarrant (data)

Submits a warrant request to the DOJ review queue when Config.UseDOJWarrants = true. Fires the ds_mdt_doj:warrantRequestReceived server event to notify all on-duty judges.

data fields: citizenid, suspectName, charges, details, caseNumber.

ds_mdt:server:prisonPauseSentence (citizenid, reason)

ds_mdt:server:prisonResumeSentence (citizenid)

Pause or resume a prisoner's sentence via exports['ds_prisoncreator']. Only registered when Config.UsePrisonCreator = true. Rank-gated by Config.Ranks.PauseSentence.

7 — DOJ Warrant Integration

When Config.UseDOJWarrants = true, the warrant workflow changes:

  1. Officer opens the MDT → Warrants tab → Request Warrant.
  2. Server inserts a row into mdt_warrant_requests and fires ds_mdt_doj:warrantRequestReceived.
  3. On-duty judges in ds_mdt_doj receive a ds_notify alert and see the request in their Warrant Requests tab.
  4. Judge approves → exports['ds_mdt']:ApproveWarrantRequest() is called → real warrant created → officer notified.
  5. Judge denies → exports['ds_mdt']:DenyWarrantRequest() is called → officer notified with reason.
Both ds_mdt and ds_mdt_doj must be running for this flow to work. When UseDOJWarrants = false, officers issue warrants directly and ds_mdt_doj is never involved.

8 — FAQ & Troubleshooting

Officers can't open the MDT

Check that their PlayerData.job.type matches an entry in Config.AllowedJobTypes and their grade meets Config.MinGrade. The IsMDTAllowed export can be used to test this from another resource.

Citations aren't giving the citizen an item

Confirm Config.CitationItem matches an item registered in QBCore.Shared.Items with unique = true and useable = true.

Citation fines aren't going to the job account

Set Config.CitationBanking to the correct backend. Ensure the backing resource (gs-businessbanking or qb-management) is started before ds_mdt in server.cfg.

Warrant requests aren't reaching the DOJ

Check Config.UseDOJWarrants = true and that ds_mdt_doj is started and running. ds_mdt fires the server-side event ds_mdt_doj:warrantRequestReceived — if ds_mdt_doj isn't loaded, the event handler is never registered.

Live Map doesn't show officer blips

Officers must be on-duty (job.onduty = true). Blips refresh every Config.BlipRefreshInterval ms. Verify qb-policejob is setting onduty correctly in player metadata.

mdt_case_evidence or mdt_warrant_requests table missing

Run sql/alter.sql. These tables were added in v1.1 and v1.8 respectively and are not in the original install for pre-v1.1 installs.
