DS MDT

Unified, multi-framework Mobile Data Terminal for law enforcement — by DS Customs

v1.0.0 Qbox QBCore ESX Lua 5.4 Escrow

1 — Overview

DS MDT is a high-performance, browser-based Mobile Data Terminal that sits inside your server's NUI layer. It auto-detects your framework (Qbox, QBCore, or ESX) and adapts its database schema accordingly. Every department on your server can have its own colour theme, icon, and badge label — all configured from a single open shared/config.lua.

The MDT is designed to work alongside DS CAD and DS Police (Qbx Police Enhanced) as a complete law-enforcement package, though it can also run independently.

This is a v1.0.0 beta release. Core systems are stable and production-ready. Additional features are actively being added.

DS MDT is protected with FiveM Escrow. The three shared scripts are excluded so you can freely configure the resource.

Open — editable by you

  • shared/config.lua
  • shared/framework.lua
  • shared/callbacks.lua

Encrypted — Escrow protected

  • client/*.lua
  • server/*.lua
  • web/*

4 — Installation

Database

DS MDT creates and auto-migrates its own tables on first start via MySQL.ready. No SQL file needs to be imported manually. The following tables are created:

TablePurpose
mdt_incidentIncident reports — title, description, charges, evidence, status, officer, fines, warrant flag.
mdt_warrantsActive, completed, and cancelled warrants with suspect citizenid, title, charges, and fines.
mdt_bolosVehicle BOLOs keyed by plate with title, description, and optional image.
mdt_chargesCriminal code / offence registry seeded from Config.MDTCharges.
mdt_jailInternal jail sentence records — citizenid, time remaining, origin coords.

The startup script also adds any missing columns to your existing framework players / users table:

Column added to players tablePurpose
warranted TINYINT(1)Warrant flag — 1 when the player has an active warrant.
p_image TEXTOfficer profile photo URL.
callsign VARCHAR(50)Officer radio callsign (e.g. 1A-01).
All ALTER TABLE statements use a SHOW COLUMNS guard — running the resource on an existing installation is safe and will never overwrite existing data.

server.cfg Start Order

ensure oxmysql
ensure qbx_core        # or qb-core / es_extended
ensure ds_mdt
ensure ds_cad          # optional — pulls active calls via export
ensure qbx_police      # optional — full police job integration

5 — Configuration — shared/config.lua

Departments

Each key in Config.Departments must match a job name in your framework. The MDT uses the matching entry's theme, icon, color, and label to skin the interface for that department.

Config.Departments = {
    ['police']   = { label = 'LSPD',        theme = 'theme-police',  icon = 'fa-shield-halved', color = '#63A6C0' },
    ['sheriff']  = { label = 'BCSO',        theme = 'theme-sheriff', icon = 'fa-star',          color = '#ff9800' },
    ['fib']      = { label = 'FIB',         theme = 'theme-fib',     icon = 'fa-user-secret',  color = '#ff3e3e' },
    ['ambulance']= { label = 'EMS',         theme = 'theme-ems',     icon = 'fa-heart-pulse',  color = '#e91e63' },
}

Dispatch access control

Config.DispatchAccess controls who can assign units to alerts — reading the Dispatch tab is always open to all department members.

KeyDescription
enabledSet false to allow all department members to assign. Default true.
defaultAllowFallback if the player's job is not in byJob. Default false.
byJob[jobName].minGradeMinimum job grade required to assign units for that department.
identifiersWhitelist of raw player identifiers (any format) always allowed regardless of grade.
citizenidsWhitelist of citizenids always allowed.

Panic / quick-dispatch alerts

Config.PanicAlerts defines the buttons shown on the MDT panic bar. Each entry has code, title, color, and icon (FontAwesome class).

Charge sync

KeyDefaultDescription
Config.ChargeSync.syncEnabledtrueSync Config.MDTCharges into mdt_charges on every resource start.
Config.ChargeSync.removeMissingFromDatabasetrueDelete DB charges that are no longer in the config list.

Debug / mock data

Set Config.Debug = true to inject the Config.MockOfficers list into the live officer feed. Useful for testing the UI without real players on-duty. Always set back to false before going live.

8 — Developer API

Server Exports

CreateDispatchCall(callData) number

Creates a new dispatch alert and broadcasts it to all online department players. Returns the assigned call id.

FieldTypeRequiredDescription
codestringNo10-code or badge label. Defaults to "10-00".
titlestringNoShort alert title. Defaults to "Unknown Call".
locationstringNoStreet / location name. Auto-resolved by client if omitted.
coordsvector3 / tableNoWorld coords. Accepts vector3, {x,y,z}, or {[1],[2],[3]}.
infostringNoAdditional details shown in the alert card.
 
-- From any server-side script
exports['ds_mdt']:CreateDispatchCall({
    code     = '10-31',
    title    = 'Grand Theft Auto',
    location = 'Great Ocean Hwy',
    coords   = vector3(-2345.1, 321.4, 12.5),
    info     = 'Suspect seen fleeing in a black Buffalo'
})

GetActiveDispatchCalls() table[]

Returns the current list of active calls. Each entry contains id, code, title, location, coords, info, time, and units.

local calls = exports['ds_mdt']:GetActiveDispatchCalls()
for _, call in ipairs(calls) do
    print(call.id, call.code, call.title)
end

GetDispatchCallDetails(callId) table|nil

Finds and returns a single call by its numeric id, or nil if not found.

local details = exports['ds_mdt']:GetDispatchCallDetails(123)

HasActiveBolo(plate) boolean

Returns true if a BOLO exists in mdt_bolos for the given plate.

local flagged = exports['ds_mdt']:HasActiveBolo("ABC 123")

GetVehicleBolo(plate) table|nil

Returns the full BOLO record (id, plate, title, description, image, created_at) or nil.

local bolo = exports['ds_mdt']:GetVehicleBolo("ABC 123")

Client Exports

ToggleMDT(state)

Force-open or force-close the MDT NUI. Pass true to open, false to close.

exports['ds_mdt']:ToggleMDT(true)   -- open
exports['ds_mdt']:ToggleMDT(false)  -- close

IsMdtOpen() boolean

Returns true if the MDT NUI is currently visible on the player's screen.

local open = exports['ds_mdt']:IsMdtOpen()

CreateDispatchCall(callData) (client)

Client-side version. If location is omitted, the script automatically resolves the street name from coords before forwarding to the server.

exports['ds_mdt']:CreateDispatchCall({
    code   = '10-31',
    title  = 'Grand Theft Auto',
    coords = vector3(-2345.1, 321.4, 12.5),
    info   = 'Suspect seen fleeing in a black Buffalo'
})

9 — Dispatch Compatibility

DS MDT listens for net events from several popular dispatch resources out of the box. If your server already uses one of these, calls will automatically appear in the MDT without any code changes.

ResourceEvent intercepted
ps-dispatchps-dispatch:server:notify
qs-dispatchqs-dispatch:server:CreateDispatchCall
cd_dispatchcd_dispatch:AddNotification · cd_dispatch:NewDispatchCallCreated
codem-dispatchcodem-dispatch:server:NewCall
Genericdispatch:server:notify
You can also call exports['ds_mdt']:CreateDispatchCall({}) directly from any server-side script — see the Developer API section above.

10 — Integration with DS CAD

DS CAD reads active dispatch calls directly from DS MDT using the GetActiveDispatchCalls export. When the CAD is open in a vehicle, the call list on-screen stays in sync with whatever is in the MDT. No extra configuration is needed — just ensure both resources are running and started in order.

ensure ds_mdt
ensure ds_cad   # must start after ds_mdt

11 — FAQ & Troubleshooting

The MDT opens but shows no officer data

Officers must be in a job listed in Config.Departments. Check that the job name key matches exactly (case-sensitive) with what the framework returns via player.job.name.

Dispatch calls aren't appearing

Confirm Config.UseExternalDispatch is set correctly. If using standalone mode (false), trigger calls via the CreateDispatchCall export or the /911 command. If using ds_departments, ensure it is started before ds_mdt.

Charges aren't showing in the Criminal Code tab

Check Config.ChargeSync.syncEnabled. If true, charges are synced from Config.MDTCharges on every resource start. If false, the mdt_charges table is seeded with defaults on first run only — add entries directly via SQL after that.

Jailed players aren't being teleported on login

Ensure Config.UseInternalJailSystem = true and Config.JailMode = "default". The teleport waits 5 seconds after QBCore:Server:PlayerLoaded / esx:playerLoaded fires to allow the player to fully spawn in.

Tables already existed on my server and the migration is failing

The addColumnIfMissing function checks SHOW COLUMNS before any ALTER TABLE. If you're seeing errors, check your database user has ALTER permission, or add the missing columns manually using the definitions in server/main.lua Section 1.
