DS Electronics Store

Full-featured player-run electronics job — collect parts, process components, assemble finished products, stock a live retail store, and deposit revenue into a business bank account.

QBCore FiveM Lua 5.4 qs-inventory / ox_inventory / qb-inventory oxmysql Escrow

1 — Overview

DS Electronics Store is a modular, player-run job built around a three-stage assembly pipeline. Employees collect raw parts in the world, process them into components at a workshop, assemble finished electronics, and then sell them through a fully player-managed retail store.

Feature summary

  • Three-stage assembly pipeline — Parts Pickup → Processing → Assembly — with looping progress bars and per-stage world zones
  • Multiple independent assembly lines supported — add a new .lua file to assembly/ to define an entirely new product line
  • Employee-stocked retail phone store with live MySQL inventory and boss-adjustable prices
  • Customer shop UI — browse by category, pay with cash or bank
  • Cart checkout — customers can queue multiple items and pay in one transaction
  • Employee stock management — deposit, withdraw, and set prices from a dedicated NUI
  • Work vehicle system — spawn and return a job van from the garage zone
  • Clock In / Out zone with server-side duty state management
  • Business banking integration — all store revenue is deposited to the job's bank account
  • Fully modular bridge system — swap notification, progress bar, prompt, and banking resources via config.lua with zero code changes
  • Auto-detects qs-inventory, ox_inventory, and QBCore native inventory at startup
  • Map blips shown on-duty for every zone across all assembly lines

3 — Installation

  1. Place the ds_electronicsstore folder inside your resources directory.
  2. Add all item entries from items.lua to your QBCore shared items file (see §8).
  3. Add the ls_electronics job entry to qb-core/shared/jobs.lua (see §7).
  4. Add item images to your inventory's image folder (see §8).
  5. Configure config.lua — set your bridge options and zone coordinates (see §5).
  6. Add ensure ds_electronicsstore to server.cfg after all dependencies.
  7. The phone store database table is created automatically on first start — no manual SQL import required.
# server.cfg — ensure dependencies before the resource
ensure oxmysql
ensure ds_notify          # if Config.Notification = 'ds_notify'
ensure ds_progressbar     # if Config.ProgressBar  = 'ds_progressbar'
ensure ds_prompt          # if Config.Prompt       = 'ds_prompt'
ensure ds_vehiclekeys     # if Config.VehicleKeys  = 'ds_vehiclekeys'
ensure gs-businessbanking # if Config.Banking      = 'gs-businessbanking'

ensure ds_electronicsstore

4 — Bridge System

Every external dependency is isolated behind a bridge — a small Lua file in bridge/ that reads a single config key and wires up a global function. Changing a config value is all that is needed to swap resources; no other files need editing.

Config KeyOptionsBridge file
Config.Notification 'ds_notify' · 'qb' · 'custom' bridge/notifications/notify.lua
Config.ProgressBar 'ds_progressbar' · 'qb' · 'custom' bridge/progressbar/progressbar.lua
Config.Prompt 'ds_prompt' · 'builtin' · 'custom' bridge/prompt/prompt.lua
Config.Banking 'gs-businessbanking' · 'qb-banking' · 'custom' bridge/banking/banking.lua
Config.VehicleKeys 'ds_vehiclekeys' · 'qb-vehiclekeys' · 'none' config.lua (inline check)

Custom bridges

Each bridge type ships with a *_custom.lua counterpart (e.g. bridge/banking/banking_custom.lua). Set the config key to 'custom' and implement the required function(s) in that file. All *_custom.lua files are excluded from escrow and are fully editable.

The 'builtin' prompt option requires no extra resource — it renders a [E] label hint using native FiveM DrawText calls. Use it if you do not have ds_prompt installed.

Banking — qb-banking auto-account creation

When Config.Banking = 'qb-banking' the bridge automatically calls CreateJobAccount on first deposit if the account does not already exist in qb-banking's in-memory table. This means you do not need to manually create the business account before the store goes live.

-- Store catalogue — item_name must match your QBCore items DB
Config.PhoneStoreItems = {

The price and quantity values are inserted into the database on first run using INSERT IGNORE — changing them in config after first run will have no effect. Use the in-game Employee Stock menu to adjust prices, or update the DB directly.

6 — Assembly Lines

Each assembly line is defined as a separate Lua file inside the assembly/ folder. The resource loads all files matching assembly/*.lua automatically — add a new file for each new product line.

AssemblyLine schema

AssemblyLine({
    id    = 'phones',          -- unique internal key
    label = 'Phone Assembly',   -- shown in blip names and prompts

    -- Items
    rawItem       = 'phone_parts',     -- collected at Parts Pickup
    rawMaxStack   = 50,               -- max raw items before pickup stops
    processedItem = 'processed_parts', -- produced at Processing (1 raw → 1 processed)
    finishedItem  = 'phone',           -- produced at Assembly  (1 processed → 1 finished)

    -- Progress bars (label shown during bar, duration in ms)
    pickupBar   = { label = 'Collecting parts…', duration = 1800 },
    processBar  = { label = 'Processing parts…', duration = 1800 },
    assembleBar = { label = 'Assembling phone…', duration = 1800 },

    -- Zone lists — add as many positions as you like per stage
    partsPickup   = { { Pos = vector3(...), Size = {x=6.5, y=6.5, z=6.5}, Color = {r=0,g=200,b=255}, Type = 22 } },
    processing    = { { Pos = vector3(...), Size = {x=15.5,y=15.5,z=1.0}, Color = {r=136,g=243,b=216}, Type = 22 } },
    phoneAssembly = { { Pos = vector3(...), Size = {x=15.5,y=15.5,z=1.0}, Color = {r=136,g=243,b=216}, Type = 22 } },

    -- Map blip (one blip per zone location while on duty)
    blip = { sprite = 162, colour = 25 },
})

Pipeline stages

StageZone keyActionInput → Output
Parts PickuppartsPickupLooping harvest — one item per bar completionNothing → rawItem
ProcessingprocessingSingle progress bar per run — loops automaticallyrawItem → processedItem
AssemblyphoneAssemblySingle progress bar per run — loops automaticallyprocessedItem → finishedItem
All three stages guard against inventory manipulation server-side. Processing and Assembly refund the input item if the output add fails (e.g. inventory full), ensuring no items are lost.

7 — Job Grades

Add the following entry to qb-core/shared/jobs.lua. Adjust grades, labels, and pay to match your server's economy.

['ls_electronics'] = {
    label = 'LS Electronics',
    defaultDuty = false,
    offDutyPay  = false,
    grades = {
        ['0'] = { name = 'Trainee',        payment = 50  },
        ['1'] = { name = 'Technician',     payment = 100 },
        ['2'] = { name = 'Senior Tech',    payment = 150 },
        ['3'] = { name = 'Manager',        payment = 250, isboss = true },
    },
}

The isboss = true flag on a grade unlocks price-setting in the Employee Stock menu. Any grade can deposit and withdraw stock; only boss grades can change item prices.

9 — Gameplay Loop

Clock In / Out

Walk to the ClockIn zone and press E. The server calls QBCore:ToggleDuty. Blips, markers, and interaction zones for all assembly stages only appear while on duty.

Parts Pickup

Walk to a partsPickup zone and press E. A looping progress bar starts — each completed bar awards one rawItem directly to your inventory. The loop runs until you leave the zone, go off duty, or hit rawMaxStack. The server validates every tick server-side.

Processing

Walk to a processing zone and press E. The server checks for at least one rawItem, runs the progress bar, then removes one input and adds one processedItem. The loop continues automatically until you run out of raw material or leave the zone.

Assembly

Walk to a phoneAssembly zone and press E. Same loop as Processing — one processedItem is consumed and one finishedItem is produced per bar. If the output add fails (inventory full), the input item is automatically refunded.

Sales Zone

Walk to the Sales zone and press E. The server searches your inventory for any item in Config.SellableItems, removes the entire stack, and pays a random amount between min and max per item as cash. The loop repeats automatically every ~1.1 seconds until you leave the zone.

Phone Store — Customers

Any player can walk to the CustomerShop zone to open the store UI. Browse items by category, adjust quantities, and choose to pay with cash or bank. Customers can either buy individual items immediately or build a cart and checkout in one transaction. All purchases are validated server-side using DB prices — client-sent prices are never trusted.

Phone Store — Employees

Employees with the ls_electronics job can access the Employee Stock zone. The stock menu shows every catalogue item, the current store quantity, and your inventory count. Use Deposit to add items from your inventory, Withdraw to retrieve stock. Boss-grade employees additionally see a Set Price option per item.

Work Vehicle

Walk to the VehicleSpawner zone and press E to spawn a work van. Drive it to the VehicleDeleter zone and press E to return it. Only one work vehicle per player is tracked — spawning a second one automatically removes the first.

12 — Notes & FAQ

  • The phone store database table (ds_phonestore by default) is created automatically on first resource start using CREATE TABLE IF NOT EXISTS. Default prices and quantities from Config.PhoneStoreItems are seeded using INSERT IGNORE — existing rows are never overwritten.
  • Changing price or quantity in Config.PhoneStoreItems after the table has been created has no effect. Adjust values directly in the database or via the in-game boss menu.
  • All three assembly stages stop cleanly when a player leaves the zone or goes off duty — the progress bar is cancelled and any server-side loop state is cleared.
  • The Parts Pickup loop is timed entirely client-side (using Wait()) to avoid bar-callback race conditions. The server only grants one item per harvestTick event it receives.
  • If Config.Prompt = 'builtin' the ds_prompt dependency can be removed from fxmanifest.lua's dependencies block entirely.
  • Adding a new assembly line requires no code changes — create a new .lua file in assembly/, call AssemblyLine({...}), and restart the resource.
  • The Config.MaxInService key is declared in config but the enforcement logic should be wired in server/main.lua if strict on-duty limiting is required. Set to -1 to disable.
