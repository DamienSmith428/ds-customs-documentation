DS Vehicle Keys

Database-backed vehicle lock & key ownership system — keyfob NUI, hotwiring, carjacking, job-shared keys, and a full developer export API — by DS Customs / GunSmoke

v1.0.0 QBCore FiveM Lua 5.4 Escrow

1 — Overview

DS Vehicle Keys replaces qb-vehiclekeys with a database-backed ownership system. Every key assignment (owner or temporary) is persisted to a dedicated ds_vehiclekeys table and loaded back into an in-memory cache on server start — so keys survive restarts and resource reloads without any data loss.

  • Keyfob NUI — press L outside a vehicle to open a radial keyfob panel with lock, unlock, trunk, and engine buttons.
  • Engine toggle — press G while seated to start/stop the engine remotely.
  • Hotwire — press H in the driver's seat of a vehicle you don't own to begin a timed hotwire progress bar.
  • Carjacking — aim at an NPC driver with a qualifying weapon to attempt a carjack.
  • Lockpicking — compatible with the standard lockpicks:UseLockpick event used by QBCore inventory items.
  • Job-shared keys — define vehicles that all employees of a job can lock/unlock without individual key grants.
  • qb-vehiclekeys backwards compatibility — the old vehiclekeys:client:SetOwner and vehiclekeys:server:GiveOwnership events are shimmed, so any resource that still fires them works without code changes.
config.lua, all locales/*.lua, and the notify bridge example are not encrypted. Everything else is escrow-protected.

3 — Installation

  1. Place the ds_vehiclekeys folder inside your resources directory.
  2. Run sql/ds_vehiclekeys.sql against your database to create the ds_vehiclekeys table.
  3. Add ensure ds_vehiclekeys to server.cfg after qb-core and oxmysql, and before any resource that uses its exports (e.g. ds_garages).
  4. Set Config.Notify in config.lua to match your notification resource.
  5. If you are replacing qb-vehiclekeys, remove or comment out ensure qb-vehiclekeys — the old event names are shimmed so other resources continue to work.
# server.cfg — example load order
ensure oxmysql
ensure qb-core
ensure qb-minigames
ensure ds_notify        # optional but recommended
ensure ds_vehiclekeys   # replaces qb-vehiclekeys
ensure ds_garages       # any resource that depends on ds_vehiclekeys

SQL

-- sql/ds_vehiclekeys.sql
CREATE TABLE IF NOT EXISTS `ds_vehiclekeys` (
  `id`           INT          NOT NULL AUTO_INCREMENT,
  `plate`        VARCHAR(12)  NOT NULL,
  `owner`        VARCHAR(50)  NOT NULL COMMENT 'citizenid of the vehicle owner',
  `temp_holders` LONGTEXT     NULL     COMMENT 'JSON array of citizenids with temp access',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uq_plate` (`plate`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
The table is small and fast — one row per unique plate. All runtime lookups are served from the in-memory VehicleList cache; the database is only written when ownership changes.

Job-Shared Keys

Employees of a configured job can lock/unlock any listed vehicle model without having individual keys. Ownership is not recorded in the database — access is purely job-based.

Config.SharedKeys = {
    ['police'] = {
        requireOnduty = false,   -- true = only on-duty officers can access
        vehicles = {
            'police', 'police2', 'police3', 'sheriff', 'sheriff2',
        }
    },
    ['mechanic'] = {
        requireOnduty = false,
        vehicles = { 'towtruck', 'towtruck2' }
    },
}

Immune & No-Lock Vehicles

-- These vehicles cannot be carjacked.
Config.ImmuneVehicles = { 'stockade' }

5 — Key Types

Every key record carries one of two types, stored in both the database and the server-side VehicleList cache.

TypeStored in DB?Description
'owner'Yes — owner columnThe vehicle's registered owner. Assigned when a vehicle is purchased/spawned. When the owner removes their keys the DB row is wiped.
'temp'Yes — temp_holders JSON arrayA temporary key holder — e.g. a passenger the owner handed keys to. Cleared per-plate when the owner deletes their key record.
An 'owner' key is never silently downgraded to 'temp'. If a GiveKeys call is made on a plate where the target player is already the owner, their status stays as 'owner'.

7 — Server Exports

All exports below are callable from any server-side script using exports['ds_vehiclekeys']:ExportName(...).

GiveKeys(serverId, plate, isOwner)

Give a player keys for a vehicle. Updates the in-memory cache and persists to the database. Also sends the key to the player's client cache and shows a notification.

ParameterTypeDescription
serverIdnumberThe player's server source ID.
platestringVehicle plate. If nil, falls back to the vehicle the player is currently in.
isOwnerboolean|niltrue = marks as owner and upserts the DB row. false/nil = marks as temp, persisted in temp_holders.
 
-- Give temp keys
exports['ds_vehiclekeys']:GiveKeys(source, 'ABC1234')

-- Give owner keys (e.g. after a vehicle purchase)
exports['ds_vehiclekeys']:GiveKeys(source, 'ABC1234', true)

RemoveKeys(serverId, plate)

Remove a player's keys (owner or temp) for a plate. If the player was the owner, the owner column in the DB is cleared. Also fires ds_vehiclekeys:client:RemoveKeys to strip the key from the player's local cache.

exports['ds_vehiclekeys']:RemoveKeys(source, 'ABC1234')

HasKeys(serverId, plate) → boolean

Returns true if the player currently holds keys (any type) for the plate. Purely in-memory — no DB query.

if exports['ds_vehiclekeys']:HasKeys(source, 'ABC1234') then
    -- player has keys
end

GetKeyType(serverId, plate) → 'owner'|'temp'|nil

Returns the type of key the player holds for the plate, or nil if they have none.

local ktype = exports['ds_vehiclekeys']:GetKeyType(source, 'ABC1234')
-- ktype == 'owner'  |  'temp'  |  nil

GetAllKeysForPlayer(serverId) → table

Returns a flat table of every plate the player holds, mapped to their key type. Useful for phone app UIs or admin panels.

local keys = exports['ds_vehiclekeys']:GetAllKeysForPlayer(source)
-- { ['ABC1234'] = 'owner', ['XYZ9999'] = 'temp', ... }
for plate, ktype in pairs(keys) do
    print(plate, ktype)
end

GetPlateOwner(plate) → citizenid|nil

Returns the owner citizenid for a plate directly (synchronous, in-memory). Returns nil if the plate has no registered owner. Useful for ownership checks in police, impound, or admin scripts.

local cid = exports['ds_vehiclekeys']:GetPlateOwner('ABC1234')
if cid then
    print('Owner:', cid)
end

SetOwner(plate, citizenid)

Directly assign ownership by citizenid without needing an active server session. Useful for dealership or purchase scripts that run entirely server-side after the player has already logged off, or before the player is available via GetPlayer(). If the player is currently online their client cache is updated automatically.

-- Called from a vehicle shop after purchase confirmation
exports['ds_vehiclekeys']:SetOwner('ABC1234', Player.PlayerData.citizenid)

BuyVehicleKeys(serverId, plate)

Purpose-built export for vehicle shop resources. In a single call it: trims and upper-cases the plate, upserts the owner row to DB, updates the in-memory cache, pushes AddKeys to the buyer's client, and sends a success notification via the configured Notify bridge.

-- In your vehicle shop server callback after charging the player:
exports['ds_vehiclekeys']:BuyVehicleKeys(source, vehiclePlate)

TransferOwnership(plate, newServerId)

Atomically transfers full ownership from the current owner to a new player. Handles everything in one call:

  1. Strips the old owner from VehicleList and fires RemoveKeys to their client if online.
  2. Sets the new owner in VehicleList.
  3. Upserts the ds_vehiclekeys table (owner column, clears temp_holders).
  4. Updates player_vehicles (citizenid + license columns).
  5. Pushes AddKeys to the new owner's client.
  6. Notifies both parties via the configured Notify bridge.
-- Used internally by ds_garages vehicle transfer system
exports['ds_vehiclekeys']:TransferOwnership(plate, newOwnerServerId)

RemoveAllKeysForPlate(plate)

Wipes all key holders (owner and temp) for a plate from both the in-memory cache and the database. Use this when a vehicle is permanently deleted or sold off the server (e.g. an admin deletion tool).

-- When permanently deleting a vehicle from your admin menu:
exports['ds_vehiclekeys']:RemoveAllKeysForPlate('ABC1234')

8 — Client Exports

All exports below are callable from any client-side script using exports['ds_vehiclekeys']:ExportName(...). They operate on the local KeysList cache — no server round-trip required.

HasKeys(plate) → boolean

Returns true if the local player currently holds keys (any type) for the plate. Reads directly from the in-memory KeysList cache.

if exports['ds_vehiclekeys']:HasKeys('ABC1234') then
    -- local player has keys
end

GetKeyType(plate) → 'owner'|'temp'|nil

Returns the key type the local player holds for the plate, or nil if they have none. Reads from the local cache.

local ktype = exports['ds_vehiclekeys']:GetKeyType('ABC1234')

IsBlacklistedVehicle(vehicle) → boolean

Returns true if the entity is on the no-lock list, is a bicycle (class 13), or has the ignoreLocks entity state flag set. Use this before attempting any lock/unlock logic in external resources.

local veh = GetVehiclePedIsIn(PlayerPedId(), false)
if not exports['ds_vehiclekeys']:IsBlacklistedVehicle(veh) then
    -- safe to interact with locks
end

ToggleVehicleLocks(vehicle, lock)

Trigger a lock or unlock from an external resource (e.g. a target action or phone app). Performs the full ownership check, keyfob animation, light flash, and server sync.

ParameterTypeDescription
vehiclenumberEntity handle of the vehicle.
lockboolean|niltrue = lock · false = unlock · nil = toggle current state
 
-- Force-lock the vehicle the player is nearest to
local veh = QBCore.Functions.GetClosestVehicle()
exports['ds_vehiclekeys']:ToggleVehicleLocks(veh, true)

-- Toggle (no argument)
exports['ds_vehiclekeys']:ToggleVehicleLocks(veh)

AddNoLockVehicle(model) / RemoveNoLockVehicle(model)

Dynamically add or remove a vehicle model name from the no-lock list at runtime. Changes are local to the calling client and do not persist across sessions.

-- Prevent BMX bikes from ever being locked
exports['ds_vehiclekeys']:AddNoLockVehicle('bmx')

-- Re-enable locking for a model previously added
exports['ds_vehiclekeys']:RemoveNoLockVehicle('bmx')

OpenKeyfob()

Programmatically open the keyfob NUI from another resource (e.g. a phone app or custom menu).

exports['ds_vehiclekeys']:OpenKeyfob()

9 — QBCore Callbacks

These are triggered from client-side scripts using QBCore.Functions.TriggerCallback.

ds_vehiclekeys:server:GetVehicleKeys

Returns { [plate] = 'owner'|'temp', ... } for every plate the calling player holds. This is the same data that is pushed to the client on login — you would only call this manually if you need a guaranteed-fresh snapshot.

QBCore.Functions.TriggerCallback('ds_vehiclekeys:server:GetVehicleKeys', function(keys)
    for plate, ktype in pairs(keys) do
        print(plate, ktype)
    end
end)

ds_vehiclekeys:server:checkPlayerOwned

Returns true if the plate has any registered holder in VehicleList (i.e. is a player-owned vehicle, not just an NPC car). Used internally to decide whether to lock parked vehicles.

QBCore.Functions.TriggerCallback('ds_vehiclekeys:server:checkPlayerOwned', function(owned)
    if not owned then
        -- NPC / unregistered vehicle
    end
end, plate)

ds_vehiclekeys:server:GetPlateOwner

Returns the owner citizenid for a plate via callback, or nil if none.

QBCore.Functions.TriggerCallback('ds_vehiclekeys:server:GetPlateOwner', function(citizenid)
    print('Owner citizenid:', citizenid)
end, plate)

11 — Notify Bridge

All player-facing notifications are routed through a Notify global table set up in bridge/notify.lua. The active implementation is selected by Config.Notify.

ValueWhat it uses
'qb'QBCore built-in QBCore.Functions.Notify / TriggerClientEvent('QBCore:Notify', ...).
'ds_notify'exports['ds_notify']:Notify (client) / exports['ds_notify']:NotifyClient (server).
'custom'Your implementation in bridge/notify_custom.lua. See template below.

Using a custom notify resource

  1. Set Config.Notify = 'custom' in config.lua.
  2. Copy bridge/notify_example.lua to bridge/notify_custom.lua.
  3. Implement Notify.Client(message, ntype, duration) and/or Notify.Server(src, message, ntype, duration).
-- bridge/notify_custom.lua
if Config.Notify ~= 'custom' then return end

-- CLIENT side
if not IsDuplicityVersion() then
    function Notify.Client(message, ntype, duration)
        -- ox_lib example:
        lib.notify({ title = 'Vehicle Keys', description = message, type = ntype })
    end
end

-- SERVER side
if IsDuplicityVersion() then
    function Notify.Server(src, message, ntype, duration)
        TriggerClientEvent('ox_lib:notify', src, { title = 'Vehicle Keys', description = message, type = ntype })
    end
end
bridge/notify_example.lua and bridge/notify_custom.lua are not encrypted — you can always read the example as a reference.

13 — Integration Guide

Vehicle shops / dealerships

When a player successfully buys a vehicle, call BuyVehicleKeys from your server callback. This is the recommended single-call path — it handles DB write, cache update, client push, and notification.

-- Server callback after successful purchase
exports['ds_vehiclekeys']:BuyVehicleKeys(source, vehiclePlate)

Admin / impound systems

Use HasKeys for ownership checks and setVehicleState (ds_garages) for moving the vehicle. Use RemoveKeys or RemoveAllKeysForPlate to revoke access.

Police / detective resources

Use GetPlateOwner(plate) to look up the citizenid of any registered vehicle's owner. This is synchronous and in-memory — no DB round-trip.

local ownerCid = exports['ds_vehiclekeys']:GetPlateOwner('ABC1234')
if ownerCid then
    local Player = exports['qb-core']:GetPlayerByCitizenId(ownerCid)
    -- Player is the vehicle owner
end

External lock/unlock triggers

Use the ToggleVehicleLocks client export from a target action, NPC interaction, or phone app. Ownership and blacklist checks are applied internally.

-- From a ds_target or qb-target action callback:
exports['ds_vehiclekeys']:ToggleVehicleLocks(entity)

Marking a vehicle as exempt from locking

Set the ignoreLocks entity state flag on the vehicle entity, or add its model to Config.NoLockVehicles. The IsBlacklistedVehicle client export respects both.

-- Mark a spawned entity as exempt at runtime
Entity(vehicle).state.ignoreLocks = true

-- Or add the model permanently in config.lua
Config.NoLockVehicles = { 'bicycle', 'bmx', 'fixter' }

14 — Frequently Asked Questions

Keys are gone after a server restart

Make sure you ran sql/ds_vehiclekeys.sql to create the ds_vehiclekeys table. Owner keys are persisted to the DB on every GiveKeys(isOwner=true) / BuyVehicleKeys / SetOwner call and re-loaded on startup. Temp keys are also persisted in the temp_holders JSON column.

Players can enter locked NPC vehicles

Check that Config.LockNPCDrivingCars and Config.LockNPCParkedCars are both true. Note that locking NPC vehicles is client-enforced — a high-latency player may still enter before the lock state is applied.

Carjacking never succeeds / always succeeds

Tune Config.CarjackChance. The key used in the table is the GTA weapon group hash as a string. Values are probability floats from 0.0 (never) to 1.0 (always). Weapons not listed in the table default to 0.5.

The /givekeys command hands keys to the wrong player

The command without an ID gives to the closest player within 1.5 m. If no one is within range the "nobody nearby" notification shows. Use /givekeys [id] to specify a target by server ID.

Notifications are not showing up

Verify Config.Notify matches the resource actually running on your server. If using 'ds_notify', confirm that resource is started and not erroring.

Can I use ds_vehiclekeys with a non-QBCore framework?

Not directly — the resource uses qb-core exports for player data and callbacks throughout. A complete bridge rewrite would be required for other frameworks.

How do I disable carjacking entirely?

Set Config.CarjackEnable = false in config.lua. The carjack loop will not start and the CarjackVehicle function will return immediately.

How do I give all officers of a job access to police vehicles without individual key grants?

Add the job and vehicle model list to Config.SharedKeys. Set requireOnduty = true if you only want on-duty officers to have access. No DB records are created — it is purely config-driven.
