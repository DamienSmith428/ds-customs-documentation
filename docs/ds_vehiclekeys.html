DS Vehicle Keys

Database-backed vehicle lock & key ownership system. Keyfob NUI, hotwiring, carjacking, lockpicking, job-shared keys, ds_garages valet delivery, and a full server & client export API — by DS Customs

v1.0.0 QBCore FiveM Lua 5.4 qs-inventory ox_inventory qb-inventory Escrow

1 — Overview

DS Vehicle Keys is a complete drop-in replacement for qb-vehiclekeys. Every key relationship is stored in a dedicated ds_vehiclekeys database table — ownership persists across restarts and is never lost when the resource stops. An optional keyfob NUI provides lock, unlock, trunk, and engine controls from outside the vehicle.

The resource ships with four bridge files so you can swap the notification library, the progress bar, and the inventory without touching any encrypted code. Everything that touches game-feel is exposed through a clean export API callable from any other resource.

The following files are never encrypted: config.lua, all locales/*.lua, bridge/notify_example.lua, bridge/notify_custom.lua, bridge/progressbar_example.lua, and bridge/progressbar_custom.lua. Core logic is escrow-protected.

3 — Installation

  1. Place the ds_vehiclekeys folder inside your resources directory.
  2. Import sql/ds_vehiclekeys.sql into your database — this creates the ds_vehiclekeys table.
  3. Add ensure ds_vehiclekeys to server.cfg after qb-core and oxmysql.
  4. Open config.lua and configure the bridges and gameplay settings to match your server.
  5. If you were previously running qb-vehiclekeys, remove it — ds_vehiclekeys listens to the same backwards-compatibility events and will conflict if both run simultaneously.
# server.cfg — recommended load order
ensure oxmysql
ensure qb-core
ensure ds_notify         # optional — set Config.Notify = 'ds_notify'
ensure ds_progressbar    # optional — set Config.Progressbar = 'ds_progressbar'
ensure ds_vehiclekeys

SQL Table

Run sql/ds_vehiclekeys.sql once on a fresh install. The table created is:

ColumnTypeDescription
plateVARCHAR(15) PKThe vehicle plate. Primary key.
ownerVARCHAR(50)citizenid of the current legal owner.
temp_holdersJSONJSON array of citizenids holding temporary (non-owner) keys.
Key state is cached in memory on resource start and kept in sync on every GiveKeys / RemoveKeys call. Players already online when the resource restarts receive a full key sync push within ~500 ms.

4 — Configuration — config.lua

config.lua is open and unencrypted. Every option is documented inline. The most important settings are described below.

Config.Notify

Controls which notification resource is used for all player-facing messages.

ValueBehaviour
'qb'Uses QBCore.Functions.Notify and the QBCore:Notify client event.
'ds_notify'Uses exports['ds_notify']:Notify / NotifyClient. Falls back to qb if the resource is not running.
'custom'Reads bridge/notify_custom.lua. Implement Notify.Client() and Notify.Server() for any notification resource. See bridge/notify_example.lua.

Config.Progressbar

Controls which progress bar resource is used for hotwire, carjack, and key-loot bars.

ValueBehaviour
'qb'Uses QBCore.Functions.Progressbar (default).
'ds_progressbar'Uses exports['ds_progressbar']:Start/Stop. Animations are driven internally since ds_progressbar is display-only. Falls back to qb if the resource is not running.
'custom'Reads bridge/progressbar_custom.lua. Implement Progressbar.Start() and Progressbar.Cancel(). See bridge/progressbar_example.lua for the full API contract and examples.

Config.Inventory

Controls which inventory resource is used for item operations (e.g. removing a broken lockpick).

ValueBehaviour
'auto'Detects at runtime in priority order: qs-inventory → ox_inventory → qb-inventory. Recommended for most servers.
'qb'Forces qb-inventory exports.
'qs'Forces qs-inventory exports.
'ox'Forces ox_inventory exports.

Config.UseDSGarages

When set to true, a Valet button is added to the keyfob NUI alongside the standard Lock / Unlock / Trunk / Engine controls. Pressing it opens a scrollable list of every vehicle the player currently has stored across all ds_garages garages. Selecting any entry dispatches a valet delivery request — the garage system spawns the chosen vehicle and drives it to the player's location.

Set this to false (or leave it unset) if ds_garages is not running on your server. The button is hidden entirely; no errors are thrown.

-- Enable the valet button (requires ds_garages)
Config.UseDSGarages = true

-- Disable the valet button (standalone / no ds_garages)
Config.UseDSGarages = false
The keyfob must also be enabled (Config.UseKeyfob = true) for the Valet button to be visible. If UseKeyfob is false the fob NUI never opens and this setting has no effect.

Config.SharedKeys

Employees of a listed job can lock and unlock any of that job's vehicles without owning the key. Set requireOnduty = true to restrict this to on-duty employees.

Config.SharedKeys = {
    ['police'] = {
        requireOnduty = false,
        vehicles = { 'police', 'police2', 'sheriff' }
    },
    ['mechanic'] = {
        requireOnduty = false,
        vehicles = { 'towtruck', 'towtruck2' }
    },
}

Config.ImmuneVehicles & Config.NoLockVehicles

Config.ImmuneVehicles — vehicle model names that cannot be carjacked (e.g. 'stockade').
Config.NoLockVehicles — model names that are never locked (e.g. bicycles). Bike class (13) and entities with state.ignoreLocks = true are also auto-exempt.

Config.CarjackChance

Per-weapon-group success probability for carjacking, keyed by the weapon group hash string.

Config.CarjackChance = {
    ['2685387236'] = 0.0,   -- melee
    ['416676503']  = 0.5,   -- handguns
    ['-957766203'] = 0.75,  -- SMG
    ['860033945']  = 0.90,  -- shotgun
    ['970310034']  = 0.90,  -- assault rifle
}

6 — Progressbar Bridge

Set Config.Progressbar = 'custom' and edit bridge/progressbar_custom.lua to hook in any progress bar resource. Two functions must be implemented:

Progressbar.Start(name, label, duration, opts, cb_done, cb_cancel)

ParameterTypeDescription
namestringUnique identifier for this bar (e.g. 'ds_hotwire').
labelstringText displayed on the progress bar.
durationnumberDuration in milliseconds.
optstableControl flags and animation data — see below.
cb_donefunctionCalled with no arguments when the bar completes successfully.
cb_cancelfunctionCalled with no arguments when the bar is cancelled or interrupted.

opts fields

FieldTypeDescription
disableMovementbooleanFreeze player movement during the bar.
disableCarMovementbooleanFreeze vehicle movement during the bar.
disableMousebooleanDisable mouse look during the bar.
disableCombatbooleanDisable combat controls during the bar.
animDictstring / nilAnimation dictionary to play while the bar runs.
animstring / nilAnimation name within the dictionary.
flagsnumber / nilAnimation flags (e.g. 16 for looping).

Progressbar.Cancel()

Force-cancel any active progress bar. Called by the carjack loop when the target ped dies or moves too far away.

Example — ox_lib progressBar

function Progressbar.Start(name, label, duration, opts, cb_done, cb_cancel)
    local ped = PlayerPedId()
    if opts.animDict and opts.anim then
        RequestAnimDict(opts.animDict)
        while not HasAnimDictLoaded(opts.animDict) do Wait(1) end
        TaskPlayAnim(ped, opts.animDict, opts.anim, 8.0, -8.0, -1, opts.flags or 16, 0, false, false, false)
    end
    local success = lib.progressBar({
        duration  = duration,
        label     = label,
        canCancel = true,
        disable   = {
            move   = opts.disableMovement    or false,
            car    = opts.disableCarMovement or false,
            combat = opts.disableCombat      or true,
            mouse  = opts.disableMouse       or false,
        },
    })
    if opts.animDict and opts.anim then
        StopAnimTask(ped, opts.animDict, opts.anim, 1.0)
    end
    if success then
        if cb_done then cb_done() end
    else
        if cb_cancel then cb_cancel() end
    end
end

function Progressbar.Cancel()
    lib.progressCancel()
end
The bridge/progressbar_example.lua file (always unencrypted) contains this and additional examples. Copy your implementation into bridge/progressbar_custom.lua.

7 — Inventory Bridge

The inventory bridge is server-side only. It exposes two functions used when a lockpick breaks:

Inventory.RemoveItem(src, itemName, count) boolean

Removes count of itemName from the player identified by server source src. Returns true on success.

Inventory.NotifyRemove(src, itemName)

Shows the inventory's built-in "item removed" UI feedback to the player (e.g. the qb-inventory item box). A no-op on inventories that handle this internally (ox, qs).

Config.InventoryRemoveItem callNotifyRemove call
'qb'exports['qb-inventory']:RemoveItem()qb-inventory:client:ItemBox event
'qs'exports['qs-inventory']:RemoveItem()no-op
'ox'exports.ox_inventory:RemoveItem()no-op
'auto'Resolves on first use — detects qs → ox → qb.

10 — Server Exports

All server exports are callable from any server-side resource with exports['ds_vehiclekeys']:FunctionName(...).

GiveKeys(src, plate, isOwner)

Give a player keys to a vehicle. isOwner = true marks the player as the legal owner and upserts the DB row. isOwner = false or nil gives a temporary key (persisted in temp_holders).

exports['ds_vehiclekeys']:GiveKeys(src, 'ABC 123', true)  -- owner
exports['ds_vehiclekeys']:GiveKeys(src, 'ABC 123')        -- temp key

RemoveKeys(src, plate)

Remove a player's keys (owner or temp) for a plate. If they were the owner, the owner column is cleared in the database.

HasKeys(src, plate) boolean

Returns true if the player currently holds any key type for the plate.

GetKeyType(src, plate) 'owner' | 'temp' | nil

Returns the key type the player holds, or nil if they have no keys.

GetAllKeysForPlayer(src) table

Returns { [plate] = 'owner'|'temp', ... } for every plate the player currently holds.

SetOwner(plate, citizenid)

Assign ownership by citizenid directly — no active player session required. Useful for dealership / purchase scripts that run entirely server-side. Pushes AddKeys to the buyer's client automatically if they are online.

-- Called from a vehicle purchase script after the sale is recorded
exports['ds_vehiclekeys']:SetOwner(plate, Player.PlayerData.citizenid)

BuyVehicleKeys(src, plate)

Purpose-built export for vehicle shop resources. Trims and uppercases the plate, writes the owner row to DB, updates the in-memory cache, pushes AddKeys to the buyer's client, and sends a success notification.

TransferOwnership(plate, newSrc)

Atomically transfer a vehicle from its current owner to a new owner. Evicts the old owner (strips keys + notifies), sets the new owner in memory and DB, updates player_vehicles, and pushes keys to the new owner's client.

RemoveAllKeysForPlate(plate)

Wipe ALL key holders (owner + temp) for a plate from memory and database. Use this when a vehicle is sold out of the system or permanently deleted.

GetPlateOwner(plate) citizenid | nil

Returns the owner citizenid for a plate, or nil if unclaimed.

DBSetOwner(plate, citizenid)

Low-level helper — directly upserts the owner row in the ds_vehiclekeys table. Prefer SetOwner or GiveKeys unless you need raw DB access.

11 — Client Exports

All client exports are callable from any client-side resource with exports['ds_vehiclekeys']:FunctionName(...).

HasKeys(plate) boolean

Returns true if the local player currently holds keys for the plate. Uses the local KeysList cache — no server round-trip.

GetKeyType(plate) 'owner' | 'temp' | nil

Returns what type of key the local player holds for the plate, or nil.

ToggleVehicleLocks(vehicle, lock)

Trigger a lock toggle from another resource. lock = true locks, false unlocks, nil toggles based on current state.

IsBlacklistedVehicle(vehicle) boolean

Returns true if the vehicle entity is on the no-lock / exempt list (bike class, ignoreLocks state, or in Config.NoLockVehicles).

AddNoLockVehicle(model) / RemoveNoLockVehicle(model)

Dynamically add or remove a vehicle model name from the no-lock list at runtime, without restarting the resource.

OpenKeyfob()

Programmatically open the keyfob NUI from another resource.

14 — Integration Examples

Vehicle Purchase (server-side)

-- In your vehicle shop server script, after writing to player_vehicles:
exports['ds_vehiclekeys']:BuyVehicleKeys(src, plate)
-- or, if you need to pass a citizenid directly (offline safe):
exports['ds_vehiclekeys']:SetOwner(plate, citizenid)

Spawn / Garage Retrieve (server-side)

-- Give the player keys when their vehicle is spawned from a garage:
exports['ds_vehiclekeys']:GiveKeys(src, plate, true)  -- marks as owner

Ownership Transfer (server-side)

-- When a player sells their vehicle to another player:
exports['ds_vehiclekeys']:TransferOwnership(plate, buyerSrc)

Vehicle Sale / Deletion (server-side)

-- When a vehicle is permanently removed from the server:
exports['ds_vehiclekeys']:RemoveAllKeysForPlate(plate)

Check Keys (client-side)

-- Any client script can check whether the local player holds keys:
if exports['ds_vehiclekeys']:HasKeys(plate) then
    -- player can drive this vehicle
end

Programmatic Lock (client-side)

-- Lock a specific vehicle entity from another resource:
exports['ds_vehiclekeys']:ToggleVehicleLocks(vehicleEntity, true)

15 — FAQ

Can I migrate from qb-vehiclekeys?

Yes. DS Vehicle Keys listens to all legacy qb-vehiclekeys events and exports. Simply stop qb-vehiclekeys, start ds_vehiclekeys, and run the SQL. Existing player_vehicles rows are unaffected — ownership is derived from the new ds_vehiclekeys table, which is populated automatically the first time each vehicle is spawned.

Players lose their keys on resource restart

This should not happen — keys are loaded from the database on every resource start and pushed to all online players. If you observe lost keys, check that oxmysql starts before ds_vehiclekeys and that the DB connection is healthy.

Hotwire bar does not appear

Make sure Config.Progressbar matches a running resource. If you set it to 'ds_progressbar' but that resource is not started, the bridge logs a warning and falls back to the QBCore bar automatically.

Lockpick does not remove from inventory

Check Config.Inventory. Set it to 'auto' and verify that at least one of qs-inventory, ox_inventory, or qb-inventory is running. The bridge logs which inventory it detects on first use.

NPC vehicles are not locking

Confirm that both Config.LockNPCDrivingCars and Config.LockNPCParkedCars are true. The lock is applied client-side when a player attempts to enter the vehicle — it does not affect vehicles they are not near.

Valet button does not appear on the keyfob

Check the following in order:

  1. Confirm Config.UseDSGarages = true is set in config.lua.
  2. Confirm Config.UseKeyfob = true — the valet button lives inside the keyfob NUI, so the fob must be enabled.
  3. Confirm ds_garages is listed in server.cfg and starts without errors before ds_vehiclekeys.
  4. If the garage list opens but is empty, the player has no vehicles currently stored in any ds_garages garage.

Valet delivery request is not arriving

The actual spawning and routing of the valet vehicle is handled entirely by ds_garages. If the delivery does not appear, check the ds_garages resource console for errors. DS Vehicle Keys only opens the selection UI and forwards the player's choice — it does not control the delivery logic.
