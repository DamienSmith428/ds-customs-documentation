DS Target

Entity & zone interaction system — qb-target compatible API, DS Customs visual language — by DS Customs

v1.0.0 QBCore FiveM Lua 5.4 PolyZone No SQL

1 — Overview

DS Target is a drop-in replacement for qb-target. It exposes the exact same export API so any existing resource that calls qb-target can be redirected with a one-line rename in server.cfg. The interaction UI is rebuilt in the DS Customs dark-glass aesthetic — corner brackets, accent colours, shimmer icon boxes, and a configurable eye reticle — matching ds_notify and ds_progressbar.

The API is a direct port of qb-target (BerkieB). If you already have target registrations working with qb-target they will work identically with ds_target — no code changes required in your other resources.

2 — Installation

  1. Ensure PolyZone is present in your resources — ds_target depends on it.
  2. Place the ds_target folder inside your resources directory (e.g. [Dependencies]).
  3. Add ensure ds_target to your server.cfg after PolyZone and before any resource that registers targets.
  4. If you were previously using qb-target, replace ensure qb-target with ensure ds_target. No other changes needed.
  5. Done — no SQL, no further configuration required.
# server.cfg
ensure PolyZone
ensure ds_target        # replaces qb-target
ensure my_job_resource  # any resource that registers targets
To declare the dependency formally in another resource, add dependency 'ds_target' to that resource's fxmanifest.lua.

3 — Configuration — config.lua

config.lua is open and unencrypted. All values here control the visual style and interaction behaviour of the target system globally.

-- Maximum raycast distance for targeting entities.
-- Keep low — entities can be detected through walls at high values.
Config.MaxDistance = 7.0

-- Accent colour for corner brackets, card outline, top-rule glow, and eye reticle.
-- Presets: 'blue' | 'red' | 'green' | 'gold' | 'purple' | 'teal' | 'orange' | 'white'
Config.Color = 'gold'

-- Unicode character shown as the centre eye reticle.
--   '◈'  Diamond dot (default)   '⊕'  Circled plus
--   '⊗'  X-circle                '◎'  Bullseye / ring dot
--   '✦'  Four-pointed star        '⬡'  Hexagon
--   '⌖'  Position target          '·'  Middle dot (minimal)
Config.EyeIcon = '◈'

-- FiveM input mapper key that opens the targeting eye.
Config.OpenKey = 'LMENU'  -- Left Alt

-- true  → DisableAllControlActions while targeting
-- false → disable only camera/aim controls; movement still works
Config.DisableControls = true

-- Prevent targeting while the player is inside a vehicle.
Config.DisableInVehicle = false

-- Draw a coloured outline on the entity being looked at.
Config.EnableOutline = false
Config.OutlineColor  = { 255, 255, 255, 255 }

-- Draw a dot sprite at the centre of PolyZone targets.
Config.DrawSprite       = true
Config.DrawDistance     = 10.0
Config.DrawColor        = { 255, 255, 255, 255 }
Config.SuccessDrawColor = { 220, 20, 60, 255 }

-- Enable built-in vehicle door toggle options.
Config.EnableDefaultOptions = true

Config.Debug = false

Config.Color presets

ValueCorner & reticle colour

'red'Danger / EMS red
'green'Success green
'gold'VIP / money gold (default)
'purple'Gang / dark-ops purple
'teal'Hacker / tech teal
'orange'Mechanic / service orange
'white'Clean / minimal white

4 — Option Definition

Every target registration accepts an options table — a list of option objects. Each object defines one entry in the interaction menu.

Option object keys

KeyTypeRequiredDescription
labelstringYesText shown in the menu row. Also used as the internal key — must be unique per registration.
iconstringYesFontAwesome class string for the icon box, e.g. 'fas fa-wrench'.
actionfunction*Lua function called with (entity) when the option is clicked. Use this or event.
eventstring*Event / command name triggered when the option is clicked.
typestringNoEvent dispatch type: 'client' (default), 'server', 'command', 'qbcommand'.
targeticonstringNoFA class to show on the eye reticle when this target is found. Overrides Config.EyeIcon.
distancenumberNoPer-option max distance override. Defaults to the registration's distance.
jobstring / tableNoRestrict to job name, or a table of {[jobName] = minGrade}.
excludejobstring / tableNoHide option for this job.
jobTypestring / tableNoRestrict by QBCore job type.
gangstring / tableNoRestrict to gang name, or {[gangName] = minGrade}.
itemstringNoRequire player to have this item in inventory.
citizenidstringNoRestrict to a specific citizen ID.
canInteractfunctionNoCustom check function (entity, distance, data) → boolean. Return false to hide the option.
Either action or event must be provided. If neither is set a Lua error is thrown when the player clicks the option.

Example option table

{
    options = {
        {
            label  = 'Repair Vehicle',
            icon   = 'fas fa-wrench',
            action = function(entity)
                TriggerEvent('mechanic:repairVehicle', entity)
            end,
        },
        {
            label  = 'Open Trunk',
            icon   = 'fas fa-door-open',
            job    = 'mechanic',    -- only mechanics see this
            event  = 'vehicle:openTrunk',
            type   = 'client',
        },
    },
    distance = 2.5,
}

5 — Zone Exports

Zone targets trigger when the player's raycast end-point is inside the zone. All zones are backed by PolyZone.

AddCircleZone

exports['ds_target']:AddCircleZone(
    name,           -- string  — unique zone name
    center,         -- vector3 / table  — {x,y,z}
    radius,         -- number  — circle radius in metres
    options,        -- table   — PolyZone options: {name, debugPoly, useZ}
    targetoptions   -- table   — {options={...}, distance=number}
)

AddBoxZone

exports['ds_target']:AddBoxZone(
    name, center, length, width,
    options,        -- {name, heading, debugPoly, minZ, maxZ}
    targetoptions   -- {options={...}, distance=number}
)

AddPolyZone

exports['ds_target']:AddPolyZone(
    name,
    points,         -- table of vector2/vector3/vector4 or {x,y} tables
    options,        -- {name, debugPoly, minZ, maxZ}
    targetoptions   -- {options={...}, distance=number}
)

AddEntityZone

exports['ds_target']:AddEntityZone(
    name, entity,
    options,        -- PolyZone EntityZone options
    targetoptions   -- {options={...}, distance=number}
)

AddComboZone

exports['ds_target']:AddComboZone(
    zones,          -- table of existing zone objects
    options,        -- {name, ...}
    targetoptions   -- {options={...}, distance=number}
)

RemoveZone

exports['ds_target']:RemoveZone(name) -- destroys and unregisters the zone

Zone example

exports['ds_target']:AddBoxZone(
    'mechanic_bench',
    vector3(-351.4, -130.1, 38.6),
    1.8, 1.2,
    { name = 'mechanic_bench', heading = 12, debugPoly = false, minZ = 37.6, maxZ = 40.6 },
    {
        options = {
            {
                label  = 'Use Workbench',
                icon   = 'fas fa-screwdriver',
                job    = 'mechanic',
                action = function() TriggerEvent('mechanic:openBench') end,
            },
        },
        distance = 1.5,
    }
)

6 — Entity Exports

Target a specific entity by its handle. Supports both networked and local (non-net) entities. The handle is automatically converted to a network ID for networked entities so targets survive across sessions.

AddTargetEntity

exports['ds_target']:AddTargetEntity(
    entities,     -- number | table of numbers — entity handle(s)
    parameters    -- {options={...}, distance=number}
)

RemoveTargetEntity

exports['ds_target']:RemoveTargetEntity(
    entities,     -- number | table of numbers
    labels        -- string | table of strings — option labels to remove, or nil to remove all
)

7 — Model Exports

Target every entity of a given model hash. Accepts model strings (auto-hashed with joaat) or raw hashes.

AddTargetModel

exports['ds_target']:AddTargetModel(
    models,       -- string | number | table — model name(s) or hash(es)
    parameters    -- {options={...}, distance=number}
)

-- Example: every gas pump on the map
exports['ds_target']:AddTargetModel('prop_gas_pump_1d', {
    options  = {{ label = 'Refuel', icon = 'fas fa-gas-pump', action = function(e) ... end }},
    distance = 2.0,
})

RemoveTargetModel

exports['ds_target']:RemoveTargetModel(models, labels)

8 — Bone Exports

Target a named vehicle bone (e.g. 'bonnet', 'boot', 'door_dside_f'). The system picks the closest matching bone from the list and shows those options.

AddTargetBone

exports['ds_target']:AddTargetBone(
    bones,        -- string | table of strings — bone name(s)
    parameters    -- {options={...}, distance=number}
)

-- Example: add a "Open Bonnet" option on the bonnet bone of every vehicle
exports['ds_target']:AddTargetBone({ 'bonnet' }, {
    options  = {{ label = 'Open Bonnet', icon = 'fas fa-car-battery', action = function(e) ... end }},
    distance = 2.5,
})

RemoveTargetBone

exports['ds_target']:RemoveTargetBone(bones, labels)

Add options to every entity of a given GTA entity type (ped, vehicle, object) or every other player.

AddGlobalVehicle(parameters)All vehicles (entity type 2)
AddGlobalObject(parameters)All objects (entity type 3)
AddGlobalPlayer(parameters)All other player peds
RemoveGlobalPed(labels)Remove ped options by label
RemoveGlobalVehicle(labels)Remove vehicle options by label
RemoveGlobalObject(labels)Remove object options by label
RemoveGlobalPlayer(labels)Remove player options by label
 
-- Show a "Frisk Player" option on every other player (police only)
exports['ds_target']:AddGlobalPlayer({
    options = {
        {
            label  = 'Frisk Player',
            icon   = 'fas fa-hands',
            job    = 'police',
            action = function(entity) TriggerEvent('police:frisk', entity) end,
        },
    },
    distance = 2.0,
})

12 — Config Pre-registration

Targets that should exist from server start can be declared directly in config.lua instead of registering them from another resource. All tables default to empty — add entries as needed.

-- Circle zones
Config.CircleZones = {
    {
        name     = 'atm_legion',
        coords   = vector3(195.0, -933.8, 30.7),
        radius   = 1.2,
        useZ     = true,
        options  = {{ label = 'Use ATM', icon = 'fas fa-credit-card', action = function() ... end }},
        distance = 1.5,
    },
}

-- Model targets
Config.TargetModels = {
    {
        models   = { 'prop_atm_01', 'prop_atm_02' },
        options  = {{ label = 'Use ATM', icon = 'fas fa-credit-card', action = function() ... end }},
        distance = 1.5,
    },
}

-- Also available: Config.BoxZones, Config.PolyZones, Config.TargetBones
-- Config.GlobalPedOptions, Config.GlobalVehicleOptions
-- Config.GlobalObjectOptions, Config.GlobalPlayerOptions

13 — Ped Spawning (Config.Peds)

DS Target can spawn and manage targetable scenario peds from config.lua. Peds are created on resource start and deleted on resource stop, and are automatically re-created on player spawn.

Config.Peds = {
    {
        model    = 'a_m_m_skater_01',
        coords   = vector4(-350.2, -125.0, 38.6, 90.0),  -- x, y, z, heading
        freeze   = true,
        invincible = true,
        scenario = 'WORLD_HUMAN_STAND_MOBILE',
        options  = {
            {
                label  = 'Talk to Mechanic',
                icon   = 'fas fa-comment',
                action = function() TriggerEvent('mechanic:openMenu') end,
            },
        },
        distance = 2.5,
    },
}

├── config.lua            ← Color, eye icon, distance, controls, pre-registered targets (open)
├── client.lua            ← Core raycast loop, NUI bridge, QBCore job/gang/item checks
├── registration.lua      ← All Add* / Remove* / Get* / Update* exports
├── peds.lua              ← SpawnPeds / DeletePeds driven by Config.Peds
├── data/
│   ├── bones.lua         ← Bone name list and options table
│   └── debug.lua         ← Debug overlay (loaded when Config.Debug = true)
└── html/
    ├── index.html        ← NUI root — eye reticle + option list DOM
    ├── style.css         ← Dark-glass visual styles, color tokens, corner brackets
    └── app.js            ← NUI message handler: openTarget / foundTarget / leftTarget / closeTarget

16 — Notes

  • The export API is fully compatible with qb-target. Changing ensure qb-target → ensure ds_target in server.cfg is the only change needed in most setups.
  • Option label strings are used as internal dictionary keys. They must be unique per registration; duplicate labels in the same AddTarget* call will overwrite each other silently.
  • required_item is accepted as an alias for item for compatibility with legacy qb-target option tables.
  • The Config.EyeIcon setting accepts any Unicode glyph or emoji — the NUI automatically detects whether it is a FontAwesome class string or a raw Unicode character and renders accordingly.
  • Entity outlines (Config.EnableOutline) are skipped on ped entities to avoid visual conflicts with targeting overlays.
  • DS Target has no database calls. The only hard dependency is PolyZone. QBCore is optional — job/gang/item checks simply pass when QBCore is not detected.
  • The resource is Escrow-protected except for config.lua, which is fully open.
