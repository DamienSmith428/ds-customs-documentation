DS Duty Creator

In-game admin NUI panel for placing and managing duty clock-in/out locations for any job — no config editing required — by DS Customs

v1.0.0 QBCore Qbox ESX FiveM Lua 5.4 oxmysql Free Escrow

1 — Overview

DS Duty Creator is a free, fully in-game admin tool for placing duty clock-in and clock-out locations for any job on your server. Open the /dutycreator NUI panel, select a job, and use the visual placement mode to drop a duty zone anywhere in the world — all without editing a single config file or restarting the server.

  • Pick any job from the live job list (sourced directly from your framework).
  • Place duty locations in-world using a visual ray-cast cursor — just aim and press E.
  • All locations are stored in MySQL and loaded automatically on every server start.
  • Each location registers a sphere zone using your configured target resource — players see a Clock In or Clock Out option depending on their current duty state.
  • Delete any location from inside the NUI panel at any time.
  • Supports QBCore, Qbox (qbx_core), and ESX out of the box.
  • Supports ox_target, qb-target, and ds_target.
This is a free resource. All files except config.lua are escrow encrypted via Cfx escrow. config.lua is fully open and editable.

3 — Installation

  1. Place the ds_dutycreator folder inside your resources directory (e.g. resources/[ds]/ds_dutycreator).
  2. Add ensure ds_dutycreator to your server.cfg after ox_lib, oxmysql, your framework, and your target resource.
  3. Start the resource — the ds_duty_locations table is created automatically on first run. No SQL import required.
  4. Open config.lua and set Config.Framework and Config.Target to match your server.
  5. In-game, type /dutycreator to open the panel.

server.cfg Start Order

ensure ox_lib
ensure oxmysql
ensure qbx_core        # or qb-core / es_extended
ensure ox_target       # or qb-target / ds_target
ensure ds_dutycreator
The ds_duty_locations MySQL table is created automatically using CREATE TABLE IF NOT EXISTS — safe to restart as many times as needed without losing data.

4 — Configuration — config.lua

config.lua is the only file that is not escrow encrypted. It is fully open and freely editable.

Config = {}

-- The chat command that opens the Duty Creator UI.
Config.Command = 'dutycreator'

-- Which framework is running on this server.
-- Options: 'qbx_core' | 'qb-core' | 'esx'
Config.Framework = 'qbx_core'

-- Which targeting resource is installed on this server.
-- Options: 'ds_target' | 'ox_target' | 'qb-target'
Config.Target = 'ox_target'

-- Radius (in metres) around each duty location that triggers the target option.
Config.TargetRadius = 1.5

-- Icon shown in the target menu (ox_target / ds_target support icons).
Config.TargetIcon = 'fa-solid fa-clock'

5 — Duty Creator Panel — /dutycreator

Open the panel in-game with /dutycreator. Press Escape or click ✕ to close the panel.

Job List

The left sidebar lists every job registered in your framework (sourced live at panel open). Use the search bar to filter jobs by name in real time. Click any job to open its duty locations in the right panel.

Managing Locations

With a job selected, the right panel shows all existing duty locations for that job. Each entry shows the world coordinates and a Delete button. To add a new location, click + Add Location — this closes the NUI and enters Placement Mode.

Placement Mode

In placement mode a red ray-cast cursor projects from your camera onto the world surface, along with a visual guide line from your character. A text hint appears at the top of the screen:

[E] Place Location   [Backspace] Cancel

All player controls are locked during placement except camera look, camera zoom, and the two action keys. Once you aim at your desired spot:

  • Press E to confirm — the coordinates are saved to the database, the zone is registered immediately, and the NUI panel reopens showing the new entry.
  • Press Backspace to cancel — no changes are made and the NUI panel reopens.

Deleting a Location

Click Delete on any location row. The row is removed from the database and the corresponding target zone is unregistered immediately — no restart required.

6 — Duty Toggle

When a player walks within Config.TargetRadius metres of a duty location and uses the target interaction, the zone shows one of two options:

OptionVisible whenResult
Clock InPlayer is currently off dutyToggles the player on-duty in the framework and sends a success notification.
Clock OutPlayer is currently on dutyToggles the player off-duty in the framework and sends an inform notification.
The server verifies that the player's current job matches the duty location's assigned job before toggling. If they are not employed in the correct job, the toggle is rejected and they receive an error notification.

Framework Behaviour

FrameworkToggle method
qbx_coreServer-side via exports['qbx_core']:SetJobDuty(src, state)
qb-coreServer-side via player.Functions.SetJobDuty(state)
esxServer-side via xPlayer.setMeta('onduty', state) — the new state is also forwarded to the client via a net event so the duty check stays accurate.

7 — Database

A single table is created automatically on first resource start. No manual SQL import is ever needed.

ds_duty_locations schema

CREATE TABLE IF NOT EXISTS `ds_duty_locations` (
    `id`       INT UNSIGNED NOT NULL AUTO_INCREMENT,
    `jobname`  VARCHAR(64)  NOT NULL,
    `x`        FLOAT        NOT NULL,
    `y`        FLOAT        NOT NULL,
    `z`        FLOAT        NOT NULL,
    PRIMARY KEY (`id`),
    INDEX `idx_jobname` (`jobname`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

One row per duty location. Multiple locations per job are supported — add as many as you need. Locations are loaded on every server start via a single SELECT query and registered as target zones on the client.

9 — Version Checker

On every server start, DS Duty Creator checks for updates by fetching the latest version number from the DS Customs GitHub. The result is printed to the server console:

Console outputMeaning
Running latest version 1.0.0You are up to date.
Your version 1.0.0 is outdated! Latest version is 1.x.xA newer version is available — update via Tebex.
Your version is higher than the latestYou are running a pre-release or development build.

If no version file exists for the resource on GitHub the check is silently skipped — this will never cause errors or delay server startup.

10 — FAQ

Do duty locations persist after a server restart?

Yes. All locations are stored in the ds_duty_locations MySQL table and loaded automatically on every resource start. Zones are re-registered on all clients as they connect.

A player at a duty location doesn't see the Clock In option

The server verifies the player's current job matches the duty location's assigned job. If they are employed in a different job they will not see the option. The canInteract check on the client also hides the matching option based on current duty state.

Zones don't appear after placing a location

Zones are registered on the client immediately after a successful addLocation callback — no restart is needed. If a zone doesn't appear, verify that your Config.Target matches the resource that is actually running on your server, and that the target resource started before ds_dutycreator.

The job list is empty

The job list is fetched live from your framework at panel open. Verify that Config.Framework is set correctly and that your framework resource is running and started before ds_dutycreator.

ESX duty state isn't updating on the client

When using ESX, the server fires a ds_dutycreator:setDutyState net event to the player after every toggle. The client stores this state and uses it for the canInteract check. If the state appears stale, verify your ESX version exposes xPlayer.setMeta.

Is this really free?

Yes. DS Duty Creator is completely free. You can find it on the DS Customs Tebex store at no cost. config.lua is open and editable; all other Lua files are escrow encrypted to protect the source.
