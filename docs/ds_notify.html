DS Notify

Standalone toast notification system — one renderer, one style, zero duplication — by DS Customs

v1.0.0 QBCore FiveM Lua 5.4 No SQL Free

1 — Overview

DS Notify is a single, self-contained notification resource that any other resource on your server can use. It renders toast notifications in a consistent style — top, center, or bottom of the screen — without every script shipping its own NUI overlay.

DS Notify has no server-side database calls and no hard dependencies. It works out of the box — drop it in, ensure it, done.

2 — Installation

  1. Place the ds_notify folder inside your resources directory.
  2. Add ensure ds_notify to your server.cfg before any resource that depends on it.
  3. Done — no SQL, no further configuration required.
# server.cfg
ensure ds_notify
ensure qb-policejob     # any resource that uses ds_notify
ensure gs-businessbanking
To declare the load-order dependency in another resource, add dependency 'ds_notify' to that resource's fxmanifest.lua.

3 — Configuration — config.lua

The only setting is toast position. config.lua is open and unencrypted.

Config.Position = 'bottom-right'

Valid position values

ValueDescription
'top-left'Top left corner
'top-center'Top center
'top-right'Top right corner
'center-left'Middle-left edge
'center-right'Middle-right edge
'bottom-left'Bottom left corner
'bottom-center'Bottom center
'bottom-right'Bottom right corner (default)

Multiple notifications stack vertically in the chosen corner. Older toasts slide out automatically after their duration expires.

4 — Notification Types

ntypeColourUse for
'success'GreenCompleted actions, positive outcomes. Default when omitted.
'error'RedFailures, permission denials, invalid input.
'info'BlueNeutral information, loading states, countdowns.

5 — Parameters

ParameterTypeRequiredDefaultDescription
messagestringYes—The text displayed in the toast.
ntypestringNo'success'Visual style. One of 'success', 'error', 'info'.
durationnumberNo3500How long the toast stays visible, in milliseconds.

6 — Client-side Usage

Call from any client-side Lua script in your resource.

Export (recommended)

-- Minimal — type defaults to 'success', duration defaults to 3500 ms
exports['ds_notify']:Notify("You collected a bag!")

-- With type
exports['ds_notify']:Notify("You don't have enough cash", "error")
exports['ds_notify']:Notify("Loading...", "info")

-- With custom duration (6 seconds)
exports['ds_notify']:Notify("This stays longer", "info", 6000)

Local event

Any client-side script can fire a notification as a local event — useful when you don't want to declare a dependency but ds_notify is running:

TriggerEvent('ds_notify:notify', "Job started!", "success")
TriggerEvent('ds_notify:notify', "Access denied", "error", 4000)

7 — Server-side Usage

Call from any server-side Lua script to push a notification to one or all players.

NotifyClient(src, message, ntype?, duration?) void

Sends a notification to a single connected player.

exports['ds_notify']:NotifyClient(source, "You were hired!", "success")
exports['ds_notify']:NotifyClient(source, "Transaction declined", "error")
exports['ds_notify']:NotifyClient(source, "Processing...", "info", 6000)

NotifyAll(message, ntype?, duration?) void

Sends a notification to every currently connected player.

exports['ds_notify']:NotifyAll("Server restart in 5 minutes!", "info")
exports['ds_notify']:NotifyAll("Maintenance complete", "success", 8000)

Net events (alternative to exports)

-- Single player by source
TriggerClientEvent('ds_notify:notify', source, "You were promoted!", "success")

-- All players (pass -1 as the target)
TriggerClientEvent('ds_notify:notify', -1, "Server event starting!", "info")

8 — NUI / JavaScript Usage

NUI frames are sandboxed per resource — JavaScript inside your resource's HTML cannot call ds_notify directly. The correct pattern routes through a NUI callback in your own resource's client Lua.

Step 1 — Add to your resource's client.lua

RegisterNUICallback('dsNotify', function(data, cb)
    exports['ds_notify']:Notify(data.message, data.ntype, data.duration)
    cb('ok')
end)

Step 2 — Add a helper to your resource's script.js

function dsNotify(message, type, duration) {
    fetch(`https://${GetParentResourceName()}/dsNotify`, {
        method:  'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({
            message:  message  || '',
            ntype:    type     || 'success',
            duration: duration || 3500
        })
    }).catch(() => {});
}

Step 3 — Call it anywhere in your JS

dsNotify("Added item to cart", "success", 2200);
dsNotify("Enter a valid amount", "error");
dsNotify("Loading inventory...", "info", 5000);

10 — File Structure

ds_notify/
├── fxmanifest.lua     ← Resource manifest
├── config.lua         ← Position setting (open, editable)
├── client.lua         ← Notify() export + ds_notify:notify event handler
├── server.lua         ← NotifyClient() and NotifyAll() server exports
└── html/
    ├── index.html     ← NUI root — toast container
    ├── style.css      ← Toast styles (position, colours, animations)
    └── script.js      ← NUI message handler; creates and removes toasts

11 — Notes

  • duration is optional in every call — omit it to use the default 3 500 ms.
  • Multiple notifications stack in the configured corner. Each auto-dismisses independently.
  • DS Notify has no database calls and no QBCore dependency. It is purely a UI bridge.
  • The resource is Escrow-protected except for config.lua, which is fully open.
