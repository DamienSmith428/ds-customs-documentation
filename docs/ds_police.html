DS Police (Qbx Police Enhanced)

Full-featured, multi-framework police job — armory, garage, evidence, ANPR, breathalyzer, trackers, security cameras, and more — by DS Customs

v1.0.0 Qbox QBCore ESX ox_inventory qb-inventory qs-inventory Lua 5.4 Escrow

1 — Overview

DS Police (Qbx Police Enhanced) is a fully modular police job built on top of the open-source qbx_policejob base and heavily extended by DS Customs. It ships with a bridge layer that auto-detects your framework, inventory system, and target resource — no manual wiring required in most cases.

It is designed as the third leg of the DS law-enforcement package, alongside DS MDT and DS CAD. All three can be used together or independently.

This is a v1.0.0 beta release. Core systems are stable and production-ready. Additional features are actively being added.

3 — Escrow & Open Files

DS Police is protected with FiveM Escrow. All config files are excluded so you can fully customise the resource.

  • html/*

4 — Installation

server.cfg Start Order

ensure oxmysql
ensure ox_lib
ensure qbx_core        # or qb-core / es_extended
ensure ox_inventory    # or your chosen inventory
ensure ox_target       # or qb-target / ds_target
ensure qbx_police

Register these items in your inventory resource. The exact method depends on your inventory — for ox_inventory place them in ox_inventory/data/items.lua; for qb-core add them to QBCore/shared/items.lua.

Admin permissions

The /policelocations admin command (used to place PD database terminals in-game) is restricted by ace permissions. Grant access:

The locations table defines all interaction points. Each entry is a vec3 (or vec4 for spawns). You can add multiple entries per location type.

KeyDescription

config/shared.lua — Breathalyzer

Full BAC simulation with per-item alcohol levels, decay rates, visual effects, and verdict thresholds.

KeyDefaultDescription
breathalyzer.item'breathalyzer'Inventory item the officer must hold to run a test.
breathalyzer.decayInterval60 sHow often (in seconds) all players' BAC values decay.
breathalyzer.alcoholItemsbeer, wine, whiskey…Keyed by item name. Each entry sets alcoholLevel (BAC added on use) and decayRate (BAC removed per tick).
breathalyzer.thresholds0.04 · 0.08 · 0.15BAC cutoffs for Sober → Impaired → Drunk → Heavily Intoxicated verdicts.

config/shared.lua — Speed Radars

radars.speedFines is an ordered array of fine tiers. Fines are applied when the vehicle speed-over-limit falls within the corresponding maxSpeed bracket.

8 — Integration with DS MDT & DS CAD

DS Police is built to work as part of the DS law-enforcement package. Here is how the three resources interact:

Integration pointHow it works
Callsign sync/callsign writes to the players table. DS MDT and DS CAD both read the callsign column and display it on officer cards and the live map.
/911p → DispatchThe /911p command fires the ds_mdt:server:addDispatchCall net event. DS MDT receives it and shows a live dispatch alert to all on-duty officers with the MDT open.
Duty stateClock-in/out calls the framework's duty API (SetJobDuty for Qbox/QBCore). DS MDT reads player.job.onduty to determine officer visibility on the live map.
Jail integrationWhen DS MDT's UseInternalJailSystem is enabled, DS Police's /jail command writes the sentence to the mdt_jail table. DS MDT then handles the countdown, task system, and release teleport.
ANPR / BOLO checkDS Police's ANPR radar calls exports['ds_mdt']:HasActiveBolo(plate) to check whether a scanned plate has an active BOLO, and notifies the officer accordingly.
 
ensure oxmysql
ensure ox_lib
ensure qbx_core
ensure ox_inventory
ensure ox_target
ensure ds_mdt
ensure ds_cad
ensure qbx_police   # starts last; all dependencies must be running first

9 — FAQ & Troubleshooting

Officers can't clock in / clock out

Check that the duty coords in config/shared.lua → locations.duty match somewhere accessible in your map. The interaction appears as an ox_lib target zone or proximity prompt depending on useTarget.

The garage shows no vehicles

Verify that the player's job grade level matches a key in authorizedVehicles (grades start at [0]). Also confirm the vehicle spawn names exist in your server's vehicle database.

Handcuffs / cuff commands don't work

The handcuffs item (or whatever you set in config.handcuffItems) must be registered in your inventory. For hard cuffs the item must be in the officer's inventory. The /sc soft-cuff command does not require an item.

Breathalyzer test returns nothing

Ensure the breathalyzer item is registered and the officer has it in their inventory. The test only works within the interaction range of the target player.

Speed radars aren't triggering

Set radars.enableRadars = true in config/client.lua. Radars are disabled by default. Also confirm radars.locations contains valid vec4 entries.

ANPR isn't checking BOLOs

ANPR calls exports['ds_mdt']:HasActiveBolo(). DS MDT must be running and started before qbx_police. If DS MDT is not present, the export will return nil and the BOLO check is silently skipped.
