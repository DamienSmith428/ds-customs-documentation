DS Bridge

Universal multi-framework bridge — framework, inventory, fuel, target, and vehicle keys — by DS Customs

v1.1.0 QBCore Qbox ESX FiveM Lua 5.4 No SQL

1 — Overview

DS Bridge is a shared dependency used by all DS Customs resources. It provides a single, normalised API that abstracts away the underlying framework (QBCore, Qbox, ESX), inventory (ox_inventory, qb-inventory, ps-inventory, qs-inventory), fuel (ox_fuel, LegacyFuel, ps-fuel, cdn-fuel, lc_fuel, esx-sna-fuel), target (ox_target, qb-target, ds_target), and vehicle keys (qb-vehiclekeys, qbx_vehiclekeys, ds_vehiclekeys) scripts running on your server.

Every DS Customs resource calls exports['ds_bridge']:SomeFunction() instead of calling framework- or script-specific APIs directly. You configure ds_bridge once in config.lua and all resources automatically use the correct implementation.

DS Bridge also fires normalised events (ds_bridge:playerLoaded, etc.) that any resource can listen to regardless of which framework is active — no framework-specific event names needed.

2 — Installation

  1. Place the ds_bridge folder inside your resources directory (e.g. [Dependencies]).
  2. Add ensure ds_bridge to your server.cfg before any DS Customs resource that depends on it.
  3. Open config.lua and set each option to match the scripts you have installed on your server.
  4. Done — no SQL, no further setup required.
# server.cfg
ensure ds_bridge         # must come before all ds_ resources
ensure ds_vehiclekeys
ensure ds_garages
ensure ds_atmrobbery
# ... other ds_ resources

3 — Configuration — config.lua

config.lua is open and unencrypted. Set each option to the exact resource name of the script you are running. These names must match both the resource folder name on your server and the filename of the bridge module inside ds_bridge.

Bridge.Config.Framework  = 'qb-core'      -- 'qb-core' | 'qbx_core' | 'es_extended'
Bridge.Config.Fuel       = 'ox_fuel'      -- 'ox_fuel' | 'ps-fuel' | 'cdn-fuel' | 'LegacyFuel' | 'lc_fuel' | 'esx-sna-fuel'
Bridge.Config.Inventory  = 'ox_inventory' -- 'ox_inventory' | 'qb-inventory' | 'ps-inventory' | 'qs-inventory'
Bridge.Config.Target     = 'qb-target'    -- 'ox_target' | 'qb-target' | 'ds_target'
Bridge.Config.VehicleKeys= 'qb-vehiclekeys' -- 'qb-vehiclekeys' | 'qbx_vehiclekeys' | 'ds_vehiclekeys'

Bridge.Config.Debug      = false          -- true prints module loading info to the console

4 — Adding Custom Modules

DS Bridge supports custom module folders. This lets you add support for a script that is not built in — for example a different inventory system — without modifying any encrypted files.

How module loading works

The loader maps each config value to a filename. For the built-in categories (inventories, fuel, etc.) it loads only the one file matching your config value from that folder. For custom modules declared in Bridge.Config.Modules it loads every .lua file found in the module's server/ and client/ sub-folders.

Adding a custom inventory (or any built-in category)

To add a new inventory not in the built-in list — e.g. my_inventory:

  1. Set Bridge.Config.Inventory = 'my_inventory' in config.lua.
  2. Create ds_bridge/inventories/server/my_inventory.lua — implement the Bridge.Inventory.* server API (see Section 6).
  3. Create ds_bridge/inventories/client/my_inventory.lua — implement the Bridge.Inventory.* client API (see Section 7).
  4. Add the two glob patterns to fxmanifest.lua so FiveM can find the new files — the existing wildcard inventories/server/*.lua and inventories/client/*.lua already covers any file added to those folders, so no manifest change is needed.
The same approach applies to all built-in categories: framework, fuel, target, and vehiclekeys. The config value must exactly match the .lua filename (without the extension).

Adding a fully custom module folder

For a completely new category (e.g. dispatch, housing) that doesn't fit an existing folder:

  1. Add the folder name to Bridge.Config.Modules in config.lua: 
    Bridge.Config.Modules = { 'dispatch' }
  2. Create the folder structure: 
    ds_bridge/dispatch/server/dispatch.lua
ds_bridge/dispatch/client/dispatch.lua
  3. Add the glob patterns to fxmanifest.lua: 
    -- in server_scripts { }
'dispatch/server/*.lua',

-- in client_scripts { }
'dispatch/client/*.lua',
Custom modules load all .lua files in their server/ and client/ folders — there is no single-file selection for them. You can split your implementation across as many files as you like.

5 — Normalised Events

DS Bridge listens to the active framework's native events and re-fires them under consistent ds_bridge: names. Any resource can listen to these without knowing which framework is running.

Server-side events

EventParametersDescription
ds_bridge:playerLoadedsourceA player finished loading into the server.
ds_bridge:playerUnloadedsourceA player is being unloaded / disconnected.
ds_bridge:playerDataUpdatedsource, key, valueA player's data changed (job, gang, money, etc.).

Client-side events

EventParametersDescription
ds_bridge:playerLoaded—The local player finished loading.
ds_bridge:playerUnloaded—The local player is being unloaded.
ds_bridge:playerDataUpdatedkey, valueThe local player's data changed.
ds_bridge:vehicleKeysGrantedplateThe local player was given keys to a vehicle.
ds_bridge:vehicleKeysRevokedplateThe local player's keys for a vehicle were removed.
 
-- Server example
AddEventHandler('ds_bridge:playerLoaded', function(source)
    print('Player loaded: ' .. source)
end)

-- Client example
AddEventHandler('ds_bridge:vehicleKeysGranted', function(plate)
    print('Got keys for: ' .. tostring(plate))
end)

8 — Custom Module Template

Use these starter templates when writing a new inventory (or any other built-in category) module. Replace my_inventory with your config value throughout.

inventories/server/my_inventory.lua

Bridge.Inventory = Bridge.Inventory or {}

function Bridge.Inventory.AddItem(source, item, count, metadata)
    return exports.my_inventory:AddItem(source, item, count, metadata)
end

function Bridge.Inventory.RemoveItem(source, item, count, metadata)
    return exports.my_inventory:RemoveItem(source, item, count, metadata)
end

function Bridge.Inventory.GetItemCount(source, item)
    return exports.my_inventory:GetItemCount(source, item)
end

function Bridge.Inventory.HasItem(source, item, count)
    return exports.my_inventory:GetItemCount(source, item) >= (count or 1)
end

function Bridge.Inventory.GetInventory(source)
    return exports.my_inventory:GetInventoryItems(source)
end

function Bridge.Inventory.RegisterStash(stashId, options)
    exports.my_inventory:RegisterStash(stashId, options.slots or 50, options.weight or 100000)
end

print('[ds_bridge] inventories/server: my_inventory loaded')

inventories/client/my_inventory.lua

Bridge.Inventory = Bridge.Inventory or {}

function Bridge.Inventory.GetItemCount(item)
    return exports.my_inventory:GetItemCount(item)
end

function Bridge.Inventory.HasItem(item, count)
    return exports.my_inventory:GetItemCount(item) >= (count or 1)
end

function Bridge.Inventory.OpenStash(stashId)
    exports.my_inventory:OpenStash(stashId)
end

print('[ds_bridge] inventories/client: my_inventory loaded')
Check the built-in files (e.g. inventories/server/ox_inventory.lua) for reference implementations. They are the authoritative examples of what each category's Bridge.* table must expose.

10 — Notes

  • config.lua and fxmanifest.lua are always plain and unencrypted — everything else is Escrow-protected.
  • The config value for each category must exactly match the .lua filename (without the extension) of the module file you want to load.
  • When adding a new file to an existing built-in category folder (e.g. inventories/server/), no manifest changes are needed — the existing *.lua wildcard glob already covers it.
  • When adding a completely new module folder via Bridge.Config.Modules, you must add the corresponding glob lines to fxmanifest.lua so FiveM registers those files.
  • DS Bridge has no database calls and no hard dependencies beyond the framework and inventory scripts you configure.
  • Set Bridge.Config.Debug = true to print module loading info to the server console — useful when diagnosing why a module is not loading.
