DS Job Creator

In-game admin NUI panel for creating, editing, and managing QBCore jobs on a live server — no file editing required — by DS Customs

v1.3.0 QBCore FiveM Lua 5.4 oxmysql

1 — Overview

DS Job Creator is a fully in-game admin tool for managing every QBCore job on your live server. Open the /jobcreator NUI panel, add or edit jobs and grades, set boss-menu and stash locations by walking to them in-world, and write everything back to jobs.lua — all without ever restarting the server or touching a file manually.

  • Create, edit, and delete jobs and grade tiers in the NUI panel.
  • Changes are applied live to QBCore.Shared.Jobs via AddJob / UpdateJob / RemoveJob exports — no restart needed.
  • Every save writes a clean jobs.lua to the resource folder so jobs survive a full server restart.
  • A sync_jobs.bat helper is auto-generated to copy that file into qb-core/shared/jobs.lua with a double-click.
  • In-game Boss Menu lets job bosses hire, fire, promote, and demote employees at a configurable in-world location.
  • Per-job Stash locations give all job members access to a shared inventory at a configurable in-world point.
All admin actions — including location placement — are restricted server-side to players with the admin, command, or god ace permission. The Boss Menu is restricted to boss-grade employees of that specific job.

3 — Installation

  1. Place the ds_jobcreator folder inside your resources directory (e.g. resources/[admin]/ds_jobcreator).
  2. Add ensure ds_jobcreator to your server.cfg after qb-core and oxmysql.
  3. Grant the admin ace permission to any player who should access the panel.
  4. Start or restart the resource — the ds_jobcreatorlocations table is created automatically by oxmysql on first run.
  5. In-game, type /jobcreator to open the panel.

server.cfg Start Order

ensure qb-core
ensure oxmysql
ensure ds_notify      # optional — only needed if Config.Notify = 'ds_notify'
ensure ds_prompt      # optional — only needed if Config.Prompt = 'ds_prompt'
ensure ds_jobcreator
The ds_jobcreatorlocations MySQL table is created automatically with CREATE TABLE IF NOT EXISTS — no manual SQL import is required.

4 — Configuration — config.lua

config.lua is unescrow'd and fully open. Three options are available:

-- Notification system to use for player-facing messages
Config.Notify = 'ds_notify'   -- 'built-in' | 'ds_notify' | 'custom'

-- Interaction prompt system to use near boss-menu and stash locations
Config.Prompt = 'ds_prompt'   -- 'built-in' | 'ds_prompt' | 'custom'

-- Auto-generate sync_jobs.bat on every "Write to jobs.lua" click
Config.GenerateSyncBat = true  -- true | false
OptionValuesDescription
Config.Notify'built-in' / 'ds_notify' / 'custom''built-in' uses QBCore's default QBCore:Notify. 'ds_notify' uses the ds_notify resource. 'custom' routes through bridge/notify_custom.lua.
Config.Prompt'built-in' / 'ds_prompt' / 'custom''built-in' uses a built-in NUI HUD card. 'ds_prompt' uses the ds_prompt resource. 'custom' routes through bridge/prompt_custom.lua.
Config.GenerateSyncBattrue / falseWhen true, every "Write to jobs.lua" click regenerates sync_jobs.bat in the resource root with the correct absolute paths for your machine.

Custom Notification Bridge

If you set Config.Notify = 'custom', open bridge/notify_custom.lua and fill in the NotifyCustom function for both server-side and client-side contexts. The file is pre-commented with examples.

Custom Prompt Bridge

If you set Config.Prompt = 'custom', open bridge/prompt_custom.lua and implement PromptCustom.Show(opts) and PromptCustom.Hide().

5 — Job Creator Panel — /jobcreator

Open the panel in-game with /jobcreator. Your server ID must have the admin, command, or god ace permission. The command also appears as a chat suggestion for admins (cosmetic only — the server enforces the real permission check).

Managing Jobs

The left panel lists all current jobs loaded from jobs.lua (or from QBCore.Shared.Jobs on first run before any save). For each job you can:

  • Edit the label, type, defaultDuty, and offDutyPay fields.
  • Add, rename, reorder, and remove grade tiers. Each grade has a name, payment amount, and optional boss flag.
  • Delete the job entirely.
  • Create a brand-new job with a unique key name.

Writing Jobs

Clicking Write to jobs.lua does three things simultaneously:

  1. Serializes all jobs to QBCore Lua format and writes ds_jobcreator/jobs.lua.
  2. Applies every change live to the running server via AddJob, UpdateJob, and RemoveJob exports. No restart needed.
  3. Regenerates sync_jobs.bat (if Config.GenerateSyncBat = true) with the correct paths for your machine.

A success notification reports how many jobs were added, updated, and removed.

Setting Locations

Each job can have a Boss Menu location and a Stash location. To set one:

  1. Select a job in the panel and open its Locations section.
  2. Click Set Boss Menu Location or Set Stash Location.
  3. The NUI panel hides and your character can move freely.
  4. Walk to the desired in-world spot and press E to confirm, or Backspace to cancel.
  5. The panel re-opens automatically and shows the saved coordinates.

Coordinates are saved to the ds_jobcreatorlocations database table and broadcast to all online clients immediately so their proximity caches update without a reconnect.

Job Type Colors

The panel includes a Type Colors section where you can assign a display color to each job type string (e.g. leo, ems, mechanic). Colors are saved to settings/jobtype-colors.json in the resource folder and loaded by the NUI on each open.

6 — Boss Menu

Employees who hold a boss-grade position in their job can access an in-world Boss Menu by walking within 2 metres of the configured boss-menu location and pressing E.

Only grades marked with isboss = true in the job definition can open the Boss Menu. The grade is verified server-side on every action.

Roster

The Roster tab shows all employees — both online and offline. Online players are sourced live from the running server; offline players are queried from the players table in MySQL. Each row shows the employee's name, grade, boss status, and online indicator.

Actions

ActionWho can use itDescription
HireBossHires a nearby player (within 10 m) into the job at grade 0. Uses the Nearby dropdown which lists players within 10 metres.
FireBossSets the target's job to unemployed grade 0. Cannot fire yourself — use Quit instead.
PromoteBossSets the target to a higher grade. Cannot promote to boss grade (that would create a second boss).
DemoteBossSets the target to a lower grade. Cannot demote yourself.
QuitBossSets your own job to unemployed grade 0 and closes the menu.

All online targets receive a notification when hired or fired via the configured Config.Notify system.

7 — Job Stash

Any employee (not just bosses) can access the job stash by walking within 2 metres of the configured stash location and pressing E. The stash is a 50-slot, 100 kg shared inventory identified by ds_job_stash_<jobname>.

Inventory System Support

The stash integrates with whichever inventory is running. Detection priority is ox_inventory → qs-inventory → qb-inventory.

InventoryOpen methodRegistration
ox_inventoryClient-side via exports.ox_inventory:openInventory('stash', id)Registered server-side via RegisterStash on resource start and on each new stash location save.
qs-inventoryServer-side via exports['qs-inventory']:OpenInventory('stash', id, data, src)Created implicitly on first open — no pre-registration required.
qb-inventoryServer-side via exports['qb-inventory']:OpenInventory(src, id, data)Created server-side via CreateInventory on resource start and on each new stash location save.

8 — sync_jobs.bat

Every time you click Write to jobs.lua, the resource writes a self-contained batch file named sync_jobs.bat into the ds_jobcreator folder (when Config.GenerateSyncBat = true). Double-clicking it on your server machine copies ds_jobcreator/jobs.lua into qb-core/shared/jobs.lua so jobs persist across a full server restart.

Why a bat file instead of writing directly?

FiveM does not permit a resource to write files outside its own resource folder. The batch file is the safe, correct workaround — the resource writes to its own folder (always permitted), and the bat gives you a one-click way to push that file to QBCore. Paths are resolved at runtime using GetResourcePath() so the generated file is always correct regardless of where your resources directory lives.

Example generated file

@echo off
echo Copying jobs.lua to qb-core/shared/jobs.lua...
copy /Y "C:\FiveM Servers\myserver\resources\[admin]\ds_jobcreator\jobs.lua" ^
        "C:\FiveM Servers\myserver\resources\[qb]\qb-core\shared\jobs.lua" >nul
echo Done!
pause

Disabling bat generation

Set Config.GenerateSyncBat = false in config.lua. You will then need to manually copy ds_jobcreator/jobs.lua over qb-core/shared/jobs.lua after each write to persist jobs across restarts. Live changes still apply immediately either way.

9 — Permissions

Every admin action is verified server-side. A player passes the admin check if they hold any of the following FiveM ace permissions:

AceDescription
adminStandard QBCore admin ace
commandFiveM command ace
godFull god-mode ace

Grant the ace in server.cfg:

# Grant by FiveM identifier
add_ace identifier.fivem:XXXXXXX admin allow

# Or grant a group
add_ace group.admin admin allow
add_principal identifier.fivem:XXXXXXX group.admin
The client-side /jobcreator command itself has no ACE restriction — the chat suggestion is cosmetic. The ACE check is enforced server-side when the command triggers the ds_jobcreator:getJobs net event. A player without the right ace receives an "Access denied" notification.

10 — Server Exports

These exports are available to any other resource on your server for reading job location coordinates at runtime.

GetJobStashCoords(source, jobname) vector3 | nil

Returns the stash vector3 for the given job, or nil if no stash location has been set. The requesting player's job must match jobname.

local coords = exports['ds_jobcreator']:GetJobStashCoords(source, 'police')
if coords then
    -- do something with coords.x, coords.y, coords.z
end

GetJobBossMenuCoords(source, jobname) vector3 | nil

Returns the boss-menu vector3 for the given job, or nil if not set. The requesting player must be in the job and on a boss grade.

local coords = exports['ds_jobcreator']:GetJobBossMenuCoords(source, 'police')
if coords then
    -- do something with coords.x, coords.y, coords.z
end

11 — Database

One table is created automatically on resource start:

TableDescription
ds_jobcreatorlocationsStores the boss-menu and stash world coordinates for each job. One row per (jobname, loc_type) pair, enforced by a UNIQUE KEY. Upserted on every location save.

Schema

CREATE TABLE IF NOT EXISTS `ds_jobcreatorlocations` (
    `id`       INT UNSIGNED NOT NULL AUTO_INCREMENT,
    `jobname`  VARCHAR(50)  NOT NULL,
    `loc_type` ENUM('stash','bossmenu') NOT NULL,
    `x`        FLOAT        NOT NULL,
    `y`        FLOAT        NOT NULL,
    `z`        FLOAT        NOT NULL,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uq_job_loctype` (`jobname`, `loc_type`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

12 — jobs.lua Format

The file written by DS Job Creator is valid QBCore Lua that can be dropped directly into qb-core/shared/jobs.lua. Jobs are sorted alphabetically with unemployed always first. Here is an example entry:

QBCore.Shared.ForceJobDefaultDutyAtLogin = true
QBCore.Shared.Jobs = {

    police = {
        label       = 'Missionrow Police Department',
        type        = 'leo',
        defaultDuty = true,
        offDutyPay  = false,
        grades = {
            ['0'] = { name = 'Recruit',   payment = 50  },
            ['1'] = { name = 'Officer',   payment = 75  },
            ['2'] = { name = 'Sergeant',  payment = 100 },
            ['3'] = { name = 'Lieutenant',payment = 125 },
            ['4'] = { name = 'Chief', isboss = true, payment = 150 },
        },
    },

}
The type field is optional. If you leave it blank in the panel it will be omitted from the output. Every grade has a name and payment. Exactly one grade per job should have isboss = true to enable the Boss Menu for that job.

14 — FAQ

Do my jobs disappear after a server restart?

No — as long as you have either run sync_jobs.bat to copy ds_jobcreator/jobs.lua into qb-core/shared/jobs.lua, or manually copied the file. The live changes applied by the panel survive until a full restart; the bat (or manual copy) makes them permanent.

The panel is empty on first run

On first run before any save, the panel loads jobs directly from QBCore.Shared.Jobs (the live in-memory table). Once you click Write to jobs.lua for the first time, subsequent opens read from ds_jobcreator/jobs.lua which is the authoritative source.

I get "Access denied" when opening /jobcreator

Your player does not have the admin, command, or god ace permission. Add one of those aces to your identifier in server.cfg and restart (or use the server console to add it live with add_ace).

The Boss Menu prompt never appears

Two things to check: (1) A boss-menu location must be set for the job in the panel — walk to the location point and click Set Boss Menu Location. (2) Your current job grade must have isboss = true. Both conditions must be met for the proximity prompt to appear.

The stash prompt never appears

A stash location must be set for the job in the panel. You must also be actively employed in that job (any grade). Check that one of ox_inventory, qs-inventory, or qb-inventory is started — the stash will not open if no inventory resource is detected.

sync_jobs.bat shows the wrong paths

The bat is regenerated on every Write to jobs.lua click using GetResourcePath() at runtime — so paths are always resolved from the actual running server. If you moved the resource or renamed folders, click Write to jobs.lua once more to refresh the bat.
