DS Job Creator

In-game admin NUI panel for creating, editing, and managing QBCore jobs on a live server — no file editing required — by DS Customs

v1.4.0 QBCore FiveM Lua 5.4 oxmysql

1 — Overview

DS Job Creator is a fully in-game admin tool for managing every QBCore job on your live server. Open the /jobcreator NUI panel, add or edit jobs and grades, set boss-menu and stash locations by walking to them in-world, and save — all without ever touching a config file.

  • Create, edit, and delete jobs and grade tiers in the NUI panel.
  • Changes are applied live to QBCore.Shared.Jobs via AddJob / UpdateJob / RemoveJob exports — no restart needed.
  • All job data is stored in the ds_jobs MySQL table. On every resource start or restart, jobs are automatically loaded from the database back into QBCore — any jobs in QBCore.Shared.Jobs that are not in ds_jobs are removed. qb-core/shared/jobs.lua is never touched.
  • Job type colors are stored in ds_jobtype_colors — no JSON settings file needed.
  • All three database tables are created automatically on first start — no SQL import required.
  • In-game Boss Menu lets job bosses hire, fire, promote, and demote employees at a configurable in-world location.
  • Per-job Stash locations give all job members access to a shared inventory at a configurable in-world point.
All admin actions — including location placement — are restricted server-side to players with the admin, command, or god ace permission. The Boss Menu is restricted to boss-grade employees of that specific job.

3 — Installation

  1. Place the ds_jobcreator folder inside your resources directory (e.g. resources/[admin]/ds_jobcreator).
  2. Add ensure ds_jobcreator to your server.cfg after qb-core and oxmysql.
  3. Grant the admin ace permission to any player who should access the panel.
  4. Start the resource — all three database tables are created automatically on first run. No SQL import required.
  5. In-game, type /jobcreator to open the panel.

server.cfg Start Order

ensure qb-core
ensure oxmysql
ensure ds_notify      # optional — only needed if Config.Notify = 'ds_notify'
ensure ds_prompt      # optional — only needed if Config.Prompt = 'ds_prompt'
ensure ds_jobcreator
All three MySQL tables (ds_jobs, ds_jobtype_colors, ds_jobcreatorlocations) are created automatically using CREATE TABLE IF NOT EXISTS — safe to restart as many times as needed.

4 — Configuration — config.lua

config.lua is unescrow'd and fully open. Two options are available:

-- Notification system to use for player-facing messages
Config.Notify = 'ds_notify'   -- 'built-in' | 'ds_notify' | 'custom'

-- Interaction prompt system to use near boss-menu and stash locations
Config.Prompt = 'ds_prompt'   -- 'built-in' | 'ds_prompt' | 'custom'
OptionValuesDescription
Config.Notify'built-in' / 'ds_notify' / 'custom''built-in' uses QBCore's default QBCore:Notify. 'ds_notify' uses the ds_notify resource. 'custom' routes through bridge/notify_custom.lua.
Config.Prompt'built-in' / 'ds_prompt' / 'custom''built-in' uses a built-in NUI HUD card. 'ds_prompt' uses the ds_prompt resource. 'custom' routes through bridge/prompt_custom.lua.

Custom Notification Bridge

If you set Config.Notify = 'custom', open bridge/notify_custom.lua and fill in the NotifyCustom function for both server-side and client-side contexts. The file is pre-commented with examples.

Custom Prompt Bridge

If you set Config.Prompt = 'custom', open bridge/prompt_custom.lua and implement PromptCustom.Show(opts) and PromptCustom.Hide().

5 — Job Creator Panel — /jobcreator

Open the panel in-game with /jobcreator. Your server ID must have the admin, command, or god ace permission. The command also appears as a chat suggestion for admins (cosmetic only — the server enforces the real permission check). Press Escape or click ✕ to close the panel.

Managing Jobs

The left panel lists all current jobs loaded from the ds_jobs database table (or from QBCore.Shared.Jobs on first run before any save). The list supports:

  • Search — type in the search box to filter jobs by key name in real time.
  • Sort — toggle between A → Z alphabetical order and By Type grouped order via the sort dropdown.

Clicking a job opens it in the editor on the right. For each job you can:

  • Edit the label, type, defaultDuty, and offDutyPay fields.
  • Add, rename, reorder, and remove grade tiers. Each grade has a name, payment amount, and optional boss flag.
  • Delete the job entirely (disabled for the unemployed job).
  • Click Discard Changes to revert the editor back to the last saved state for that job.
  • Create a brand-new job with + New Job.

Boss Grade Assignment

When saving a job, the boss grade is determined as follows: if any grade row has its Boss checkbox manually checked, those grades receive isboss = true. If no boss checkbox is checked, the highest-numbered grade is automatically assigned as boss. Only one grade needs to be the boss grade — the Boss Menu checks this server-side on every action.

Saving a Job

Clicking Save Job saves the currently open job immediately — it does not batch all jobs at once. Each save:

  1. Upserts the job into the ds_jobs table via INSERT … ON DUPLICATE KEY UPDATE.
  2. Applies the change live to the running server via AddJob or UpdateJob. No restart needed.

A status message at the top of the panel confirms the save with the job name.

On every resource start or restart, all rows from ds_jobs are pushed back into QBCore.Shared.Jobs automatically — qb-core/shared/jobs.lua is never touched.

First-Run Import

On first run, when ds_jobs is empty, the panel seeds itself from QBCore.Shared.Jobs (the live in-memory table) and shows an Import to Database button at the top. Clicking it bulk-inserts all displayed jobs into the database in one operation. The button disappears permanently once the database has been populated.

Setting Locations

Each job can have a Boss Menu location and a Stash location. To set one:

  1. Select a job in the panel and scroll to its Locations section at the bottom of the editor.
  2. Click Place… next to Boss Menu or Stash.
  3. The NUI panel hides and your character can move freely.
  4. Walk to the desired in-world spot and press E to confirm, or Backspace to cancel.
  5. The panel re-opens automatically and shows the saved coordinates.
  6. Click Clear next to a location to delete it from the database.

Coordinates are saved to the ds_jobcreatorlocations database table. After saving, the server broadcasts a ds_jobcreator:locationUpdated event to all online clients so their proximity caches update immediately without a reconnect.

Job Type Colors

The panel includes a ⊟ Type Colors button in the top bar that opens a modal where you can assign a hex display color to each job type string (e.g. leo, ems, mechanic). Colors are saved to the ds_jobtype_colors table and loaded from the database every time the panel opens. The color appears as a badge on each job row in the job list.

6 — Boss Menu

Employees who hold a boss-grade position in their job can access an in-world Boss Menu by walking within 2 metres of the configured boss-menu location and pressing E.

Only grades marked with isboss = true in the job definition can open the Boss Menu. The grade is verified server-side on every action.

Roster

The Roster tab shows all employees — both online and offline. Online players are sourced live from the running server; offline players are queried from the players table in MySQL. Each row shows the employee's name, grade, boss status, and online indicator.

Actions

ActionWho can use itDescription
HireBossHires a nearby player (within 10 m) into the job at grade 0. Uses the Nearby Players dropdown in the Hire tab which lists players within 10 metres.
FireBossSets the target's job to unemployed grade 0. Cannot fire yourself — use Quit instead. Target must be online.
PromoteBossSets the target to a higher grade. Cannot promote to boss grade or above. Target must be online.
DemoteBossSets the target to a lower grade. Cannot demote yourself. Target must be online.
QuitBossSets your own job to unemployed grade 0 and closes the menu.

Online targets receive a notification when hired or fired via the configured Config.Notify system.

7 — Job Stash

Any employee (not just bosses) can access the job stash by walking within 2 metres of the configured stash location and pressing E. The stash is a 50-slot, 100 kg shared inventory identified by ds_job_stash_<jobname>.

Inventory System Support

The stash integrates with whichever inventory is running. Detection priority is ox_inventory → qs-inventory → qb-inventory.

InventoryOpen methodRegistration
ox_inventoryClient-side via exports.ox_inventory:openInventory('stash', id)Registered server-side via RegisterStash on resource start and on each new stash location save.
qs-inventoryServer-side via exports['qs-inventory']:OpenInventory('stash', id, data, src)Created implicitly on first open — no pre-registration required.
qb-inventoryServer-side via exports['qb-inventory']:OpenInventory(src, id, data)Created server-side via CreateInventory on resource start and on each new stash location save.

8 — Migrating away from DS Job Creator

If you ever decide to stop using DS Job Creator you can export your jobs back to QBCore's shared file manually:

  1. Run the following SQL in any MySQL client to see all jobs currently in the database:
    SELECT * FROM ds_jobs;
  2. Rebuild qb-core/shared/jobs.lua from that data and remove ensure ds_jobcreator from your server.cfg.
Because every job is fully stored in ds_jobs — jobname, label, type, defaultDuty, offDutyPay, and the full grades JSON — you can reconstruct the QBCore shared file from a single SELECT * at any time.

9 — Permissions

Every admin action is verified server-side. A player passes the admin check if they hold any of the following FiveM ace permissions:

AceDescription
adminStandard QBCore admin ace
commandFiveM command ace
godFull god-mode ace

Grant the ace in server.cfg:

# Grant by FiveM identifier
add_ace identifier.fivem:XXXXXXX admin allow

# Or grant a group
add_ace group.admin admin allow
add_principal identifier.fivem:XXXXXXX group.admin
The client-side /jobcreator command itself has no ACE restriction — the chat suggestion is cosmetic. The ACE check is enforced server-side when the command triggers the ds_jobcreator:getJobs net event. A player without the right ace receives an "Access denied" notification.

10 — Server Exports

These exports are available to any other resource on your server for reading job location coordinates at runtime.

GetJobStashCoords(source, jobname) vector3 | nil

Returns the stash vector3 for the given job, or nil if no stash location has been set. The requesting player's job must match jobname.

local coords = exports['ds_jobcreator']:GetJobStashCoords(source, 'police')
if coords then
    -- do something with coords.x, coords.y, coords.z
end

GetJobBossMenuCoords(source, jobname) vector3 | nil

Returns the boss-menu vector3 for the given job, or nil if not set. The requesting player must be in the job and on a boss grade.

local coords = exports['ds_jobcreator']:GetJobBossMenuCoords(source, 'police')
if coords then
    -- do something with coords.x, coords.y, coords.z
end

11 — Database Tables

All three tables are created automatically using CREATE TABLE IF NOT EXISTS on every resource start. No manual SQL import is ever needed.

TableDescription
ds_jobsAuthoritative job store. One row per job — jobname (PK), label, type, defaultDuty, offDutyPay, and grades as a JSON object. Upserted on every Save Job.
ds_jobtype_colorsOne row per job type string. Stores the hex color used by the panel's type badges. Replaced entirely on each color save.
ds_jobcreatorlocationsBoss-menu and stash world coordinates per job. One row per (jobname, loc_type) pair, enforced by a unique key. Upserted on every location save.

ds_jobs schema

CREATE TABLE IF NOT EXISTS `ds_jobs` (
    `jobname`     VARCHAR(50)  NOT NULL,
    `label`       VARCHAR(100) NOT NULL DEFAULT '',
    `type`        VARCHAR(50)  NOT NULL DEFAULT '',
    `defaultDuty` TINYINT(1)   NOT NULL DEFAULT 1,
    `offDutyPay`  TINYINT(1)   NOT NULL DEFAULT 0,
    `grades`      LONGTEXT     NOT NULL, -- JSON object keyed by grade index
    PRIMARY KEY (`jobname`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

ds_jobtype_colors schema

CREATE TABLE IF NOT EXISTS `ds_jobtype_colors` (
    `type`  VARCHAR(50) NOT NULL,
    `color` VARCHAR(7)  NOT NULL, -- hex e.g. #3b82f6
    PRIMARY KEY (`type`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

ds_jobcreatorlocations schema

CREATE TABLE IF NOT EXISTS `ds_jobcreatorlocations` (
    `id`       INT UNSIGNED NOT NULL AUTO_INCREMENT,
    `jobname`  VARCHAR(50)  NOT NULL,
    `loc_type` ENUM('stash','bossmenu') NOT NULL,
    `x`        FLOAT        NOT NULL,
    `y`        FLOAT        NOT NULL,
    `z`        FLOAT        NOT NULL,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uq_job_loctype` (`jobname`, `loc_type`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

13 — FAQ

Do my jobs disappear after a server restart?

No. On every resource start and restart, server.lua queries ds_jobs and pushes every row into QBCore.Shared.Jobs via AddJob / UpdateJob. Any job in QBCore's memory that is not in ds_jobs is also removed, making the database the single source of truth. As long as ds_jobcreator is ensured in your server.cfg, your jobs are always loaded automatically — qb-core/shared/jobs.lua is never touched.

The panel shows an "Import to Database" button

This button only appears on first run, when the ds_jobs table is empty. The panel seeds itself from QBCore.Shared.Jobs (live in-memory data) and shows the button so you can bulk-import all of those jobs into the database in one click. Once the database has been populated the button is hidden permanently and the panel reads only from ds_jobs.

I get "Access denied" when opening /jobcreator

Your player does not have the admin, command, or god ace permission. Add one of those aces to your identifier in server.cfg and restart (or use the server console to add it live with add_ace).

The Boss Menu prompt never appears

Two things to check: (1) A boss-menu location must be set for the job in the panel — select the job, scroll to Locations, and click Place… next to Boss Menu. (2) Your current job grade must have isboss = true. Both conditions must be met for the proximity prompt to appear.

The stash prompt never appears

A stash location must be set for the job in the panel. You must also be actively employed in that job (any grade). Check that one of ox_inventory, qs-inventory, or qb-inventory is started — the stash will not open if no inventory resource is detected.

My type colors disappeared

Type colors are stored in ds_jobtype_colors in your database, so they persist across restarts automatically. If they appear missing, open the ⊟ Type Colors modal in the panel and re-save — this will re-insert all current type/color pairs into the table.
