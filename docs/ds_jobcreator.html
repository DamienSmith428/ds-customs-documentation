DS Job Creator

In-game admin NUI panel for creating, editing, and managing QBCore jobs on a live server — no file editing required — by DS Customs

v1.5.1 QBCore FiveM Lua 5.4 oxmysql Escrow

1 — Overview

DS Job Creator is a fully in-game admin tool for managing every QBCore job on your live server. Open the /jobcreator NUI panel, add or edit jobs and grades, set boss-menu, stash, and garage locations by walking to them in-world, and save — all without ever touching a config file.

  • Create, edit, and delete jobs and grade tiers in the NUI panel.
  • Changes are applied live to QBCore.Shared.Jobs via AddJob / UpdateJob / RemoveJob exports — no restart needed.
  • All job data is stored in the ds_jobs MySQL table. On every resource start or restart, jobs are automatically loaded from the database back into QBCore — any jobs in QBCore.Shared.Jobs that are not in ds_jobs are removed. qb-core/shared/jobs.lua is never touched.
  • Job type colors are stored in ds_jobtype_colors — no JSON settings file needed.
  • All four database tables are created automatically on first start — no SQL import required.
  • In-game Boss Menu lets job bosses hire, fire, promote, and demote employees at a configurable in-world location.
  • Per-job Stash locations give all job members access to a shared inventory at a configurable in-world point.
  • Per-job Garage locations push a job-restricted garage zone to ds_garages (or any custom garage resource) automatically on save and on every server restart.
All admin actions — including location placement — are restricted server-side to players with the admin, command, or god ace permission. The Boss Menu is restricted to boss-grade employees of that specific job.

3 — Installation

  1. Place the ds_jobcreator folder inside your resources directory (e.g. resources/[admin]/ds_jobcreator).
  2. Add ensure ds_jobcreator to your server.cfg after qb-core, oxmysql, and — if using the garage integration — after ds_garages.
  3. Grant the admin ace permission to any player who should access the panel.
  4. Start the resource — all four database tables are created automatically on first run. No SQL import required.
  5. In-game, type /jobcreator to open the panel.

server.cfg Start Order

ensure qb-core
ensure oxmysql
ensure ds_notify      # optional — only needed if Config.Notify = 'ds_notify'
ensure ds_prompt      # optional — only needed if Config.Prompt = 'ds_prompt'
ensure ds_garages     # optional — only needed if Config.Garages = 'ds_garages'
ensure ds_jobcreator  # must come AFTER ds_garages when using garage integration
All four MySQL tables (ds_jobs, ds_jobtype_colors, ds_jobcreatorlocations, ds_job_garages) are created automatically using CREATE TABLE IF NOT EXISTS — safe to restart as many times as needed.

4 — Configuration — config.lua

config.lua is unescrow'd and fully open. Three bridge options are available:

-- Notification system to use for player-facing messages
Config.Notify = 'ds_notify'   -- 'built-in' | 'ds_notify' | 'custom'

-- Interaction prompt system to use near boss-menu and stash locations
Config.Prompt = 'ds_prompt'   -- 'built-in' | 'ds_prompt' | 'custom'

-- Garage integration backend
Config.Garages = 'ds_garages' -- 'ds_garages' | 'custom' | false

-- Job stash capacity (applies to every job stash)
Config.StashSlots  = 75      -- number of inventory slots
Config.StashWeight = 750000  -- maximum carry weight in grams
OptionValuesDescription
Config.Notify'built-in' / 'ds_notify' / 'custom''built-in' uses QBCore's default QBCore:Notify. 'ds_notify' uses the ds_notify resource. 'custom' routes through bridge/notify_custom.lua.
Config.Prompt'built-in' / 'ds_prompt' / 'custom''built-in' uses a built-in NUI HUD card. 'ds_prompt' uses the ds_prompt resource. 'custom' routes through bridge/prompt_custom.lua.
Config.Garages'ds_garages' / 'custom' / false'ds_garages' pushes garages to ds_garages via its registerJobGarage export. 'custom' routes through bridge/garages_custom.lua. false disables live registration entirely — locations are still stored in the database but never pushed to any garage resource.
Config.StashSlotsnumberNumber of inventory slots for every job stash. Default: 50.
Config.StashWeightnumberMaximum carry weight (in grams) for every job stash. Default: 100000.

Custom Notification Bridge

If you set Config.Notify = 'custom', open bridge/notify_custom.lua and fill in the NotifyCustom function for both server-side and client-side contexts. The file is pre-commented with examples.

Custom Prompt Bridge

If you set Config.Prompt = 'custom', open bridge/prompt_custom.lua and implement PromptCustom.Show(opts) and PromptCustom.Hide().

Custom Garage Bridge

If you set Config.Garages = 'custom', open bridge/garages_custom.lua — this file is unescrow'd and fully editable. Implement the GarageRegisterCustom function to push job garage data to whichever garage resource your server uses. The file ships with three fully-commented examples covering export-based, event-based, and file-based garage resources.

-- bridge/garages_custom.lua — minimal example (export-based)
function GarageRegisterCustom(jobname, label, coords, spawnPoint, opts)
    exports['my_garages']:AddJobGarage({
        job        = jobname,
        label      = label,
        x          = coords.x,    y = coords.y,    z = coords.z,
        spawnX     = spawnPoint.x, spawnY = spawnPoint.y,
        spawnZ     = spawnPoint.z, spawnH = spawnPoint.w,
    })
    return true
end

The function receives:

ParameterTypeDescription
jobnamestringQBCore job name — use as the garage key.
labelstringHuman-readable garage name for the UI.
coordstable {x,y,z,w}E-prompt interaction zone centre + heading.
spawnPointtable {x,y,z,w}Vehicle spawn position + heading.
optstableExtra optional data: opts.jobType, opts.category, opts.zoneRadius, opts.blip.

Return true on success or false, "error message" on failure.

5 — Job Creator Panel — /jobcreator

Open the panel in-game with /jobcreator. Your server ID must have the admin, command, or god ace permission. Press Escape or click ✕ to close the panel.

Managing Jobs

The left panel lists all current jobs loaded from the ds_jobs database table (or from QBCore.Shared.Jobs on first run before any save). The list supports:

  • Search — filter jobs by key name in real time.
  • Sort — toggle between A → Z alphabetical and By Type grouped order.

Clicking a job opens it in the editor. For each job you can:

  • Edit the label, type, defaultDuty, and offDutyPay fields.
  • Add, rename, reorder, and remove grade tiers.
  • Delete the job entirely (disabled for the unemployed job).
  • Click Discard Changes to revert to the last saved state.
  • Create a brand-new job with + New Job.

Boss Grade Assignment

When saving a job, if any grade row has its Boss checkbox manually checked, those grades receive isboss = true. If no checkbox is checked, the highest-numbered grade is automatically assigned as boss.

Saving a Job

Clicking Save Job saves the currently open job immediately. Each save:

  1. Upserts the job into the ds_jobs table via INSERT … ON DUPLICATE KEY UPDATE.
  2. Applies the change live to the running server via AddJob or UpdateJob. No restart needed.

First-Run Import

On first run, when ds_jobs is empty, the panel seeds itself from QBCore.Shared.Jobs and shows an Import to Database button. Clicking it bulk-inserts all displayed jobs. The button disappears permanently once the database has been populated.

Setting Locations — Locations Modal

Once a job is saved, the ⊙ Locations button appears in the editor action bar. Click it to open the Locations modal. Three location types can be set per job:

LocationWho uses itDescription
Boss MenuBoss-grade employeesIn-world point where the Boss Menu proximity prompt appears.
StashAll job membersIn-world point where the shared job stash proximity prompt appears.
GarageAll job membersTwo points: a Prompt (where the E-prompt appears) and a Spawn (where the vehicle is placed). Both are required for the garage to register.

The three small dots on the Locations button show at a glance which locations are configured — a filled dot means that location is set.

To place any location:

  1. Open the Locations modal and click Place… (or Prompt… / Spawn… for garage).
  2. The modal and NUI panel hide — your character can move freely in-world.
  3. Walk to the desired spot and press E to confirm, or Backspace to cancel.
  4. The panel and modal reopen automatically showing the saved coordinates.

For the Garage, you must place both the Prompt and Spawn points. Each can be placed in any order. Once both are set, the garage row is saved to the database and immediately registered with the configured garage backend — no restart needed. Click Clear to remove a location from the database.

Press Escape to close the Locations modal without closing the main panel. Clicking outside the modal also closes it.

Job Type Colors

The ⊟ Type Colors button in the top bar opens a modal to assign a hex color to each job type string. Colors appear as badges on each job row in the job list and are stored in the ds_jobtype_colors table.

6 — Boss Menu

Employees who hold a boss-grade position can access the Boss Menu by walking within 2 metres of the configured boss-menu location and pressing E.

Only grades marked with isboss = true can open the Boss Menu. The grade is verified server-side on every action.

Roster

The Roster tab shows all employees — both online and offline. Online players are sourced live from the running server; offline players are queried from the players MySQL table.

Actions

ActionWho can use itDescription
HireBossHires a nearby player (within 10 m) into the job at grade 0.
FireBossSets the target's job to unemployed grade 0. Cannot fire yourself.
PromoteBossMoves the target up one grade. Cannot promote to boss grade or above.
DemoteBossMoves the target down one grade. Cannot demote yourself.
QuitBossSets your own job to unemployed grade 0 and closes the menu.

7 — Job Stash

Any employee can access the job stash by walking within 2 metres of the configured stash location and pressing E. The stash is a shared inventory identified by ds_job_stash_<jobname>. Slot count and weight limit are controlled by Config.StashSlots and Config.StashWeight in config.lua (defaults: 50 slots, 100 000 g).

Inventory System Support

Detection priority is ox_inventory → qs-inventory → qb-inventory.

InventoryOpen methodRegistration
ox_inventoryClient-side via exports.ox_inventory:openInventory('stash', id)Registered server-side via RegisterStash on resource start and on each new stash save.
qs-inventoryServer-side via exports['qs-inventory']:OpenInventory('stash', id, data, src)Created implicitly on first open — no pre-registration required.
qb-inventoryServer-side via exports['qb-inventory']:OpenInventory(src, id, data)Created server-side via CreateInventory on resource start and on each new stash save.

8 — Job Garage

Each job can have a garage location set through the Locations modal. The garage is job-restricted — only players whose current job matches the job name (or job type, if configured) will see the E-prompt zone. The garage uses the full ds_garages NUI — no preview camera — displaying all vehicles the player owns stored in that garage.

How It Works

  1. An admin sets a Prompt location (where the E-prompt appears) and a Spawn location (where the vehicle physically appears) via the Locations modal.
  2. Both coordinates are saved to the ds_job_garages table.
  3. The garage is immediately registered with the configured backend (e.g. ds_garages) — no restart required.
  4. On every server restart, all rows in ds_job_garages are automatically re-registered with the backend at startup.
  5. Players who receive or change their job in-game see the garage prompt appear (or disappear) instantly without reconnecting.

Using with ds_garages

Set Config.Garages = 'ds_garages' in config.lua and ensure ds_garages starts before ds_jobcreator in server.cfg. The bridge calls exports['ds_garages']:registerJobGarage() with the following defaults:

FieldDefaultDescription
type'job'Always job-restricted.
category'car'Vehicle class filter. Change in bridge/garages.lua or pass via opts.
zoneRadius3.0Metres from the prompt point before the E-prompt appears.
blip{ show = false }No map blip by default — job garages are private.
Garages registered this way have no cinematic preview camera — the vehicle list opens directly. This is intentional since no static preview spawn location is defined.

Using a Custom Garage Resource

Set Config.Garages = 'custom' and implement GarageRegisterCustom in bridge/garages_custom.lua. See § 4 — Custom Garage Bridge for the full parameter reference and examples.

9 — Migrating away from DS Job Creator

If you ever decide to stop using DS Job Creator you can export your jobs back to QBCore's shared file manually:

  1. Run SELECT * FROM ds_jobs; in any MySQL client to see all stored jobs.
  2. Rebuild qb-core/shared/jobs.lua from that data and remove ensure ds_jobcreator from your server.cfg.
Every job is fully stored in ds_jobs — jobname, label, type, defaultDuty, offDutyPay, and the full grades JSON. You can reconstruct the QBCore shared file from a single SELECT * at any time.

10 — Permissions

Every admin action is verified server-side. A player passes the check if they hold any of:

AceDescription
adminStandard QBCore admin ace
commandFiveM command ace
godFull god-mode ace
 
# Grant by FiveM identifier
add_ace identifier.fivem:XXXXXXX admin allow

# Or grant a group
add_ace group.admin admin allow
add_principal identifier.fivem:XXXXXXX group.admin
The /jobcreator command has no client-side ACE restriction — the check is enforced server-side when the command triggers the ds_jobcreator:getJobs net event. A player without the right ace receives an "Access denied" notification.

11 — Server Exports

These exports are available to any other server-side resource for reading job location coordinates at runtime.

GetJobStashCoords(source, jobname) vector3 | nil

Returns the stash vector3 for the given job, or nil if no stash location has been set. The requesting player's job must match jobname.

local coords = exports['ds_jobcreator']:GetJobStashCoords(source, 'police')
if coords then
    -- coords.x, coords.y, coords.z
end

GetJobBossMenuCoords(source, jobname) vector3 | nil

Returns the boss-menu vector3 for the given job, or nil if not set. The requesting player must be in the job and on a boss grade.

local coords = exports['ds_jobcreator']:GetJobBossMenuCoords(source, 'police')
if coords then
    -- coords.x, coords.y, coords.z
end

GetJobGarageCoords(jobname) table | nil

Returns the full garage definition for the given job, or nil if no garage has been set. Unlike the stash and boss-menu exports, this one does not check the caller's job — it returns the raw data for any resource to use. The returned table has the shape:

-- returns:
{
    label  = "Police Garage",
    prompt = { x = 0.0, y = 0.0, z = 0.0, w = 0.0 },
    spawn  = { x = 0.0, y = 0.0, z = 0.0, w = 0.0 },
}
local g = exports['ds_jobcreator']:GetJobGarageCoords('police')
if g then
    -- g.prompt.x/y/z/w  — E-prompt zone centre + heading
    -- g.spawn.x/y/z/w   — vehicle spawn position + heading
end

12 — Database Tables

All four tables are created automatically using CREATE TABLE IF NOT EXISTS on every resource start. No manual SQL import is ever needed.

TableDescription
ds_jobsAuthoritative job store. One row per job — jobname (PK), label, type, defaultDuty, offDutyPay, and grades as a JSON object. Upserted on every Save Job.
ds_jobtype_colorsOne row per job type string. Stores the hex color used by the panel's type badges. Replaced entirely on each color save.
ds_jobcreatorlocationsBoss-menu and stash world coordinates per job. One row per (jobname, loc_type) pair, enforced by a unique key. Upserted on every location save.
ds_job_garagesGarage prompt and spawn coordinates per job. One row per job (jobname is PK). Stores label, prompt x/y/z/w, and spawn x/y/z/w. Upserted on every garage save.

ds_jobs schema

CREATE TABLE IF NOT EXISTS `ds_jobs` (
    `jobname`     VARCHAR(50)  NOT NULL,
    `label`       VARCHAR(100) NOT NULL DEFAULT '',
    `type`        VARCHAR(50)  NOT NULL DEFAULT '',
    `defaultDuty` TINYINT(1)   NOT NULL DEFAULT 1,
    `offDutyPay`  TINYINT(1)   NOT NULL DEFAULT 0,
    `grades`      LONGTEXT     NOT NULL, -- JSON object keyed by grade index
    PRIMARY KEY (`jobname`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

ds_jobtype_colors schema

CREATE TABLE IF NOT EXISTS `ds_jobtype_colors` (
    `type`  VARCHAR(50) NOT NULL,
    `color` VARCHAR(7)  NOT NULL, -- hex e.g. #3b82f6
    PRIMARY KEY (`type`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

ds_jobcreatorlocations schema

CREATE TABLE IF NOT EXISTS `ds_jobcreatorlocations` (
    `id`       INT UNSIGNED NOT NULL AUTO_INCREMENT,
    `jobname`  VARCHAR(50)  NOT NULL,
    `loc_type` ENUM('stash','bossmenu') NOT NULL,
    `x`        FLOAT        NOT NULL,
    `y`        FLOAT        NOT NULL,
    `z`        FLOAT        NOT NULL,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uq_job_loctype` (`jobname`, `loc_type`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

ds_job_garages schema

CREATE TABLE IF NOT EXISTS `ds_job_garages` (
    `jobname`   VARCHAR(50)  NOT NULL,
    `label`     VARCHAR(100) NOT NULL DEFAULT '',
    `prompt_x`  FLOAT NOT NULL,  -- E-prompt zone centre
    `prompt_y`  FLOAT NOT NULL,
    `prompt_z`  FLOAT NOT NULL,
    `prompt_w`  FLOAT NOT NULL DEFAULT 0.0,  -- heading
    `spawn_x`   FLOAT NOT NULL,  -- vehicle spawn position
    `spawn_y`   FLOAT NOT NULL,
    `spawn_z`   FLOAT NOT NULL,
    `spawn_w`   FLOAT NOT NULL DEFAULT 0.0,  -- heading
    PRIMARY KEY (`jobname`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

14 — FAQ

Do my jobs disappear after a server restart?

No. On every resource start and restart, server.lua queries ds_jobs and pushes every row into QBCore.Shared.Jobs. Any job in QBCore's memory that is not in ds_jobs is also removed, making the database the single source of truth. qb-core/shared/jobs.lua is never touched.

Do garage locations re-register after a restart?

Yes. On every resource start, all rows in ds_job_garages are read and pushed to the configured garage backend automatically. Ensure ds_garages (or your custom garage resource) starts before ds_jobcreator in server.cfg.

The garage prompt doesn't appear after I get the job

Job-gated garage zones are rebuilt automatically whenever a player's job changes in-game — no reconnect is needed. If the prompt still doesn't appear, check that: (1) both the Prompt and Spawn locations have been set for that job in the Locations modal, and (2) ds_garages is running and started before ds_jobcreator.

The panel shows an "Import to Database" button

This only appears on first run when ds_jobs is empty. Click it to bulk-import all jobs from QBCore's live memory into the database. The button disappears permanently once the database has been populated.

I get "Access denied" when opening /jobcreator

Your player does not have the admin, command, or god ace permission. Add one in server.cfg and restart, or use the server console live with add_ace.

The Boss Menu prompt never appears

Two things to check: (1) a boss-menu location must be set for the job in the Locations modal, and (2) your current job grade must have isboss = true. Both conditions must be met.

The stash prompt never appears

A stash location must be set for the job in the Locations modal. You must also be employed in that job. Check that one of ox_inventory, qs-inventory, or qb-inventory is started.

My type colors disappeared

Type colors are stored in ds_jobtype_colors and persist across restarts. If they appear missing, open the ⊟ Type Colors modal and re-save to re-insert all current pairs.
