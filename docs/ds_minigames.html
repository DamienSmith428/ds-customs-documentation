DS Minigames

Modular, framework-agnostic minigame library. Six fully playable games, four difficulty tiers each, one clean export per game — by DS Customs

v1.0.0 FiveM Lua 5.4 No SQL No Framework Escrow

1 — Overview

ds_minigames is a standalone minigame library that any other resource on your server can call with a single Lua export. It ships six original minigames, each isolated in its own folder with its own client Lua, server Lua, JavaScript, and CSS. The calling resource never touches the NUI — it just awaits a true or false.

Every game supports four named difficulty tiers — easy, medium, hard, and insane — all configured in a single open config.lua. Callers can also pass an inline override table instead of a string to fine-tune parameters for a specific scenario.

No framework dependency. No SQL. Works with QBCore, ESX, ox, or any standalone resource. Drop it in, ensure it, done.

Architecture at a glance

2 — Installation

  1. Place the ds_minigames folder inside your resources directory.
  2. Add ensure ds_minigames to server.cfg before any resource that calls its exports.
  3. Done — no SQL, no further configuration required unless you want to adjust difficulties.
# server.cfg
ensure ds_minigames
ensure ds_vehiclekeys    # any resource that calls ds_minigames exports
ensure my_robbery_script

3 — Configuration — config.lua

config.lua is completely open and unencrypted. Every difficulty value for every game lives here. You should never need to touch any other file.

Global settings

Config.Sounds = true   -- master sound toggle for all games
Config.Debug  = false  -- print game name + config to console on each start

Difficulty tiers

Each game has four named tiers. The table keys match the strings you pass to the export. Example for Thermal Crack:

Config.ThermalCrack = {
    easy   = { zones = 3, holdTime = 1.2, driftSpeed = 0.4, timeLimit = 40, zoneArc = 0.38 },
    medium = { zones = 5, holdTime = 1.8, driftSpeed = 0.8, timeLimit = 30, zoneArc = 0.28 },
    hard   = { zones = 7, holdTime = 2.4, driftSpeed = 1.4, timeLimit = 22, zoneArc = 0.20 },
    insane = { zones = 9, holdTime = 3.0, driftSpeed = 2.2, timeLimit = 16, zoneArc = 0.14 },
}

Every game follows the same pattern — four tiers, keys match export strings. All six tables are documented individually in the Games section below.

4 — Export API

Every export is registered in client/client_main.lua and follows the same contract: pass a difficulty string or an inline config table, receive a blocking boolean result.

Calling pattern

-- Pattern A: named difficulty string
local success = exports['ds_minigames']:CircuitBreaker('hard')

-- Pattern B: inline override table (any key from the Config table)
local success = exports['ds_minigames']:ThermalCrack({
    zones       = 4,
    holdTime    = 1.5,
    driftSpeed  = 1.0,
    timeLimit   = 28,
    zoneArc     = 0.24,
})

-- Result handling — identical for every game
if success then
    -- player succeeded: unlock door, give reward, advance job step, etc.
else
    -- player failed: trigger alarm, remove item, penalise, etc.
end

Server-side triggers

A server script can launch a minigame on a specific player without needing that player to call the export directly.

-- Fire-and-forget: server triggers a game on a player (result logged server-side)
TriggerClientEvent('ds_minigames:server:startGame', source, 'ThermalCrack', 'hard')

-- Callback variant: result comes back via the ds_minigames:gameCompleted server event
TriggerClientEvent('ds_minigames:server:startGameCb', source, 'CircuitBreaker', 'insane', myCallbackId)

-- Listen for the result on the server
AddEventHandler('ds_minigames:gameCompleted', function(src, success, cbId)
    if success then
        -- reward the player server-side
    end
end)

5 — The Six Games

CircuitBreaker

A grid of glowing nodes — some are real path nodes, the rest are decoys. The player must click only the correct sequence from the highlighted SOURCE node to the TARGET node. Clicking a decoy costs a life. On Hard and Insane difficulty the entire board reshuffles at a set interval mid-round.

Controls: Mouse click on nodes. Escape to cancel.

Best for: Bank hacks, server room access, electric fence bypasses, power plant sabotage.

medium9430s2Never
hard12620s1Every 10s
insane16914s1Every 5s
 
local success = exports['ds_minigames']:CircuitBreaker('hard')

ThermalCrack

A circular ring with a drifting amber heat zone. The drill head is fixed at 12 o'clock. The player must hold Space while the zone passes under the drill head for a set duration. Holding too long past the zone edge causes an overheat and instant failure. Complete every zone to succeed.

Controls: Hold Space. Escape to cancel.

Best for: Safe cracking, vault doors, car lockpicking, hotwiring, drill jobs.

TierZonesHold timeDrift speedZone arcTime limit
easy31.2s0.4×Wide40s

hard72.4s1.4×Narrow22s
insane93.0s2.2×Very narrow16s
 
local success = exports['ds_minigames']:ThermalCrack('medium')
This is the recommended game for car lockpicking — the hold-tension mechanic maps directly to the feeling of applying pressure on a lock tumbler. It is already wired into ds_vehiclekeys via the Config.Minigames bridge.

SignalTrace

An oscilloscope-style grid filled with noise characters. A correct path winds from the ENTRY cell to the EXIT cell — faintly visible if you look closely. The player navigates using WASD. Moving onto an off-path cell injects static noise that temporarily blinds nearby cells. On higher difficulties the path reseeds and the blind duration increases significantly.

Controls: WASD to move. Escape to cancel.

Best for: Phone taps, radio tower intercepts, comms hacking, surveillance bypass.

local success = exports['ds_minigames']:SignalTrace('hard')

SurgeControl

Multiple vertical power meters fill simultaneously at slightly different rates. Each bar has a red spike zone near the top. When a bar's fill reaches the spike zone the player must press the matching number key (1–9) to release pressure before the auto-fail timer expires. Miss a bar and lose a life. All bars are visible simultaneously — on Insane all nine fire near-concurrently.

Controls: Number keys 1–9. Escape to cancel.

Best for: Generator sabotage, drug lab operations, electrical panel bypass, power grid disruption.

local success = exports['ds_minigames']:SurgeControl('insane')

CipherDecode

A Mastermind-style code cracker. A hidden code is generated using the configured alphabet. The player submits guesses from an on-screen keyboard; each guess row returns per-character colour feedback — green = correct position, yellow = correct character wrong position, grey = not in code. Higher difficulties extend code length, restrict alphabet to symbols, and shrink attempt limits to three.

Controls: Mouse click on the on-screen keyboard, or physical keyboard. Enter to submit. Escape to cancel.

Best for: Keypad bypasses, ATM skimmers, evidence safes, secure terminal access.

GhostWire

A circuit-board grid. The player steers a wire from the START cell to the END cell using WASD. The wire cannot cross itself or land on obstacle components — either triggers an immediate short-circuit failure. On Hard and Insane the cursor auto-advances in the last input direction at increasing speed, forcing the player to steer reactively.

Controls: WASD to route. Escape to cancel.

Best for: Bomb defusal, alarm bypass, CCTV tap, vehicle tampering, hotwiring high-end vehicles.

6 — Integration Examples

Car lockpicking (ds_vehiclekeys)

ds_vehiclekeys has a built-in bridge for ds_minigames. Set Config.Minigames.Resource = 'ds' in its config and Thermal Crack will automatically be used when a player uses a lockpick item.

-- ds_vehiclekeys/config.lua
Config.Minigames = {
    Resource       = 'ds',      -- 'qb' = qb-minigames Skillbar | 'ds' = ds_minigames ThermalCrack
    DSNormalDiff   = 'medium',  -- normal lockpick difficulty
    DSAdvancedDiff = 'easy',    -- advanced lockpick difficulty
}

Dynamic difficulty by vehicle class

local veh      = GetVehiclePedIsIn(PlayerPedId(), false)
local vehClass = GetVehicleClass(veh)

local diff
if     vehClass == 18 then diff = 'insane'   -- emergency / armoured
elseif vehClass == 8  then diff = 'hard'     -- motorcycle
elseif vehClass == 7  then diff = 'medium'   -- SUV
else                        diff = 'easy'     -- standard cars
end

local success = exports['ds_minigames']:ThermalCrack(diff)
if success then
    TriggerServerEvent('myresource:server:unlockVehicle', NetworkGetNetworkIdFromEntity(veh))
else
    TriggerServerEvent('myresource:server:triggerAlarm')
end

Multi-step bank robbery

-- Step 1: hack the server room
local hackOk = exports['ds_minigames']:CircuitBreaker('hard')
if not hackOk then Notify.Client('Hack failed!', 'error') return end

-- Step 2: crack the vault door
local crackOk = exports['ds_minigames']:ThermalCrack('insane')
if not crackOk then Notify.Client('Drill overloaded!', 'error') return end

-- Both passed — open the vault
TriggerServerEvent('mybank:server:openVault')

Server-triggered with result callback

-- server.lua — trigger a minigame on a specific player and get the result back
local cbId = 'vault_' .. source
TriggerClientEvent('ds_minigames:server:startGameCb', source, 'GhostWire', 'hard', cbId)

AddEventHandler('ds_minigames:gameCompleted', function(src, success, returnedCbId)
    if returnedCbId ~= cbId then return end
    if success then
        TriggerClientEvent('myresource:openVaultDoor', src)
    end
end)

Adding a new game

  1. Create games/my_game/client.lua — declare a promise, register NUI callbacks, expose DS_MyGame(cfg).
  2. Create games/my_game/server.lua — add any server hooks you need (can be an empty file).
  3. Create html/js/my_game.js — game logic; post back via dsPost('mg_success') / dsPost('mg_fail').
  4. Create html/css/my_game.css — game-specific styles.
  5. Add the container <div id="mg-container"> block to html/index.html.
  6. Add the difficulty table to config.lua.
  7. Register the export in client/client_main.lua following the existing pattern.
  8. Add both lua files to fxmanifest.lua under client_scripts and server_scripts.

9 — FAQ

Can I use ds_minigames without QBCore?

Yes — ds_minigames has no framework dependency. It works with any FiveM resource that can call Lua exports.

Will calling an export block the thread?

Yes, intentionally. Each export uses promise.new() + Citizen.Await(), so the calling thread suspends until the minigame resolves. This means you can write linear code — no callbacks needed.

Can two players run different minigames at the same time?

Yes — each player's NUI is isolated. The Lua promise is per-client, and all game state in JavaScript is scoped inside an IIFE with no shared globals between games.

What happens if a player disconnects mid-game?

The NUI unloads and the promise is never resolved, but since the player is gone there's no thread to hang. The server-side callback entry will be orphaned — clear it in a playerDropped handler if you use the callback-style trigger.

Can I change difficulty at runtime without restarting?

Yes — pass an inline table override instead of a string. The config is only read at the moment the export is called, so you can compute any values you want dynamically before the call.
