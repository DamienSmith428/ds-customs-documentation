DS Prompt

Standalone interaction prompt — key badge, color presets, proximity-aware — by DS Customs

v1.0.0 QBCore FiveM Lua 5.4 No SQL

1 — Overview

DS Prompt is a single, self-contained interaction prompt resource. Any other resource on your server can display a persistent key-press hint via a clean export API — the calling resource supplies the key label, action text, color, and size. The prompt sits on screen until your code hides it or the player presses the configured key.

DS Prompt shares the same 4-corner bracket visual language, dark-glass card, color palette, and animated top-rule as DS Notify, DS Progressbar, and DS Target — all four resources look like a cohesive suite.

2 — Installation

  1. Place the ds_prompt folder inside your resources directory.
  2. Add ensure ds_prompt to your server.cfg before any resource that depends on it.
  3. Done — no SQL, no further configuration required.
# server.cfg
ensure ds_prompt
ensure my_job_resource  # any resource that calls ds_prompt exports
To declare the load-order dependency in another resource, add dependency 'ds_prompt' to that resource's fxmanifest.lua.

3 — Configuration — config.lua

config.lua is open and unencrypted. Every setting here is a server-wide default — individual Show() calls can override color and size per-prompt.

-- Fallback color when none is passed to Show()
Config.DefaultColor = 'gold'

-- Fallback size when none is passed to Show()
Config.DefaultSize = 'medium'

-- Where the prompt widget appears on screen
Config.Position = 'bottom-center'

-- Key label shown when Show() does not supply one
Config.DefaultKey = 'E'

-- When true the prompt auto-hides as soon as the player presses the key
Config.HideOnPress = true

4 — Show(opts)

Displays the prompt widget. The prompt stays on screen until Hide() is called or — when Config.HideOnPress = true — until the player presses the configured key.

Options table

KeyTypeRequiredDefaultDescription
keystringYesConfig.DefaultKeyKey label shown in the badge — e.g. 'E', 'F', 'G', 'SPACE'. The calling resource owns this value.
labelstringYes''Action description shown next to the key badge — e.g. 'Open Trunk'.
colorstringNoConfig.DefaultColorAny color preset name — see §3.
sizestringNoConfig.DefaultSize'small', 'medium', or 'large'.
hideOnPressbooleanNoConfig.HideOnPressPer-call override for auto-hide behaviour. Pass false to keep the prompt visible after the key is pressed. Pass true to force auto-hide even if the global config is off. Omit to use the config default.
The key field is the label displayed inside the badge — it is not a FiveM control index. Your resource is responsible for detecting the actual key press in its own IsControlJustPressed logic.

Examples

-- Minimal — color and size fall back to config
exports['ds_prompt']:Show({
    key   = 'E',
    label = 'Open Trunk',
})

-- Full options
exports['ds_prompt']:Show({
    key   = 'G',
    label = 'Hack Terminal',
    color = 'teal',
    size  = 'large',
})

-- Keep prompt visible after keypress (e.g. a door that stays nearby)
exports['ds_prompt']:Show({
    key          = 'E',
    label        = 'Unlock Door',
    color        = 'gold',
    hideOnPress  = false,
})

Typical proximity pattern

CreateThread(function()
    local shown = false
    while true do
        Wait(250)
        local dist = #(GetEntityCoords(PlayerPedId()) - targetCoords)
        if dist < 2.5 and not shown then
            exports['ds_prompt']:Show({ key = 'E', label = 'Search Crate', color = 'orange' })
            shown = true
        elseif dist >= 2.5 and shown then
            exports['ds_prompt']:Hide()
            shown = false
        end
    end
end)

5 — Hide()

Hides the prompt widget with a fade-out transition. Safe to call at any time, even when the prompt is not visible.

exports['ds_prompt']:Hide()
Always call Hide() when the player moves out of range, enters a vehicle, or completes the interaction. Failing to do so leaves the prompt on screen indefinitely.

6 — Update(opts)

Updates the prompt content while it is already visible — no hide/show flicker. Useful for toggling the label between two states (e.g. Open / Close) without a visual pop.

Options table

KeyTypeDescription
keystringNew key label to display in the badge.
labelstringNew action description.
colorstringNew color preset.
sizestringNew size preset.
hideOnPressbooleanUpdate the auto-hide behaviour while the prompt is already visible. Follows the same logic as the Show() option.
 
-- Toggle between Open and Close without hiding first
if trunkOpen then
    exports['ds_prompt']:Update({ key = 'E', label = 'Close Trunk' })
else
    exports['ds_prompt']:Update({ key = 'E', label = 'Open Trunk' })
end

7 — Key Labels & Auto-hide

The key field is a display string — whatever you put there is rendered in the badge. When auto-hide is active (controlled by Config.HideOnPress globally, or overridden per-call via hideOnPress), DS Prompt internally maps common label strings to FiveM control indices and hides the prompt when that control fires. The built-in mapping covers the most common interaction keys:

LabelFiveM ControlLabelFiveM Control
'E'INPUT_PICKUP (38)'R'INPUT_RELOAD (45)
'F'INPUT_ENTER (23)'Q'INPUT_SELECT_PREV_WEAPON (82)
'G'INPUT_DETONATE (47)'ENTER'INPUT_FRONTEND_ACCEPT (18)
'H'INPUT_VEH_HEADLIGHT (74)'SPACE'INPUT_JUMP (22)
'T'INPUT_MP_TEXT_CHAT (245)'LSHIFT'INPUT_SPRINT (21)
'X'INPUT_DETONATE (73)'LCTRL'INPUT_DUCK (36)
'Z'INPUT_CHARACTER_WHEEL (20)'U'INPUT_MP_FOLLOW_WAYPOINT (303)
'Y'INPUT_MP_TEXT_CHAT_TEAM (246)'LALT'INPUT_CHARACTER_WHEEL (19)
Keys not in the table are displayed correctly in the badge but will not trigger auto-hide. Pass hideOnPress = false to Show() or set Config.HideOnPress = false globally, and call Hide() manually — or extend the KEY_CONTROLS table in client.lua.

    ├── index.html     ← NUI root — widget with corner brackets, key badge, pulse bar

10 — Notes

  • The calling resource owns the key — pass whatever label makes sense for your interaction. Multiple resources can show different prompts with different keys.
  • Only one prompt is visible at a time because ds_prompt is a single NUI overlay. If two resources call Show() simultaneously, the second call overwrites the first. Coordinate visibility in your own resource logic.
  • Config.HideOnPress auto-hides via an internal IsControlJustPressed check for recognised key labels. Your own key-press handler will also fire normally — auto-hide does not consume or block the input.
  • Update() is a live patch — only the keys you pass change. Omitting color leaves the current color unchanged.
  • DS Prompt has no database calls and no QBCore dependency. It is purely a client UI layer.
  • The resource is Escrow-protected except for config.lua, which is fully open.
