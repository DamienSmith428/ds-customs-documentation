DS Hunting

Full-featured wildlife hunting system with graded loot, carry animations, a butcher shop NUI, server leaderboard, 75 achievements, anti-farm, and managed spawn zones — multi-framework, multi-inventory, multi-target — by DS Customs

v1.0.0 QBX Core QB-Core ESX ox_inventory qb-inventory ps-inventory qs-inventory tgiann-inventory ox_lib oxmysql Lua 5.4 Escrow

1 — Overview

DS Hunting is a complete wildlife economy for FiveM servers. Players track and kill animals across the map, skin or pick up the carcass, carry it back to a butcher NPC, and sell graded loot for cash. Kill quality is determined server-side by weapon choice and bone hit — a headshot with the right weapon yields a perfect-grade item worth double the base price.

Progression is tracked persistently in MySQL. A server-wide leaderboard NPC displays the top hunters at all times. A 75-achievement system with escalating cash rewards keeps long-term players engaged without locking core gameplay behind a grind wall.

All compatibility logic lives in isolated bridge files — only the one matching your config is ever active. There is no dead code path or cross-framework bleed. config.lua and spawnzones.lua are fully open; all other files are escrow-protected.

3 — Installation

Drop-in

Copy the ds_hunting folder into your resources directory.

Database

Two tables are created automatically by the resource on first start via server/modules/stats.lua:

-- Created automatically — no manual SQL import needed
ds_hunting_stats        -- per-player kill counts and total earnings
ds_hunting_achievements -- per-player unlocked and claimed achievement arrays (JSON)
No SQL file needs to be imported manually. Both tables are created with CREATE TABLE IF NOT EXISTS on the first server start.

Inventory Items

Add all hunting items to your inventory's item definition file. Grab the ready-to-use item definitions and inventory images from the INSTALL-ME/ folder included in the resource:

  • INSTALL-ME/item.txt — item definitions (copy into your inventory's items file)
  • INSTALL-ME/inv images/ — PNG images for all hunting items (copy into your inventory's images folder)
Item images inside INSTALL-ME/inv images/ use generic grade icons (hunting_meat_1.png, hunting_pelt_2.png, etc.) shared by all species. If your inventory supports per-item images, the butcher shop UI uses its own ui/images/ folder with species-specific per-grade art.

server.cfg Start Order

ensure oxmysql
ensure ox_lib
ensure qbx_core      # or qb-core / esx
ensure ox_inventory  # or whichever inventory you use
ensure ox_target     # only if Config.UseTarget = true
ensure ds_hunting

Quick-Start Config

Open config.lua and set the three stack keys to match your server:

Config.Framework      = 'qbx_core'    -- 'qbx_core' | 'qb-core' | 'esx'
Config.Inventory      = 'ox_inventory' -- 'ox_inventory' | 'qb-inventory' | 'ps-inventory' | 'qs-inventory' | 'tgiann-inventory'
Config.UseTarget      = true           -- true = target resource | false = E-prompt
Config.TargetResource = 'ox_target'   -- 'ox_target' | 'qb-target' | 'ds_target' (only used when UseTarget = true)

Kill Grades — Config.grades & Config.goodWeapon

Grade is determined server-side at the moment the animal dies. The grade suffix is appended to the item name before it is added to the player's inventory.

GradeLabelConditionPrice Multiplier
1 — Poor★☆☆Killed with any weapon not in Config.goodWeapon0.5×
2 — Good★★☆Killed with a weapon in Config.goodWeapon1.0×
3 — Perfect★★★Good weapon and kill shot hit the animal's headshot bone2.0×

Default Config.goodWeapon list: WEAPON_MUSKET, WEAPON_SNIPERRIFLE, WEAPON_KNIFE. Add or remove weapon hashes to adjust which weapons qualify for grade 2+.

Headshot bones are defined per-animal in Config.headshotBones. These are GTA bone IDs — the defaults are correct for all seven shipped animals. Only change them if you add custom animal models.

5 — Spawn Zones — spawnzones.lua

Spawn zones are defined in spawnzones.lua, which is excluded from escrow. Each zone maintains a minimum and maximum live animal count, repopulating whenever a player is nearby. Zones go dormant when no player is within Config.SpawnZoneSettings.activationRadius metres — spawned peds are deleted after despawnDelay seconds.

6 — Hunting Flow

The full sequence from kill to cash, with where each step runs:

StepWhereWhat happens
1 — KillClientPlayer kills an animal. The client detects the death, checks if the ped model is in Config.carcass, and registers a target or E-prompt on the corpse.
2 — Anti-farm checkServerBefore any loot is awarded, the server runs the anti-farm zone check. If the kill is blocked, the player is notified and the flow stops.
3 — Grade resolutionServerThe server evaluates the killing weapon hash against Config.goodWeapon and checks if the kill bone was in Config.headshotBones. Grade 1, 2, or 3 is assigned.
4 — Skin animalClient → ServerPlayer selects "Skin Animal". A skinning animation plays client-side. On completion, the server adds the graded loot items to the player's inventory and records the kill in ds_hunting_stats.
5 — Pick up carcassClientPlayer selects "Pick Up Carcass". The carcass ped is attached to the player using the carry or drag animation defined in Config.carcassPos.
6 — Carry to butcherClientPlayer walks to the butcher NPC. Press G at any time to drop the carcass. A "too far" check prevents selling if the player is not near the actual carcass.
7 — SellClient → ServerPlayer opens the butcher shop UI. The server validates each item before sending shop data. Player confirms the sale. Server removes items from inventory, adds money, and records earnings in stats.
8 — AchievementsServerAfter every kill and every sale, the server runs Achievements.CheckAndUnlock. Any newly unlocked achievements are sent to the client, which displays a notification. Cash rewards are claimable via the leaderboard NUI.

10 — FAQ

Animals aren't showing interaction prompts.

Verify that Config.UseTarget and Config.TargetResource match your running setup. If using ox_target, confirm it is started before ds_hunting. If using the E-prompt mode (UseTarget = false), confirm the player is standing close enough to the dead animal — targets are only registered on peds whose model is in Config.carcass. Enable Config.Debug = true and check the F8 console for target registration logs.

Everything I harvest is grade 1 (poor).

Grade is determined by the weapon used to kill the animal. Only weapons listed in Config.goodWeapon produce grade 2 or 3. The default list is WEAPON_MUSKET, WEAPON_SNIPERRIFLE, and WEAPON_KNIFE. If players are using other weapons, add those hashes to Config.goodWeapon. For grade 3 (perfect), the kill shot must also hit the specific headshot bone defined in Config.headshotBones for that animal.

Players are getting blocked too quickly by anti-farm.

Tune Config.antiFarm: increase maxAmount to allow more kills per zone, reduce size to make zones smaller (so the radius covers less area), or increase time to widen the tracking window. Setting personal = false switches from per-player to server-wide zone limits, which is more restrictive — switch it back to true for per-player limits.

Achievements aren't unlocking.

Confirm that oxmysql is running and the ds_hunting_stats and ds_hunting_achievements tables were created (check the server console on first start). Achievement checks run after every successful skin and sell — if loot is being awarded but achievements are not triggering, enable Config.Debug = true and watch for achievement-related server console output. Also verify the player's citizenid is being resolved correctly by the active framework bridge.

Animals aren't spawning in the spawn zones.

Spawn zones only activate when a player is within Config.SpawnZoneSettings.activationRadius metres (default 400 m) of the zone centre. If no player is nearby, no peds spawn. Confirm Config.UseSpawnZones = true in config.lua. Enable Config.Debug = true and look for spawn manager logs in the server console. Also confirm OneSync is enabled — the server-side spawn manager requires it.

Items aren't appearing in the player's inventory after skinning.

Confirm Config.Inventory matches a running inventory resource. The resolved inventory bridge logs a message on startup. Check that the item names in your inventory definition match the names in Config.harvestYields plus the grade suffix (e.g. deer_meat_2). All item definitions and images are provided in INSTALL-ME/.

The carry / drag animation looks wrong or the carcass is floating.

Carry attachment offsets are defined per-animal in Config.carcassPos in config.lua. Adjust the xPos, yPos, zPos, xRot, yRot, zRot values for the affected animal. Set drag = true for large animals (drag animation) and drag = false for small ones (shoulder carry).

Can I add more animal species?

Yes. Add an entry to Config.carcass, Config.harvestYields, Config.carcassPos, Config.headshotBones, and Config.itemPrices for the new animal. Add the new species to any spawn zones you want it to appear in. Create the item definitions and optionally add UI images to ui/images/. The resource reads all five tables at runtime — no core code changes are required.
